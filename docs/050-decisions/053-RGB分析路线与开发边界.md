# 053｜RGB 分析路线与开发边界

**Status: Proposed**

## 决策背景

NIR 正式分析已经完成并形成稳定 AMD/DirectML runtime；RGB 在 `rgb-dev` 上进行正式视频方法验证，不直接改动稳定 NIR 路线。RGB 目标是建立可与 NIR/Behavior 对齐的连续行为测量，而不是直接生成 Attention Score。

## 当前路线

1. **Motion**：OpenCV frame-difference global Motion 已在 `sub-031` 正式视频上完成 gap/QC/review 验证；
2. **Pose**：MediaPipe Tasks Pose Landmarker / Pose Lite / VIDEO mode，`sub-031` 10 fps 完整正式时间窗 pilot、landmark QC 和质量门控后的派生 feature 均已完成；
3. **Face**：下一开发步骤直接进入 Py-Feat vs LibreFace 2.0 benchmark。

## 信息保留决策

RGB 强制遵循 `docs/040-rgb/044-RGB输出Schema与信息保留原则.md`：昂贵推理尽量只运行一次，raw 层优先保存以后难以恢复的完整模型输出；QC 先 flag 后 filter；derived feature 与 summary 尽量从 raw 重建；正式结果通过 manifest 记录模型、配置、版本、hash、Git commit 和源文件 provenance。

## Pose 10 fps 决策

`sub-031` 首次完整正式时间窗 Pose pilot：15,494 个采样时点，`pose_valid_fraction=1.0`，0 个 multi-pose frame，约 429.1 s（7.15 min），实际约 36.1 inference/s，输出 511,302 landmark rows / 约 22.7 MB。

因此撤销此前基于速度担忧提出的临时 5 fps 方案，正式开发参数恢复 **10 fps**。10 fps 在当前时间预算内可接受，并保留更高时间分辨率。非采样帧继续只 `grab` 推进 AVI，采样帧才 decode。

## 上半身机位与 Pose 可用边界

`sub-031` 的逐 landmark QC 已完成。结论不是“完整上半身骨架稳定”，而是**头肩稳定、肘腕髋大多在画外**：

- nose、左右 shoulder：visibility/presence 接近 1，100% in-frame；
- elbows：presence 很低且基本画外；
- wrists：presence 约 0.006/0.015，几乎完全画外；
- hips：presence 约 0.001，完全不应作为真实观测。

因此 MediaPipe 返回 world coordinate 不等于 landmark 真实可见。Raw 层继续保存全部 33 点；derived 层必须同时经过 visibility、presence 和 in-frame 质量门控。

`rgb-pose-features-v0.2` 对 `sub-031` 的实测：15,494 行，0 multi-pose ambiguity，2 个 >300 ms Pose gap reset，15,491 行 shoulder motion 有效，0 行 elbow motion 有效，6 行 wrist motion 有效，0 行 trunk angle 有效。

据此正式开发口径调整为：

- **shoulder motion / shoulder center / shoulder-line posture 是当前 Pose 主测量；**
- wrist/elbow/trunk 为 opportunistic 指标，只在实际入画且质量门控通过时使用；
- `upper_body_motion` 不能在当前机位下宽泛解释为“整个上半身总运动”，因为在 `sub-031` 中它几乎等于 shoulder-only 聚合；
- Raw 仍不删除画外 landmark，以保留其他被试可能更宽机位的信息。

## Pose-derived motion 与 body Motion Energy 分界

必须区分：

- **Pose-derived shoulder/body posture motion**：由质量合格 landmark 的位置变化直接计算，按真实 dt 和 shoulder width 标准化；可完全从 `pose-test.parquet` 重建；
- **body_motion_energy**：在被试人体 ROI 内计算像素帧差，需要重新消费 RGB 帧。

`body_motion_energy` 不在此阶段单独再扫一次 AVI；等待 Face backend 冻结后，与 Motion/Pose/Face 的正式统一视频读取一起计算。

## Face benchmark 顺序

Pose 首个 representative pilot 已完成必要的模型、速度、coverage、landmark QC 和 derived-feature sanity check。为了赶时间，**不再等待额外 Pose 小测试**；下一开发步骤直接进入 Py-Feat vs LibreFace benchmark。最终再合成单次视频读取的正式 batch。

## AMD / MediaPipe 边界

MediaPipe Python Pose 当前使用 CPU/XNNPACK；实测 10 fps Pose 时间可接受，因此不为了 Pose 单独增加 DirectML 转换工程。Face 深度模型仍允许在 benchmark 后尝试 ONNX Runtime DirectML，但 preprocessing/postprocessing 与数值一致性必须验证。
