# 053｜RGB 分析路线与开发边界

**Status: Proposed**

## 决策背景

NIR 正式分析已经完成并形成稳定 AMD/DirectML runtime；RGB 在 `rgb-dev` 上进行正式视频方法验证，不直接改动稳定 NIR 路线。RGB 目标是建立可与 NIR/Behavior 对齐的连续行为测量，而不是直接生成 Attention Score。

## 当前路线

1. **Motion**：OpenCV frame-difference global Motion 已在 `sub-031` 正式视频上完成 gap/QC/review 验证；
2. **Pose**：MediaPipe Tasks Pose Landmarker / Pose Lite / VIDEO mode，`sub-031` 10 fps 完整正式时间窗 pilot、landmark QC 和质量门控后的派生 feature 均已完成；
3. **Face**：Py-Feat Detectorv2 vs LibreFace 2.0 已完成 350 张稀疏共同样本和 30 秒连续 10 fps 第二轮 benchmark，当前不冻结 backend；下一步在同一 AMD GPU 上并行验证 **LibreFace ONNX/DirectML** 与 **Py-Feat ONNX/DirectML**。

## 信息保留决策

RGB 强制遵循 `docs/040-rgb/044-RGB输出Schema与信息保留原则.md`：昂贵推理尽量只运行一次，raw 层优先保存以后难以恢复的完整模型输出；QC 先 flag 后 filter；derived feature 与 summary 尽量从 raw 重建；正式结果通过 manifest 记录模型、配置、版本、hash、Git commit 和源文件 provenance。

## Pose 当前结论

`sub-031` Pose 10 fps representative pilot：15,494 个采样时点，`pose_valid_fraction=1.0`，0 multi-pose frame，约 429.1 s / 7.15 min，实际约 36.1 inference/s，输出约 22.7 MB。

逐 landmark QC 显示：nose 与双肩稳定且始终入画；肘、腕、髋大多为画外模型外推。`rgb-pose-features-v0.2` 经 visibility/presence/in-frame 质量门控及 >300 ms gap reset 后，shoulder motion 有效 15,491 行、elbow 0 行、wrist 6 行、trunk angle 0 行。因此当前 Pose 正式解释优先收敛到 shoulder motion / shoulder center / shoulder-line posture；其他部位仅在各被试实际质量通过时作为 opportunistic 指标。

`body_motion_energy` 是人体 ROI 内的像素级帧差，不等同于 Pose-derived motion；它等待 Face backend 冻结后与正式统一视频读取一起实现，避免当前重复扫描大体积 AVI。

## Face 第一轮：稀疏共同样本

`sub-031` 350 张 phase-stratified 共同 JPEG：

- Py-Feat：350/350 image-level coverage，348 单脸 + 2 multi-face；输出 20 AU、7 emotion、VA、gaze、6DoF head pose、68 landmarks、478×3 mesh、51 blendshape、identity；CPU 约 0.529 image/s。
- LibreFace：349/350 alignment；唯一失败为 multi-face 路径实现缺陷，不是 no-face；12 AU detection + 12 AU intensity + expression + gaze + head pose/landmarks 均完整覆盖成功帧。
- LibreFace binary AU detection 多数为常数；AU intensity 信息量更高。

第一轮只用于 coverage / output / robustness screening，不冻结 backend。

## Face 第二轮：连续 30 秒 / 10 fps

连续样本 300 帧，中位实际间隔 99 ms，0 temporal gap。两候选 coverage 均为 100%。

### Py-Feat

- 300 张完整 inference 568.05 s，约 **0.528 image/s**；
- 20 AU 中 18 个变化，AU11/AU20 在该窗口为常数；非恒定 AU lag-1 中位约 **0.723**；
- gaze 连续性中等；
- head pose 连续性较好，Pitch/Roll/Yaw lag-1 约 0.828 / 0.956 / 0.722；
- 信息完整性仍明显领先。

### LibreFace

- fresh end-to-end (`alignment_reused=false`) 67.38 s / 300，约 **4.452 image/s**，当前 CPU reference 吞吐约 Py-Feat 的 **8.43×**；
- 12 AU intensity 均变化，lag-1 中位约 **0.648**；
- binary AU detection 多数仍为常数，不作为正式连续主变量；
- head pose 连续性较好；
- categorical expression 在该窗口不变，信息量有限；
- gaze 尤其 yaw 存在较大的高频变化（median step≈5.68°、p95≈17.30°、max≈41.81°），当前不直接作为正式主变量。

### Cross-model uncertainty

共同 AU intensity 的 Spearman 整体较弱，11 个可计算 common AU 相关范围约 -0.419 至 0.386，绝对值中位约 0.298。Gaze 一致性也较弱；head pose 的 Pitch/Roll 一致性明显更高。

因此不能把两个工具的 AU/gaze 当作可互换测量，也不能用“模型间相关更高”直接定义准确率。弱一致性本身应作为 measurement uncertainty 记录。

## Face visual review

不再要求逐帧人工 FACS 标注，改用模型输出 overlay 做快速 sanity check。`face-visual-review` 已升级为 v0.2，只读取已有连续 300 帧结果，不重新运行模型。

新版目标：

- 两边尽量统一显示 FaceMesh 关键轮廓；
- 眼睛/虹膜单独区分；
- 黄色箭头只表示 gaze；
- 红 X / 绿 Y / 蓝 Z 三轴表示 head pose；
- AU 显示中文含义；
- Py-Feat 标明 0–1 probability-like AU；LibreFace 标明 0–5 AU intensity；
- Py-Feat 显示 top emotion probability，LibreFace 显示 expression label；
- LibreFace alignment 状态改成“人脸对齐：成功/失败”。

该 overlay 不是人工 ground truth，不用于计算严格准确率，只用于快速发现漏脸、mesh 偏移、gaze 抖动、head-pose 方向异常和明显不合理的 AU/expression 输出。

## Face 当前候选定位

当前不再采用“Py-Feat 只做 scientific reference、LibreFace 只做 deployment candidate”的二分。两者都是正式候选：

- **Py-Feat Detectorv2**：字段完整性、multi-face raw handling、FaceMesh/blendshape/VA 等信息量明显更高，但 CPU reference 极慢；若 AMD DirectML 能显著加速且 parity 通过，仍可能成为正式 backend；
- **LibreFace 2.0**：CPU reference 明显更快，官方已有 ONNX derivative，工程接入门槛更低；主连续 AU 优先看 AU intensity，binary AU 作为 raw/event 信息保留；
- 两者都必须在 AMD GPU 上公平比较后再决定；
- multi-face 必须在正式 pipeline 外层显式 primary-face 选择，不能依赖 LibreFace 当前 `get_aligned_image()` multi-face 路径。

## AMD / backend 边界

MediaPipe Python Pose 当前使用 CPU/XNNPACK，实测速度可接受，因此不为 Pose 单独增加 DirectML 工程。

当前暂无 RTX 5070 可用，因此 Face 下一步优先在 Windows AMD 上并行验证两条路线。

### LibreFace DirectML

```text
raw RGB frame
→ MediaPipe alignment / primary-face handling
→ LibreFace official ONNX heads
→ ONNX Runtime DmlExecutionProvider
→ AU intensity / AU detection / expression / gaze
```

必须分别记录 model-core 与 raw-frame end-to-end wall time，因为 alignment 可能仍主要在 CPU 上。

### Py-Feat DirectML

```text
raw RGB frame
→ RetinaFace
→ isotropic square-pad 256 crop
→ Detectorv2 multitask model
   AU / emotion / VA / gaze / head pose / 478 mesh / blendshape
→ ONNX Runtime DmlExecutionProvider
```

第一轮 scientific-core benchmark 暂不把 optional identity branch 纳入速度比较；但正式 Py-Feat DirectML 不能只导出 multitask 子模型后声称完成端到端迁移，必须复刻 RetinaFace、crop、normalization 与 postprocessing。

### 公平 benchmark 规则

两套 DirectML 都使用现有同一批连续 300 帧，至少报告：

1. 实际 execution provider 与模型/权重 hash；
2. warm-up 后 batch 1 / 8 / 16 / 32 中可运行配置；
3. model-core throughput；
4. raw-frame end-to-end throughput；
5. CPU fallback 情况；
6. 与现有 PyTorch CPU reference 的逐字段数值 parity；
7. coverage / missing / multi-face 行为；
8. raw schema 是否完整保留昂贵推理已经可获得的信息。

速度测试与科学输出 parity 必须分开判断；“ONNX 能跑”不等于输出等价，也不等于实际主要在 GPU 上执行。
