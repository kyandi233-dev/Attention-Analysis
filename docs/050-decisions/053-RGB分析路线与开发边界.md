# 053｜RGB 分析路线与开发边界

**Status: Proposed**

## 决策背景

NIR 正式分析已经完成并形成稳定 AMD/DirectML runtime；RGB 分析刚进入开发阶段，因此单独使用 `rgb-dev` 分支，不在稳定 NIR 路线上直接试验新的深度学习依赖或分析口径。

RGB 当前研究目标不是直接生成 Attention Score，而是建立可与 NIR 和 Behavior 对齐的连续行为测量。

## 当前路线

RGB 第一阶段固定为三个测量层面：

1. **Face**：Py-Feat 与 LibreFace 2.0 benchmark 后二选一；
2. **Pose**：MediaPipe Pose 作为默认第一路线；
3. **Motion**：OpenCV frame-difference Motion Energy 作为默认第一路线。

Face benchmark 主要比较正式视频上的检测覆盖、时间连续性、明显动作 spot-check、缺失率、计算效率和实际有用的输出覆盖。没有人工 FACS ground truth 时，不把两个模型之间的一致性直接解释为准确率。

## 信息保留决策

RGB 开发新增一条强制的数据工程规则：**昂贵推理尽量只运行一次，模型第一次运行时优先完整保存其能够稳定返回、以后可能需要且无法从现有结果直接恢复的 raw 输出。**

因此：

- 不根据当前研究假设提前只保存少数 AU、少数 landmark 或单一 Motion Energy 指标；
- raw 层优先保存完整模型输出和 frame/timestamp identity；
- QC 先标记，不在 raw 层静默 `continue` 丢弃；
- derived feature 与 summary 尽量从 raw 输出重新计算；
- 正式被试结果使用 manifest 记录模型、配置、backend、hash、Git commit、schema version 和源文件 provenance。

详细规范以 `docs/040-rgb/044-RGB输出Schema与信息保留原则.md` 为 canonical 说明。后续增加任何 Face/Pose/Motion 模型 stage 前必须先检查该文档和 `configs/rgb_analysis.yaml:retention`。

## AMD / DirectML 决策边界

项目已经在 NIR 上验证 ONNX Runtime DirectML 可用于 Windows AMD GPU，因此 Py-Feat / LibreFace 的核心网络允许尝试导出 ONNX 并使用 DirectML。

但 Face 模型的 preprocessing、face detection/alignment、postprocessing 和数值一致性必须重新验证。当前不把“可导出 ONNX”自动等同于“已经形成正式 DirectML Face runtime”。

## 时间轴与 gap 决策

RGB 不物理切分 baseline、practice、block 等视频段。分析保持一条连续时间序列，实验阶段通过 FocusWave 输出的绝对时间戳映射。

实验程序 provenance 以 `kyandi233-dev/FocusWave@formaltest` 为准；当前正式数据主要为 v3.1.3 / v3.1.4 的最终 BB（B1/B2）结构。分析读取 RGB frame timestamp、`master_timeline.csv` 和行为 `absolute_onset_time`，不通过 nominal FPS 猜测实验时间。

采集 frame index 不连续本身不自动排除被试。只要现存 AVI 帧与 timestamp 行一一对应、Unix 时间单调且覆盖正式时间窗，局部 gap 作为 missing/QC 处理。依赖相邻帧的 Motion Energy、速度、角速度等在 gap 后第一帧不得跨 gap 计算。

`rgb_timestamp_gaps.csv` 保存 gap 前后 frame identity、真实持续时间、capture index 缺失数、按时间估计的缺失帧数、phase/block 和 source provenance。当前 100 ms 仅是开发期扫描阈值，不是正式排除标准。

## 当前明确不进入第一阶段主链

- YuNet 作为独立主分析工具；
- YOLO Pose；
- Action Recognition；
- rPPG / HR / HRV；
- 综合 facial activity / restlessness / Attention Score 的人为评分。

这些路线没有被永久拒绝，只是在当前主路线出现明确测量缺口前不增加工程复杂度。

## 当前完成状态

- RGB 文件、时间戳和行为文件 audit：已实现并完成第一轮正式数据检查；
- timestamp gap QC：已实现，等待本地正式数据运行与结果复核；
- Motion Energy：尚未开始正式实现；
- MediaPipe Pose：尚未开始正式实现；
- Py-Feat vs LibreFace benchmark：尚未开始。

## 何时改为 Accepted

至少完成以下事项后再把本 decision 从 `Proposed` 改为 `Accepted`：

- Py-Feat vs LibreFace pilot benchmark；
- MediaPipe Pose 与 Motion Energy 的正式视频可用性检查；
- raw output schema 按 044 在 representative pilot 上核对完整；
- Face backend、采样率和正式 QC 规则冻结；
- 若采用 DirectML，完成与参考 backend 的数值一致性验证。
