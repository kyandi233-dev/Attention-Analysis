# 053｜RGB 分析路线与开发边界

**Status: Proposed**

## 决策背景

NIR 正式分析已经完成并形成稳定 AMD/DirectML runtime；RGB 在 `rgb-dev` 上进行正式视频方法验证，不直接改动稳定 NIR 路线。RGB 目标是建立可与 NIR/Behavior 对齐的连续行为测量，而不是直接生成 Attention Score。

## 当前路线

1. **Motion**：OpenCV frame-difference global Motion 已在 `sub-031` 正式视频上完成 gap/QC/review 验证；
2. **Pose**：MediaPipe Tasks Pose Landmarker 已实现正式视频长窗口 pilot，当前直接进入 `sub-031` 实跑；
3. **Face**：Pose pilot 通过后立即进行 Py-Feat vs LibreFace 2.0 benchmark。

## 信息保留决策

RGB 强制遵循 `docs/040-rgb/044-RGB输出Schema与信息保留原则.md`：昂贵推理尽量只运行一次，raw 层优先保存以后难以恢复的完整模型输出；QC 先 flag 后 filter；derived feature 与 summary 尽量从 raw 重建；正式结果通过 manifest 记录模型、配置、版本、hash、Git commit 和源文件 provenance。

## 时间与 gap

RGB 不物理切分 baseline/practice/block。所有模型输出使用真实 RGB timestamp，并映射 master timeline 与行为 `absolute_onset_time`。Motion 已验证 timestamp gap 后第一帧不跨 gap 计算运动；`irregular_dt` 继续只作为 QC flag。

## Motion 当前结论

`sub-031` global Motion pilot：46,479 行、约 78.3 fps、约 3 MB。13.853 s/758 ms Block2 gap 等均正确 missing。人工 review 进一步确认 baseline 最高 global Motion 主要来自主试在画面中移动，并非简单曝光跳变。

因此 `global_motion_energy` 定义为**整画面变化量/QC**，不直接等价为被试运动。Pose 提供人体位置后再构建 `body_motion_energy`，并保留 global/body 两条序列。

## Pose pilot 决策

为尽快完成正式 RGB 链路验证，Pose 第一轮采用：

- MediaPipe Tasks Pose Landmarker / Pose Lite；
- `VIDEO` 模式；
- 真实 baseline 到 Block2 的完整正式时间窗；
- 10 fps 推理用于快速 coverage/速度/schema 验证；
- `num_poses=2`，baseline 主试入镜不在 raw 层提前过滤；
- 保存全部 33 normalized landmarks、33 world landmarks、visibility、presence、pose bbox、frame/timestamp/behavior identity；
- 检测失败帧保留 `pose_valid=False`；
- 暂不输出高体积 segmentation masks，人体 ROI 先由完整 landmarks 可重复构建。

10 fps 是开发 pilot 参数，不是正式冻结采样率。根据实测速度、覆盖和时序稳定性再决定正式 fps。

## AMD / MediaPipe 边界

MediaPipe Python Pose pilot 当前使用官方 CPU Task runtime；不因为主机是 AMD 就人为增加 DirectML 转换工作。Face 深度模型仍允许在 benchmark 后尝试 ONNX Runtime DirectML，但 preprocessing/postprocessing 与数值一致性必须验证。
