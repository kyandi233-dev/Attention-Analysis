# NIR × Behavior 对齐原型与数据契约

> 2026-08-26（Asia/Shanghai）｜工作分支：`amd-DirectML`。本文件定义 frozen full-class NIR 与 FocusWave v3.1.3 BB 正式行为数据之间的下游对齐契约。RGB 在 `rgb-dev` 独立推进；本实现不修改 `runtime/nir-formal/`，也不定义 RGB blink/PERCLOS。

## 1. 当前阶段与目标

- 北京正式样本按 **116 名被试**处理；当前只有 `sub-031` 已完成 `ritnet-fullclass-v1.2-fast-qc` extension。
- 当前任务不是利用单被试选择群体效应或最终 QC 阈值，而是先用 `sub-031` 冻结 **数据结构、时间对齐、provenance、候选时间窗和非破坏性行为 QC**。
- 其余被试 full-class 完成后，应使用同一 schema 批量运行，不重新设计字段。

总体数据流：

```text
FocusWave v3.1.3 B1/B2 behavior CSV
                    +
frozen full-class NIR CSV (一帧 × 一眼)
                    ↓
         Unix-ms 统一绝对时间轴
                    ↓
      trial / probe 候选时间窗
                    ↓
trial_level + trial_nir_windows + probe_windows
                    ↓
trial/probe coverage reports + alignment diagnostics
                    ↓
后续 mixed models / trajectory / prediction / questionnaire linkage
```

## 2. 代码边界

新增下游包：

```text
src/attention_pipeline/nir_behavior/
```

运行入口：

```text
scripts/nir_behavior_alignment.py
```

默认配置：

```text
configs/nir_behavior_alignment.yaml
```

边界原则：

1. `runtime/nir-formal/` 是正式 NIR 推理与 full-class extension 的 frozen 生产层，本阶段只读，不修改。
2. `src/attention_pipeline/behavior_formal/` 继续负责 v3.1.3 BB 行为读取与既有行为分析口径；NIR 对齐不改写其原始评分。
3. 新模块只负责跨数据源的时间对齐、派生 QC、窗口特征、coverage 与 alignment diagnostics。
4. RGB 不导入该模块；若后续形成 RGB×Behavior 路线，在 `rgb-dev` 使用独立模块，避免两个分支同时改同一实现。

## 3. 输入契约

### 3.1 Behavior

复用：

```text
configs/behavior_formal.yaml
src/attention_pipeline/behavior_formal/extract.py
```

正式输入仍为：

```text
sub-XXX_Block1_B_beh.csv
sub-XXX_Block2_B_beh.csv
```

保留原始 27 列以及 `source_file/source_row` provenance。程序原始 `correct / commission / omission / rt` 不被新的 QC 逻辑覆盖。

### 3.2 NIR

权威 frame-level source 是现有 subject-specific full-class CSV，例如：

```text
sub-031_ritnet_fullclass_v1-2-fast-qc.csv
```

不再复制第二份 `frame_level_nir.csv`。该文件本身已经是一帧 × 一眼，并保留 `phase / phase_segment / frame_idx / video_time_ms / unix_ms / eye`。

主要分析字段：

```text
fullclass_pupil_to_iris_diameter_ratio
fullclass_normalization_valid
fullclass_ocular_aperture_ratio_median
fullclass_ocular_aperture_ratio_p90
```

解释规则：

- raw pupil px 不作为主要瞳孔指标；PIR 使用外虹膜作同帧尺度参照。
- PIR 只有在 `fullclass_normalization_valid == True` 时进入 PIR 特征。
- OAR 是可见眼球纵向高度 / ocular bbox width 的无量纲连续开合度指标，不是 EAR、blink 或 PERCLOS。
- `roi_clipped` 仅作为辅助 QC 描述，不作为自动排除门。
- 当前不融合左右眼，不对 NIR 定义 closed state。

## 5. 时间对齐

行为事件使用：

```text
absolute_onset_time
probe_onset_time
```

NIR 使用：

```text
unix_ms
```

同一 block 内定义：

```text
relative_ms = nir.unix_ms - event_onset_ms
```

窗口采用半开区间 `[start, end)`。只使用对应 `block1` 或 `block2` 的 NIR；Block 开头的长窗口如果数据不足，不向前吸收 practice/rest/上一 block 数据，而是通过实际 `n_nir_rows` 与 valid fraction 显式暴露覆盖不足。

## 6. `trial_level.csv`

一行 = 一个正式 SART trial。sub-031 应为 864 行。

至少保留：

```text
subject / block_num / trial_num / global_trial_index
cycle_num / position_in_cycle / condition
absolute_onset_time / next_trial_onset_time / time_in_block_sec
stimulus_name / stimulus_size / is_no_go
prev_stimulus_name / prev_stimulus_size / prev_is_no_go
response / rt / response_time / correct / commission / omission
raw_keypresses / prestimulus_press_ms
probe fields
source_file / source_row
```

行为侧新增非破坏性 QC：

```text
n_raw_keypresses
first_raw_keypress_ms
second_raw_keypress_ms
rt_reconstructed_ms
rt_reconstruction_error_ms
prestimulus_press_flag
prestimulus_delta_to_onset_ms
multiple_keypress_flag
rt_candidate_lt_100_flag
rt_candidate_lt_150_flag
rt_candidate_lt_200_flag
rt_candidate_gt_900_flag
rt_candidate_gt_1000_flag
rt_candidate_gt_1150_flag
previous_second_press_to_current_onset_ms
carryover_candidate_flag
ambiguous_omission_flag
anticipatory_candidate_flag
```

100/150/200 ms 等仅是候选描述标签，**不是当前正式排除阈值**。最终阈值需等待 116 人总体分布后冻结。

额外保存 `nir_rows_trial_left/right`，用于检查每个 trial 的 NIR 实际覆盖，不作为当前固定 exclusion gate。

## 7. `trial_nir_windows.csv`

采用长表：一行 = `trial × window × eye`。左右眼永久分开。

### 7.1 Event-adjacent 窗口

```text
pre_200ms       [-200, 0)
post_200ms      [0, 200)
post_200_1150ms [200, 1150)
```

这些窗口用于事件对齐和 PLR/视觉历史分离，不直接等同于持续注意状态。

### 7.2 State / prediction 候选窗口

```text
pre_1s
pre_3s
pre_5s
pre_10s
pre_20s
pre_30s
pre_60s
```

当前全部保留用于 prototype 和后续时间尺度比较；传统推断分析不得在全样本中试完所有窗口后只报告最显著者。主窗口/robustness 窗口需要在群体正式模型前冻结；预测分析可在被试级交叉验证的训练折中选择窗口。

### 7.3 每个窗口的 NIR 特征

PIR 与 OAR 均计算：

```text
n_valid
median
mean
MAD
IQR
SD
P10 / P90
binned-median slope per second
successive-difference MAD
successive-difference-rate MAD per second
```

其中 slope 使用少量等时间 bin 的中位数后再拟合线性斜率，避免对全量 30-Hz 数据使用计算量过高的逐帧 Theil/Siegel slope，同时降低少数分割尖峰影响。

还保留：

```text
n_nir_rows
pir_valid_fraction
oar_valid_fraction
roi_clipped_fraction
ritnet_found_fraction
ocular_fragmented_candidate_fraction
```

### 7.4 Probe contamination 信息

Trial 长窗口必须额外记录：

```text
n_probes_in_window
window_crosses_probe
last_probe_before_trial_ms
time_since_last_probe_sec
```

因为 probe 会中断任务并诱发自我反思，后续可在模型中控制或做排除跨 probe 窗口的敏感性分析，不能在生成阶段丢失该信息。

## 8. `probe_windows.csv`

一行 = `probe × window × eye`。当前候选：

```text
10 s / 20 s / 30 s / 60 s
```

这些时间窗反映持续注意/警觉状态的不同尺度；probe 文案中的“前一刻/过去几个试次”用于减少回顾偏差，不等于要求生理分析只能使用几秒。

每行同时保存：

1. probe response / vigilance 与 RT；
2. 同窗 PIR/OAR 水平、变异、趋势、变化强度；
3. 同窗客观 SART：trial 数、Go/No-Go 数、Go RT median/MAD/IQR/CV、commission、omission、prestimulus/anticipatory candidate 数；
4. 上一个 probe 信息：

```text
previous_probe_onset_ms
seconds_since_previous_probe
window_crosses_previous_probe
seconds_of_window_before_previous_probe
```

这样后续可比较固定 60 s 窗口与“上一次 probe 后至当前 probe”的连续状态，而无需重新读取原始数据。

## 9. Window coverage reports

每次对齐同时生成：

```text
sub-XXX_trial_window_coverage.csv
sub-XXX_probe_window_coverage.csv
```

一行 = `subject × block × eye × window` 的描述性覆盖摘要。它们用于回答两个不同问题：

1. **窗口里到底有多少 NIR 行**：`n_nir_rows`、`nir_rows_per_sec` 的 median/P10/min，以及零 NIR 窗口比例；
2. **已有 NIR 行中指标有多少可用于分析**：`pir_valid_fraction`、`oar_valid_fraction` 的 median/P10/min，同时保留 `roi_clipped_fraction` 与 `ritnet_found_fraction` 描述。

这里故意同时保留 row-density 和 metric-validity，因为“这个窗口根本没采到足够 NIR”与“采到了 NIR，但 PIR normalization 无效”不是同一种缺失机制。

**Prototype 阶段 coverage 只做描述，不根据 sub-031 冻结任何排除阈值。** 最终 `valid_fraction`、最低 row-density 或单眼可用性规则必须等待 116 人 cohort distribution 后决定。

## 10. Alignment diagnostics 的绘图边界

Timeline 图使用每秒中位数，仅用于检查时间轴和信号连续性，不进入正式统计。

- Probe 时刻用细竖线标出；Block1/Block2 起点用更明显的虚线及标签标出。
- 若相邻每秒摘要之间的数据间隔超过配置中的 `diagnostics.max_line_gap_sec`（当前 2.5 s），绘图自动插入断点，**不再跨休息或长缺失段画人工长斜线**。
- 这个 gap break 只改变图片连接方式，不插值、不删除、不修改 CSV 数值。
- Probe-centered PIR QC 当前使用 **5 s bins**：先在每个 probe×eye×bin 内取 PIR median，再跨 probe 取 median；图标题明确记录 bin 宽和 probe 数。它用于检查 trajectory 构造是否正常，不用于 sub-031 单被试效应推断。

## 11. 刺激视觉协变量

Phase 1 先完整保留当前与上一 trial 的：

```text
stimulus_name
stimulus_size
prev_stimulus_name
prev_stimulus_size
```

后续单独生成版本化 `stimulus_visual_properties.csv`，按 FocusWave 实际绘制规则重建：

```text
刺激.png + scaled fruit PNG
```

正式组合共 9 个刺激 × 3 个 size = 27 种。视觉表至少考虑 rendered/central luminance 与 contrast，然后通过 `stimulus_name + stimulus_size` join；视觉定量算法改变时只重算 27 行，不重跑 NIR 和时间对齐。

在视觉表完成前，不在 prototype 中把 PNG 文件本身的平均亮度伪装成已经冻结的 PLR 控制变量。

## 12. Provenance 与 completion

每次 subject run 保存：

- 两个 Behavior 源 CSV 路径与 SHA256；
- full-class CSV 路径与 SHA256；
- full-class completion 与 extension version；
- alignment config digest；
- alignment schema/pipeline version；
- Git commit（可获取时）；
- 候选时间窗完整定义；
- 选中的 production NIR run 与其他候选 output run；
- trial/probe coverage 文件路径。

只有 identity 完整一致且 `status=complete` 时才允许 skip。Behavior、NIR 或 config 任何一个改变都必须重建下游结果。Coverage CSV 现在也属于 completion required artifacts，不能缺失后仍标记完整。

## 13. sub-031 prototype 验收条件

prototype 不用于群体结论；验收的是工程正确性：

1. `trial_level` = 864 行，B1/B2 各 432；
2. 20 个正式 probe 被完整识别；
3. trial/probe windows 行数符合 `事件数 × 窗口数 × 眼数`，缺眼时仍可通过输出明确发现；
4. `absolute_onset_time / probe_onset_time ↔ unix_ms` 范围合理；
5. sub-031 已知双按、prestimulus、ambiguous omission 模式能在 trial-level 保留；
6. 左右眼不提前融合；
7. PIR 只从 `normalization_valid` 帧计算，OAR 独立保留；
8. `roi_clipped` 不被自动删除；
9. QC timeline 中 trial/probe 与 NIR 时间顺序无明显整体偏移，休息/长缺失不被直线跨接；
10. trial/probe coverage 能区分 row-density 与 PIR/OAR validity；
11. 输出带 manifest/summary/completion，源文件或配置变化后不会静默复用旧结果。

sub-031 已完成首次结构性 prototype：864 trial、20 probe、17,280 条 trial-window、160 条 probe-window，左右眼四个 block-eye 组合均存在。该事实只验证工程结构，不用于冻结群体效应或 QC cutoff。

通过 prototype 后才把 `subjects.include` 从 `sub-031` 改为全量发现，等待其余 115 人 full-class 完成后批量运行。

## 14. 当前尚未冻结的研究决策

以下不在 sub-031 阶段决定：

- RT 最终 anticipatory/exclusion threshold；
- NIR valid-fraction / row-density 排除门；
- 左右眼中心化/融合公式；
- 传统推断分析的 primary trial/probe window；
- PIR/OAR 的 subject×eye 个体内标准化方法；
- NIR blink/PERCLOS 阈值（当前不定义，RGB 路线负责补充）；
- 最终 mixed model / GAMM / ML 超参数；
- 问卷正式变量与旧版前四名被试的兼容处理；
- rendered luminance/contrast 的最终算法。

这些项目必须在相应数据与群体 QC 可用后显式冻结，不能由 sub-031 单例倒推出全样本规则。
