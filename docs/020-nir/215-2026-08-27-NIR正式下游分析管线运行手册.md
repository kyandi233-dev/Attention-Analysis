## 6. 中断、断电与续跑

`11_analysis_tables` 采用 subject-level completion identity。正常重复执行时：

- completion identity 一致的 subject → `skipped / validated_completion`；
- 从未完成的 subject → 正常生成；
- 上次运行中途被打断、没有有效 completion 的 current subject → 重新构建该 subject；
- 不需要删除已经完成的 subject 输出；
- 不需要使用 `--force-tables` 才能续跑。

统一入口现在会在 cohort 开始前以及每完成一个 subject 后原子更新：

```text
11_analysis_tables/cohort_manifest.json
```

manifest 的 `status` 可能是：

```text
running
running_with_failures
interrupted
complete
partial
```

若用户按 `Ctrl+C` 或进程收到 `KeyboardInterrupt`，manifest 会先写成：

```text
status = interrupted
current_subject = sub-XXX
```

然后才退出。下次仍使用同一命令：

```powershell
python scripts/nir_formal_pipeline.py --stage tables
```

程序会从已有 completion 状态自动恢复，而不是从第一个 subject 强制重算。

**不要**为了续跑而：

```text
删除 11_analysis_tables
--force-tables
git reset --hard
```

当前 2026-08-27 的实际开发运行曾在 `sub-031`–`sub-041` 共 11 人完成后人为中止；旧版本只留下 representative cohort manifest。新增 resumable runner 后，需要用少量被试验证 manifest 的 `interrupted → resume` 行为即可，不要求为了这个测试立即跑完剩余 33 人。

## 7. 什么时候才重新 materialize

当前 44 人 `10_analysis_ready` 已经完成。一般情况下不要重复运行。

只有以下情况才重建：

- analysis-ready 代码或 schema 被明确升级；
- source production 新增正式被试；
- 已确认需要补充新的只读派生字段；
- provenance 明确要求生成新的 snapshot。

单独运行：

```powershell
python scripts/nir_formal_pipeline.py --stage materialize
```

若目标 derived 文件已经存在，默认拒绝覆盖。只有明确需要重建时才：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage materialize `
  --overwrite-derived
```

`--overwrite-derived` 只授权覆盖 `10_analysis_ready` 派生文件，不授权修改 frozen production。

## 8. 从头重建完整下游派生层

仅在明确需要重建当前 cohort snapshot 时：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage all `
  --overwrite-derived `
  --force-tables
```

含义：

```text
production
→ 10_analysis_ready
→ 11_analysis_tables
```

仍然不会运行 YOLO / RITnet。

## 9. `--force-tables` 什么时候用

正常重复运行时，completion identity 一致的被试会自动跳过。

只有明确要重建 `11_analysis_tables` 时：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage tables `
  --force-tables
```

不要把 `--force-tables` 当成日常默认参数，也不要把它用于普通断点续跑。

## 10. 运行后 Codex 必须检查

不能只报告“命令完成”。至少报告：

1. 测试结果；
2. 发现 subject 数、processed / validated / failed 数；
3. `cohort_manifest.json` 的 `status`；
4. 每名被试 completion 是否 complete；
5. trial / probe / time-on-task 行数是否符合预期；
6. 是否存在 missing block track；
7. coverage 是否出现明显异常或大段技术缺口；
8. 输出是否只写入 `11_analysis_tables`；
9. `10_analysis_ready` 与 production 是否保持未修改；
10. 最后 `git status --short --branch`。

若运行被人为中止，必须明确报告 `status=interrupted`、`current_subject`、已经 validated 的 subject 数，不得把 partial manifest 描述为完整 cohort manifest。
