
## 6. 什么时候才重新 materialize

当前 44 人 `10_analysis_ready` 已经完成。一般情况下不要重复运行。

只有以下情况才重建：

- analysis-ready 代码或 schema 被明确升级；
- source production 新增正式被试；
- 已确认需要补充新的只读派生字段；
- provenance 明确要求生成新的 snapshot。

单独运行：

```powershell
python scripts/nir_formal_pipeline.py --stage materialize
```

若目标 derived 文件已经存在，默认拒绝覆盖。只有明确需要重建时才：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage materialize `
  --overwrite-derived
```

`--overwrite-derived` 只授权覆盖 `10_analysis_ready` 派生文件，不授权修改 frozen production。

## 7. 从头重建完整下游派生层

仅在明确需要重建当前 cohort snapshot 时：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage all `
  --overwrite-derived `
  --force-tables
```

含义：

```text
production
→ 10_analysis_ready
→ 11_analysis_tables
```

仍然不会运行 YOLO / RITnet。

## 8. `--force-tables` 什么时候用

正常重复运行时，completion identity 一致的被试会自动跳过。

只有明确要重建 `11_analysis_tables` 时：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage tables `
  --force-tables
```

不要把 `--force-tables` 当成日常默认参数。

## 9. 运行后 Codex 必须检查

不能只报告“命令完成”。至少报告：

1. 测试结果；
2. 发现 subject 数、成功数、失败数；
3. `cohort_manifest.json` 是否存在；
4. 每名被试 completion 是否 complete；
5. trial / probe / time-on-task 行数是否符合预期；
6. 是否存在 missing block track；
7. coverage 是否出现明显异常或大段技术缺口；
8. 输出是否只写入 `11_analysis_tables`；
9. `10_analysis_ready` 与 production 是否保持未修改；
10. 最后 `git status --short --branch`。
