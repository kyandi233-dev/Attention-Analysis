## 1. 任务目的

本任务只处理 NIR 时间戳 CSV 第一列 capture counter 与 AVI 顺序帧编号之间的映射问题，并验证它是否解释此前 `sub-100` / `sub-178` 被判定为 block 内 NIR frame gap 的现象。

不要修改 RGB scientific/runtime 代码，不启动 RGB 分析，不开始新的 NIR 特征探索或最终分类模型。

待吸收的候选修复来自临时分支：

`codex/rgb-nvidia-formal-pipeline-v1@8c32eaaf31f2404646103986df11c64a3c37c9f2`

commit message：`fix(nir): map capture timestamps to sequential AVI frames`

核心语义：timestamp CSV 第一列为采集设备 capture-frame counter，可能因采集丢帧而跳号；timestamp 文件的有效行与实际写入 AVI 的顺序帧一一对应。正式 NIR 分析应使用 sequential AVI frame index 映射 `unix_ms`，同时保留原始 capture counter 作为 provenance，而不能把 capture counter 跳号直接当作 AVI 文件内部缺帧。

先运行新增单元测试和与 NIR formal active surface 相关的既有测试。

## 3. 第二阶段：建立 regression validation set

至少选择三类 session：

### A. 正常控制 session

从已经完成且此前没有 frame-gap blocker 的正式 NIR session 中选择 2–3 个，优先覆盖普通连续 capture counter 与存在轻微 capture counter 跳号但过去仍成功的情况（若存在）。

目标：确认新映射不会无故改变正常 session 的：

- AVI frame count
- phase start/end unix_ms
- phase frame span
- Probe/window 时间对齐
- YOLO/RITnet/fullclass 已有科学输出的时间语义
- completion/QC 资格

不要求重跑所有模型。优先通过 timestamp/phase resolver dry-run、已有 manifest 对比或最小必要正式重跑验证。

### B. `sub-100`

此前 blocker：NIR frame gap inside block1。

检查：

1. timestamp CSV 原始第一列是否存在 capture-counter jump；
2. 有效 timestamp 行数是否与 AVI frame count 一致；
3. 用 sequential AVI frame mapping 后，block1 是否仍然存在真正的 AVI frame discontinuity；
4. `master_timeline` 与 Probe unix-ms 是否能正常落入对应 NIR 时间轴；
5. 如果映射修复后 phase/window 合法，运行最小正式恢复验证；
6. 若通过，再判断该 session 是否可以加入后续 fullclass / Probe-window 分析。

### C. `sub-178`

同上，但此前 blocker 位于 block2。

## 4. 严格区分三类“gap”

输出必须分别记录：

1. `capture_counter_gap`：采集设备计数跳号；
2. `timestamp_time_gap`：相邻有效帧 unix_ms 间隔异常；
3. `avi_decode/frame_gap`：AVI 实际缺帧、解码失败或 timestamp 行数与 AVI 帧数不一致。

只有第 3 类可以继续作为“AVI 帧缺失” blocker。不得继续把第 1 类自动等同于第 3 类。
