# NIR 正式分析设计与待验证项

> 2026-08-25（Asia/Shanghai）｜工作分支：`amd-DirectML`。本文件记录当前 NIR-only 分析阶段已经明确的变量语义、行为对齐原则、统计路线、质量控制与尚未冻结的决策。RGB 分析在独立 `rgb-dev` 分支推进，本文件不修改 RGB 方法与变量定义。

## 1. 当前研究范围与样本

- 北京正式样本按 **116 名被试**处理；此前 114 为误记。
- 不要求所有分析拥有完全相同的有效 N。行为、NIR、probe、问卷按被试 ID 对齐后，各模型根据所需数据完整性形成 analysis-specific N，并报告纳入/排除原因。
- 当前 NIR 正式链路仍为：FocusWave v3.1.3 phase windows → YOLO26n 双眼检测 → 放大 ROI → RITnet 四分类分割 → 瞳孔/虹膜/可见眼球几何派生量。
- 原始像素尺度仅作为中间测量和 QC 信息；正式生理解释优先使用尺度无关或个体内标准化后的指标。

## 2. 瞳孔主指标：使用外虹膜作同帧几何参照

单独使用 `pupil_*_px` 不能充分区分真实瞳孔变化与摄像距离、头部前后移动造成的整体缩放，因此 raw pupil px 不作为主要统计指标。

当前 full-class extension 已经冻结主指标：

```text
fullclass_pupil_to_iris_diameter_ratio
```

RITnet 的 class 2 是可见虹膜组织，瞳孔孔洞由 class 3 单独表示，因此外虹膜参考不是直接使用 class 2，而是先重建：

```text
iris_outer = iris OR pupil
           = class 2 OR class 3
```

随后分别拟合 pupil 与 iris_outer 椭圆，使用几何平均直径构造：

```text
PIR_D = sqrt(pupil_axis_a * pupil_axis_b)
        ----------------------------------
        sqrt(iris_axis_a * iris_axis_b)
```

这比直接使用 pupil px 或把 class-2 iris 面积当分母更合理：摄像距离引起的整体缩放会同时作用于瞳孔与外虹膜，而 class-2 可见虹膜组织本身会随瞳孔扩缩发生机械面积变化。

正式 pupil 分析优先使用 `fullclass_pupil_to_iris_diameter_ratio`，并要求 `fullclass_normalization_valid == True`。ellipse-area ratio 与 contour-area ratio 可作为 secondary / robustness measures。用于实时预测时，任何进一步的 subject-level 标准化不得使用被试未来时段计算全程基线，避免信息泄漏。

## 3. RITnet 派生眼睑开合度：`fullclass_ocular_aperture_ratio`

当前 CSV 有两个版本：

```text
fullclass_ocular_aperture_ratio_median
fullclass_ocular_aperture_ratio_p90
```

它们不是 pupil 指标，也不是 MediaPipe EAR，而是基于 RITnet 四分类全图得到的可见眼球几何比例。

先定义：

```text
ocular = sclera ∪ iris ∪ pupil
```

即把巩膜、虹膜、瞳孔合并为当前可见眼球区域。取得该区域的水平 bbox 宽度 `width`，并只在中间 80% 横向范围内逐列计算可见眼球高度：

```text
h_x = y_max,x - y_min,x + 1
```

随后：

```text
fullclass_ocular_aperture_ratio_median = median(h_x) / ocular_bbox_width
fullclass_ocular_aperture_ratio_p90    = p90(h_x)    / ocular_bbox_width
```

该比值已经通过“高度 / 宽度”降低 ROI 大小和摄像距离整体缩放的影响，是无量纲指标。`median` 更稳健，优先作为 NIR 开合度连续特征；`p90` 更接近局部最开处高度，但更容易受异常分割列影响。

该指标目前不能直接命名为 blink 或 PERCLOS。若后续需要把连续开合度转成 closure proportion / closed state，仍需解决个体眼形差异、左右眼差异、unknown 帧、时序阈值与人工效度验证。

## 4. `roi_clipped` 的正确语义

`roi_clipped` 不表示 YOLO 只检测到部分眼睛。当前逻辑是 YOLO 已检测眼睛后，为 RITnet 输入对眼框进一步放大；放大后的 ROI 若碰到原始画面边界，则标记 clipped。

因此：

- `roi_clipped` **不是自动坏帧条件**；
- 大量 clipped 帧仍可能包含完整眼睛；
- 不因 clipped 比例高就自动删除整只眼或整名被试；
- clipped 只保留为辅助 QC 变量，真正有效性应由眼球实际可见程度、RITnet 分割几何、时间连续性与人工抽检共同判断；
- 可在正式模型后做“含 clipped / 排除 clipped”的敏感性分析。

## 5. 行为刺激与视觉协变量

正式水果大小不是固定值。行为任务逐 trial 记录 `stimulus_name` 和 `stimulus_size`，代码按：

```text
actual_size = BASE_SIZE × stimulus_size / 100
```

绘制刺激。因此视觉控制变量可从行为 CSV 精确重建，不需要从视频猜测水果尺寸。

实验显示亮度固定，实验室照明大体固定，这降低了跨被试外源亮度差异；但水果种类、大小和局部对比度仍可能引起瞳孔光反射（PLR），需要在 trial-level pupil 模型中控制。

计划至少保留：

```text
current_stimulus_name
current_stimulus_size
previous_stimulus_name
previous_stimulus_size
```

如后续完成刺激图像定量，可进一步加入当前/前一刺激的局部亮度、对比度等协变量。

## 6. Trial onset 前后的视觉历史

当前 trial 的水果 onset 定义为 `t = 0`。正常情况下，onset 前约 `-200~0 ms` 屏幕上主要是固定 mask，而不是上一水果；但瞳孔反射存在生理延迟，因此该窗口的瞳孔状态仍可能携带上一刺激留下的 PLR / 恢复过程。

因此：

- 不把 `-200~0 ms` 简单解释成“完全不受视觉历史影响”；
- current fruit 的即时 PLR 尚未来得及充分出现，但 previous fruit 的延迟反应可能仍存在；
- trial-level 模型应考虑 previous stimulus 的视觉协变量；
- onset 前后短窗主要用于事件对齐和视觉反应分离，不等同于持续注意状态的唯一分析窗口。

## 7. Probe 前窗口：不因题目写“前一刻/过去几个试次”就限定为极短窗口

Probe 的措辞主要用于让被试报告最近、真实的主观状态，而不是要求生理分析只覆盖前一个 trial 或数秒。持续注意与警觉状态往往具有慢变化特征，因此 probe prediction 需要同时比较中短时和较长时窗。

当前原则：

- 不预先只固定 3–5 s 极短窗；
- 候选窗口应覆盖多个时间尺度，例如约 10/20/30/60 s 或经数据质量和 probe 间隔调整后的相近组合；
- 传统推断分析不能“把所有窗口都试一遍，只报告最显著的一个”；
- 若目标是纯预测，可把窗口长度作为模型/特征工程候选，但必须在被试级交叉验证框架内选择，并在独立测试折评价；
- 最终主窗口与探索窗口需在正式全量模型前冻结并记录理由。

## 8. NIR 动态特征不能只看平均大小

对尺度校正后的 pupil 指标和 `fullclass_ocular_aperture_ratio_median`，候选特征至少包括：

| 特征类型 | 示例 | 含义 |
|---|---|---|
| 水平 | median / trimmed mean | 当前状态水平 |
| 趋势 | robust slope | 窗口内持续增大或减小 |
| 波动 | MAD / IQR / SD | 状态稳定性 |
| 短时变化强度 | successive-difference MAD | 帧间变化幅度 |
| 阈值/事件 | closure candidate count、duration | 对眼睑更合适 |

标准差/离散程度不等于“变化频率”。真正的频率类指标需要基于事件次数、阈值穿越或明确的时间频谱定义；第一版 pupil 分析不优先堆叠高维频谱特征。

## 9. 行为按键必须先做 trial-level 审计

行为程序会记录不止一个摘要 RT，因此正式行为清洗前要检查：

```text
rt_ms
n_key_presses
raw_keypress_timestamps
prestimulus_press_ms
omission / commission / correct
```

重点排查：

1. 一个 trial 内是否出现多次按键，以及程序如何保留首次 RT 与后续重复按键；
2. prestimulus press 是否造成“实际上提前按了，但当前 trial 被记成 omission”；
3. 上一 trial 的晚按是否吸收了本来针对下一 trial 的预判按键；
4. `上一 trial 极晚 RT / 多次按键 + 下一 trial omission` 是否形成可识别的连续模式；
5. 极短 RT 是否代表 anticipatory response。

原则上不直接把人工推断的按键从上一 trial 搬到下一 trial，而是保留原始评分，额外建立 anticipatory / ambiguous QC 标记，并进行主分析与敏感性分析。

## 10. 四层数据表

正式整合建议形成四张核心表：

| 表 | 一行代表 | 主要用途 |
|---|---|---|
| `frame_level_nir` | 一帧 × 一眼 | pupil/iris、aperture、QC、时序事件 |
| `trial_level` | 一个 SART trial | RT/错误 × NIR × 当前/前序视觉刺激 |
| `probe_window` | 一个 probe × 一个候选时间窗 | 主观注意/警觉预测与 trajectory |
| `subject_summary` | 一个被试 | 问卷 × 总体行为 × time-on-task NIR |

所有表通过被试 ID、block、trial/time reference 对齐，并保留可追溯到原始帧/行为行的键。当前 full-class CSV 已保留 `phase / phase_segment / frame_idx / video_time_ms / unix_ms / phase_time_ms`；trial-level 下游对齐优先使用 full-class `unix_ms` 与行为 trial absolute timestamp，不用 frame count 作为主时间锚。

## 11. 客观行为、Probe、问卷之间的效度链

NIR 不应孤立分析。需要至少建立：

```text
Questionnaire ↔ Objective SART ↔ Probe ↔ NIR
```

重点包括：

- Probe 状态是否对应临近 trial 的 RT variability、omission/commission、time-on-task 等客观行为变化；
- 问卷/实验前状态是否对应总体行为、Block 变化或 NIR 持续状态指标；
- NIR 是否在主观低警觉或客观错误前出现可重复的变化；
- 不要求每一条链都显著，效度分析用于判断不同测量到底在反映同一状态、相邻状态还是相对独立的过程。

## 12. Trajectory 与时间模型

`pupil trajectory` / `aperture trajectory` 指指标在某事件之前随时间变化的曲线，而不是一个新的生理变量。例如把 probe 定义为 `t=0`，向前取 60 s，再按 5 s bin 汇总，就得到 12 个连续时间点。

可先使用较透明的 mixed model 检验 `state × time-to-probe`，而不是每个时间点分别做大量 t 检验。若真实曲线明显非线性，再考虑 GAMM。

如对多个时间点分别检验，需要 FDR 或 cluster-based correction 控制 multiple comparisons；优先先做整体时间效应/交互，再解释具体时段。

## 13. 统计推断与机器学习的分工

传统混合模型用于解释效应，机器学习用于测试多特征组合的预测能力，两者可以同时存在。

| 目标 | 首选方法 |
|---|---|
| 连续 RT / 连续 NIR 指标 | LMM |
| No-Go error、omission 等 0/1 结果 | Logistic GLMM |
| 1–4 有序警觉等级 | Ordinal mixed model |
| 无序的多类别 probe 状态 | Multinomial / categorical mixed model |
| 非线性时间轨迹 | GAMM（必要时） |
| 多个 NIR 特征预测状态/错误 | Elastic Net、Random Forest、XGBoost 等 |

随机森林、XGBoost、神经网络并不只用于多模态。仅使用 pupil、aperture、趋势、波动、closure 等多个 NIR 特征，也属于单模态内部多特征融合。

但独立样本量的核心仍是被试数量而不是帧数。机器学习必须采用 **subject-grouped cross-validation**：同一被试的帧/trial/probe 不能同时进入训练和测试折。否则模型可能学习被试身份而不是注意状态。

第一版不优先使用神经网络；先建立可解释 baseline（混合模型 / logistic / Elastic Net），再比较 Random Forest / XGBoost 是否有稳定增益。

## 14. 人工视频 / ROI 验证

人工验证不等于重新训练模型，也不需要 116 名被试逐帧标注。

full-class extension 已设计固定的 sparse QC 图像策略：周期抽样、每个 phase segment 的首/中/末帧，以及有限数量的 `roi_clipped / ritnet_missing / normalization_invalid / ocular_fragmented` 异常样本；每个选中眼睛保留四分类 `labels` 图和原灰度 ROI 的 segmentation overlay。这些图像可优先作为人工审计材料，不需要重新从全部视频人工截图。

如仍需冻结 closure 阈值，可再采用分层抽样 QC：

- 覆盖多个被试、左右眼、不同数据质量；
- 对 aperture 高/中/低、pupil/iris 极端值、突然跳变、连续低值等区域抽取帧或短片段；
- 人工检查原始 ROI 与 RITnet mask overlay，判断是真实眼睑/瞳孔变化还是 segmentation artifact；
- 如未来要冻结 closed threshold，可给抽样帧标注 open / partial / mostly closed / closed（或更粗的 closed/not-closed），用 ROC/一致性检查阈值；
- 可由第二名标注者复核一部分样本评估一致性；
- 这一步用于效度和阈值验证，不是训练新网络。

## 15. 当前仍未冻结的问题

以下事项必须在正式全量统计前确认：

1. `fullclass_ocular_aperture_ratio_median` 是否需要额外 subject×eye baseline normalization 才用于 closure proportion / 阈值化解释；
2. probe / No-Go / arousal 各自的主时间窗与探索时间窗；
3. 多次按键与 prestimulus press 在真实行为 CSV 中的频率和模式；
4. 水果/No-Go 刺激的完整图像亮度与对比度协变量是否需要进入主模型还是只做敏感性控制；
5. 人工 NIR 验证若用于 closure 阈值冻结时的抽样规模、人工标签层级和阈值规则；
6. 机器学习的目标变量、特征集和 subject-grouped CV 方案。

这些项目在验证前保持“候选/待冻结”状态，不通过代码默认值或一次显著结果静默固定。
