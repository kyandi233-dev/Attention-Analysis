## 3. NIR 结果目录的实际形态

### 3.1 目录和被试计数

- 根目录存在 45 个名称以 `sub-` 开头的目录，但只有 44 个唯一被试编号。
- 44 个唯一编号均有一份 `*_ritnet_fullclass_v1-2-fast-qc_completion.json`，且 `status=complete`、`extension_version=ritnet-fullclass-v1.2-fast-qc`。
- `sub-035_formal_v3.1.3_yolo_b16_fp32` 是一个旧/不完整并存目录，仅含 `completion.json` 与 `phase_windows.json`，没有 full-class fast-QC CSV；真正的 `sub-035` 完成结果位于 `sub-035_formal_v3.1.3_yolo-b8_ritnet-b16_fp32`。分析时必须按 completion marker 选择完成结果，不能把两个目录拼接。
- 完成结果目录分为前 4 个 `sub-031`–`sub-034` 的 `yolo_b16_fp32` 命名和其余 40 个 `yolo-b8_ritnet-b16_fp32` 命名。当前 marker 中的 RITnet 科研口径相同，但上游运行目录命名不同，应保留作为 provenance。

根目录文件类型统计为 `.csv` 177 个、`.json` 315 个、`.png` 6,568 个、`.jpg` 712 个。PNG/JPG 主要是 QC、label/overlay 或运行辅助图像；后续 cohort 分析的主输入不是把所有图片重新读取，而是按 marker 定位的 44 个 fast-QC CSV。

根目录的两个批处理汇总不能单独作为 44 人清单：`ritnet_fullclass_batch_summary.json` 当前记录 43 条，`batch_run_summary.json` 记录 4 条。最终被试和完成状态以逐被试 fast-QC completion marker、CSV、summary、manifest 和 QC index 的一致性为准。

### 3.2 主 CSV 与附件

每个完成被试的 canonical full-class 结果文件为：

```text
sub-XXX_formal_.../sub-XXX_ritnet_fullclass_v1-2-fast-qc.csv
```

同目录通常还包含：

- `*_summary.json`：处理行数、解码帧数、normalization-valid 计数/比例、速度和均值摘要；
- `*_manifest.json`：源 `eyes.csv`、模型哈希、输入尺寸、运行设备、产物哈希和所需附件；
- `*_qc_index.csv`：抽样 QC 帧、reason、RITnet found、ROI clipped、normalization valid 与 label/overlay 文件引用；
- `completion.json`、`run_manifest.json`、`phase_windows.json`：上游正式运行完成状态、运行身份和 phase 窗口。

逐帧×眼 CSV 的内容层次包括：subject/video/phase/phase segment/frame/time/eye/source/status；YOLO 眼框和 ROI；RITnet device/precision/batch；原始瞳孔结果；四类 mask 的像素数/比例；ocular 连通分量和 aperture 几何；PIR 相关比例、中心偏移和 normalization-valid；以及 source/full-class parity 与 QC 字段。

当前冻结的下游关键字段是：

- PIR：`fullclass_pupil_to_iris_diameter_ratio`，只有 `fullclass_normalization_valid=True` 才进入 PIR 特征；
- OAR：`fullclass_ocular_aperture_ratio_median` / `fullclass_ocular_aperture_ratio_p90`，是基于 `sclera ∪ iris ∪ pupil` 的可见 ocular aperture 指标；
- OAR 不等同于 EAR、blink、closed state 或 PERCLOS；当前数据里的结构/QC字段不能直接改名为眨眼标签。

### 3.3 必须在分析前处理的 schema 差异

44 个 fast-QC CSV 不是完全同一列数：

| 文件组 | 数量 | 表头 |
|---|---:|---:|
| `sub-031`–`sub-034` | 4 | 106 列 |
| `sub-035`–`sub-177` 的其余完成结果 | 40 | 107 列 |

差异是后 40 份在 `ritnet_found` 前增加了 `yolo_batch_size`，其余字段按同一逻辑顺序延续。这个差异不应通过位置索引静默处理；后续读取必须按列名对齐，并在 cohort preflight 中检查所有 44 份表头、类型和关键字段是否一致。

## 6. 44 人后续全量分析的直接入口与风险

在用户提供分析计划后，建议按以下顺序执行：

1. 以 44 个 `*_ritnet_fullclass_v1-2-fast-qc_completion.json` 建立 cohort discovery 清单；
2. 按列名统一 106/107 列 CSV，核验 `yolo_batch_size` 的新增差异不改变其他字段含义；
3. 汇总 subject×eye×block 的 rows、时间跨度、phase 覆盖、PIR normalization-valid、OAR availability、ROI clipped、RITnet found 和 temporal gap；
4. 再与正式 Behavior B1/B2 及问卷字段联结；
5. 先输出描述性 QC 和异常标记，再根据分析计划冻结阈值、标准化、左右眼处理和模型结构。

当前不能从这份资料识别记录直接推出：

- 哪些 subject×eye×block 应排除；
- PIR/OAR 的最终 QC 阈值；
- 左右眼是否平均或保留为重复测量；
- primary trial/probe window；
- 行为模型、视觉协变量和机器学习设置。

这些属于后续分析计划或 cohort QC 决策，不能由单个被试、文件名或当前 valid fraction 自动替代。
