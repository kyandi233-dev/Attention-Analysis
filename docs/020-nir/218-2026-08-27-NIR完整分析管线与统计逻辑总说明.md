# 218｜NIR 完整分析管线与统计逻辑总说明

> 2026-08-27｜工作分支：`analysis/multimodal-integration`。本文不是新的零散分析清单，而是把当前 NIR 数据从逐帧测量到正式统计的**完整逻辑链**统一收口。它同时说明主分析、Behavior/Probe 联合分析、QC、敏感性分析以及后续 OAR/问卷/RGB 扩展应该分别发生在哪一层。
>
> **当前重要边界：现阶段已经生成的 NIR/PIR 数值已知错误。** 因此当前 `12_pipeline_validation` 只能把这些数值当作占位输入，用来验证数据结构、统计接口和代码生成图；所有 PIR 方向、效应量、p 值、窗口优劣都没有科学解释资格。本文定义的是**正确 NIR 重建之后应复用的分析架构**。

---

## 先把整条链看成一个问题，而不是一堆指标

NIR 分析真正要回答的不是“有哪些列可以算”，而是下面这条因果和测量链是否能被可靠地观察：

```text
被试在持续完成 SART
        ↓
注意/警觉状态随时间缓慢变化
        ↓
瞳孔水平、波动、趋势等生理信号发生变化
        ↓
客观行为出现 RT 变化、波动、遗漏、抑制失败或 anticipatory motor pattern
        ↓
Probe 时被试报告某种主观状态 / vigilance
        ↓
不同测量之间是否形成一致、可重复、可解释的关系？
```

所以正式分析必须同时保留四个尺度：

```text
连续时间尺度      → time-on-task
单次任务事件尺度  → trial / No-Go event
主观状态锚点尺度  → probe window
个体差异尺度      → subject summary / questionnaire
```

PIR 的一个均值、一个 RT 或一个 Probe 选项都只是这条链中的局部观测。如果把它们过早压成一个总分，就会丢失我们真正关心的“状态如何形成、如何恶化、如何转化成行为错误”的时间结构。

---

# 从测量开始：先保证“这个 PIR 是什么”再谈统计

NIR 的最底层仍然是逐帧、逐眼的 RITnet 派生测量。正式主指标是 pupil-to-iris diameter ratio（PIR），但统计层不会直接读取 production CSV，而要经过 `10_analysis_ready`。

当前层级固定为：

```text
YOLO / RITnet / full-class production
        ↓
10_analysis_ready
        ↓
11_analysis_tables
        ↓
12_pipeline_validation
        ↓
20_formal_statistics
```

这里的关键不是文件夹编号，而是**每一层只做一种性质的工作**。

### `10_analysis_ready`：把逐眼测量变成可解释的连续信号

这一层回答的是：“哪些帧的 PIR 可以作为测量？左右眼如何保留？个体基线如何处理？”

primary validity 不再把 whole-mask edge、`roi_clipped`、blur 等辅助 QC 全部硬塞进主纳入条件，而只要求 pupil/iris geometry 本身成立；旧 production validity 继续作为 strict sensitivity。这样主分析和严格敏感性分析不会混成同一个过滤器。

左右眼也不在这里被压缩掉。正确逻辑是：

```text
left raw PIR / right raw PIR
        ↓
分别做 subject×eye baseline
        ↓
left/right centered PIR
        ↓
两眼都有效 → binocular mean
只有一眼有效 → single-eye fallback
两眼均无效 → missing
```

因此 `binocular_PIR` 永远伴随 source mode：

```text
binocular
left_only
right_only
missing
```

这使后续任何一个 trial/probe window 都能追溯“这个 PIR 到底来自双眼还是单眼”。

### within-person 与 between-person 在这里开始分轨

注意：subject×eye 中心化后的 PIR 非常适合研究**个体内变化**，但不能再把它的 subject mean 当成真正的个体间瞳孔水平。

因此正式统计应该明确分成：

```text
within-person：centered PIR / 当前偏离自身基线多少
between-person：raw PIR baseline / 被试本身绝对 PIR 特征
```

当前 validation 已增加只读 `10_analysis_ready` 的 raw-PIR subject baseline 汇总，用来提前验证 between-person 数据接口。正式研究中，个体间差异应来自 raw baseline，而不是对已经中心化的数据再次求均值。

# 从连续信号到科学分析单位：时间窗不是清洗规则，而是问题定义

`10_analysis_ready` 保持连续时间序列；`11_analysis_tables` 才把它投影到不同科学问题需要的时间尺度。这个区分非常重要：coverage 不是逐帧清洗标准，而是“某一个具体分析窗口是否有足够的时间代表性”。

## Time-on-task：看状态是否随任务持续时间缓慢漂移

基础网格是：

```text
subject × Block × 1 second × track
```

1 s 不是最终报告单位，而是后续 mixed model / GAMM 的稳定连续时间基底。展示时可以汇总成 30 s，但模型仍保留连续时间。

这一层主要回答：

> 在一个 Block 内，PIR 是否随 time-on-task 逐渐变化？Block2 是否整体处在不同状态？不同被试的漂移速度是否不同？

图形应同时显示：

- 每名被试的淡色轨迹；
- cohort median / IQR；
- Block1 与 Block2 分开；
- 不把 Block 分别重新中心化，从而保留真实 B1→B2 shift。

统计入口以 mixed model 为主；如果曲线明显非线性，再进入 GAMM，而不是在几十个时间点分别做 t 检验。

---

## Trial：把“当前状态”与一次具体行为结果联系起来

Trial 分析不是只截一个 `pre_5s`。`11_analysis_tables` 已经同时保存两类窗口：

```text
事件邻近窗口：
pre_200ms
post_200ms
post_200_1150ms

状态窗口：
pre_1s
pre_3s
pre_5s
pre_10s
pre_20s
pre_30s
pre_60s
```

这两类窗口回答的问题不同。

事件邻近窗口主要用于区分 stimulus onset 附近的快速视觉/生理反应，尤其帮助控制 PLR 与上一刺激残留；较长的 pre-trial 状态窗口则用于描述错误发生前的 sustained-attention state。

因此正式 trial 分析应该同时保留两个逻辑：

```text
短时事件响应：当前刺激出现后发生了什么？
长期状态前兆：错误发生前几十秒是否已经逐渐偏离？
```

### PIR 不能只使用 median

每个 trial/probe window 已经保存：

```text
水平：median / mean / P10 / P90
波动：MAD / IQR / SD
趋势：robust slope per second
短时不稳定性：successive-difference MAD
短时变化速率：successive-difference-rate MAD per second
```

这些特征分别对应不同生理问题：

```text
level       → 当前瞳孔相对自身基线处在什么水平
variability → 当前状态是否稳定
slope       → 这段时间是否持续扩张/收缩
instability → 是否出现更频繁、更突发的短时变化
```

所以正式模型不会只问“PIR 大不大”，还要检验“PIR 是否更不稳定、是否正在发生趋势性改变”。当前 validation 已把这些特征全部接入 trial/probe long table 和 smoke-model 接口。

# Behavior 不是一个 accuracy：必须保留错误形成方式

SART 行为侧至少有三条彼此不同的心理过程：

```text
Go 反应速度 / 稳定性
No-Go 抑制失败（commission）
Go 持续注意失败（omission）
```

再加上真实数据中已经发现的 anticipatory / multiple-keypress 连续运动模式，单纯用 accuracy 会把这些过程混在一起。

## 正确 Go：速度之外还要分析稳定性和长尾

正式 Behavior 管线已有：

```text
RT median / mean / SD
RT-CV
ex-Gaussian μ / σ / τ
极短 RT 比例
```

其中 RT-CV 和 ex-Gaussian τ 对 sustained-attention lapse 特别有价值，因为注意失败不一定首先表现为平均 RT 变慢，也可能表现为波动变大、长尾增加。

这些指标主要在 Block/subject 层解释；trial-level 模型则直接使用单 trial RT，并控制 time-on-task、Block、PIR 与视觉协变量。

## Commission：不仅看错误本身，还看错误前发生了什么

No-Go 分析应该形成一个事件前兆设计：

```text
正确抑制事件：-5 -4 -3 -2 -1 → No-Go
commission：   -5 -4 -3 -2 -1 → No-Go error
```

前 5 个正确 Go trial 同时提取：

```text
RT trajectory
PIR trajectory
PIR slope / variability
```

因此我们可以问：

> commission 是否在真正发生之前就伴随 RT 加速、PIR 偏移或波动增加？

而不是只比较“commission trial vs correct trial”两个点。

当前 validation 已增加 `nogo_precursor_trajectory.csv`，并分别生成 RT 与 PIR 前兆图，同时准备 `lag × event_outcome` mixed-model smoke test。

## Omission：程序评分、QC 敏感性和 motor timing 必须分开

原始 `omission=1` 永久保留，不能人工重写。但真实审计已经证明某些 omission 之前存在 prestimulus press 或上一 trial 的第二次按键，因此 omission 不能被视为完全同质。

正式结构固定为三轨：

```text
Primary program scoring
    原程序 omission

QC-aware sensitivity
    clean omission
    prestimulus-associated omission
    carryover-associated omission
    prestimulus + carryover

Exploratory motor timing
    anticipatory candidate
    multiple keypress
    very-short RT
```

这不是重新评分，而是在保留原始任务定义的同时承认“漏按”背后可能存在不同的运动时序模式。

正式主模型先使用 program omission；随后做排除 ambiguous omission 的 clean sensitivity；anticipatory candidate 作为独立行为表型分析，不简单当脏数据删除。

# Probe 是主观状态锚点，而不是一个 vigilance 数字

Probe 必须同时保留：

```text
probe_response
probe_vigilance
probe_rt
probe_vigilance_rt
```

目前 v3.1.3 的正式语义仍以 raw numeric code 为 canonical，因此 `probe_response` 在任务源码再次核验前不擅自翻译成文字心理状态。

## Probe 的第一条分析轨：回答“选了什么”

`probe_response` 是分类变量。当前 validation 已增加：

- 每个 raw option 的频率和被试内分布；
- 不同 option 前 10/20/30/60 s PIR；
- 不同 option 前的 RT、RT-CV、commission、omission、ambiguous omission、anticipatory；
- option 对应的 probe response RT；
- 分类 mixed-model smoke test。

## Probe 的第二条分析轨：回答“警觉程度是多少”

`probe_vigilance` 作为独立维度保留，可以分析：

- vigilance × pre-probe PIR；
- vigilance × pre-probe RT / RT-CV；
- vigilance response RT；
- Block 和 time-on-task 的控制。

## 两个 Probe 维度还需要互相校验

`probe_response × probe_vigilance` 的联合表用于回答：

> 某个 response option 是否通常伴随较低/较高 vigilance，还是两个问题提供了不同信息？

这一步相当于 Probe 内部的 construct-validity 检查。

## Probe 前行为与 PIR 都必须是多时间尺度

Probe 说“刚才/最近”并不意味着生理分析只能取最后一个 trial。当前固定并列：

```text
pre_10s
pre_20s
pre_30s
pre_60s
```

每个窗口同时拥有：

```text
PIR level / variability / slope / instability
Go RT median / MAD / IQR / CV
commission / omission
ambiguous omission
anticipatory candidate
previous-probe contamination
coverage
```

正式分析不允许把四个窗口全部跑完以后只报告最显著者。主窗口需要在正式全样本推断前冻结；其他窗口作为预先声明的 temporal robustness / trajectory。

# 视觉刺激不是噪声背景：PIR 模型必须控制 PLR 相关协变量

Pupil 对亮度与视觉刺激敏感，因此不能把水果刺激带来的 PLR 变化误解释为 attention effect。

项目已经重建 27 个正式刺激条件的数字视觉属性，包括：

```text
relative luminance
RMS contrast
fruit visible area
central ROI luminance / contrast
与 background / mask 的 luminance delta
```

trial-level 模型至少连接：

```text
current stimulus visual properties
previous stimulus visual properties
```

之所以保留 previous stimulus，是因为 pupil response 有延迟；即使当前 onset 前存在 mask，前一个水果的 PLR 恢复仍可能延续到当前 trial。

因此最终 Go RT / error 模型不应只是：

```text
behavior ~ PIR
```

而应形成逐步控制：

```text
behavior
~ PIR_within
+ raw/between-person PIR characteristics（若模型需要）
+ time-on-task
+ Block
+ current visual covariates
+ previous visual covariates
+ subject random effects
```

当前 validation 会在版本化 `stimulus_visual_properties.csv` 存在时自动连接；文件缺失只记录 `unavailable`，不会为了跑通而临时猜视觉属性。

---

# 个体差异层：不要让 centered PIR 偷偷承担 between-person 解释

正式 subject-level 层将整合：

```text
raw PIR baseline characteristics
总体/Block 行为指标
Probe 分布
Block deterioration / time-on-task slope
Questionnaire
```

这里的核心问题不是“谁的 centered PIR 平均更高”，因为 centered PIR 本身已经以个体基线为中心。真正的 between-person 生理差异应来自 raw PIR baseline 或其它明确未被个体中心化的特征。

Behavior 个体差异则可以包括：

```text
RT-CV
ex-Gaussian τ
d′ / criterion c / β
commission / omission
Block change
```

问卷接入后再建立：

```text
Questionnaire ↔ Objective SART ↔ Probe ↔ NIR
```

当前仓库还没有冻结 questionnaire CSV 数据契约，所以 validation 只提供按 subject ID 自动连接和数值变量 Spearman 接口；如果未配置文件，明确写 `questionnaire: unavailable`，而不是假装已完成问卷分析。

# QC 与 sensitivity 必须在科学分析旁边平行存在，而不是事后补救

## Coverage 是窗口测量质量，不是 outcome-driven exclusion

每个 trial/probe window 都保留：

```text
available_duration_fraction
boundary truncation
internal_coverage_fraction
max_temporal_gap_sec
pir_valid_fraction
```

这些指标回答五个不同问题：

```text
这个理论窗口在 Block 里实际存在多少？
是否被 Block 边界截断？
时间轴内部连续吗？
最长技术缺口多大？
真正有效 PIR 占多少？
```

当前 validation 会把它们做成多维 QC 图，而不是只看一个 `pir_valid_fraction` heatmap。

正式 threshold 必须根据时间代表性、测量可靠性和人工 QC 冻结，不能根据“哪个 threshold p 值最好”反推。

## Source mode 必须看组成

binocular PIR 窗口还要同步报告：

```text
both-eye fraction
left-only fraction
right-only fraction
missing fraction
```

如果一个分析窗口大部分由 single-eye fallback 构成，这不是自动删除理由，但必须能在 QC 图中看到，并可做 robustness sensitivity。

## 六条 track 是稳健性设计，不是六套结果供挑选

`11_analysis_tables` 已经生成：

```text
binocular_primary
left_primary
right_primary
binocular_strict
left_strict
right_strict
```

正式解释优先 `binocular_primary`；其它轨道只回答：

> 换成 strict validity 后结论是否保持？
> 是否被单一眼睛驱动？

当前 validation 已增加 track correlation / agreement 表和 heatmap。任何“某个 track 显著所以改用它”的做法都不允许。

# 统计推断应该按层次展开，而不是一次把所有变量塞进一个模型

正式统计建议使用“由简单到完整”的模型阶梯。

### 第一层：描述与测量检查

先回答：

- PIR/Behavior/Probe 分布是什么样；
- 是否存在明显 coverage/source-mode 问题；
- Block/time-on-task 是否有肉眼可见趋势；
- Probe 各 raw option 是否有足够样本；
- omission subtype / commission 是否有足够事件数。

这一步不做显著性驱动变量选择。

### 第二层：核心 mixed-effects 推断

围绕三类主要 outcome：

```text
连续 outcome：RT / vigilance / PIR
二元 outcome：commission / omission / anticipatory
分类 outcome：probe_response
```

核心模型优先 mixed-effects / GEE，subject 至少作为重复测量聚类或随机截距；不做“每个被试先算一个相关，再对相关系数平均”。

### 第三层：within-person / between-person 分解

对于 PIR-behavior 关系，必须把：

```text
当前相对自身基线的变化
```

和：

```text
这个人本身 raw PIR baseline 的个体差异
```

分开解释。这样才能区分“一个人在自己瞳孔变小时更容易犯错”和“天生/测量上 PIR 较小的人是否整体更容易犯错”这两个完全不同的问题。

### 第四层：预先声明的 sensitivity

包括：

- strict vs primary；
- left/right eye；
- clean omission vs program omission；
- coverage threshold sensitivity；
- visual covariates；
- 单眼 fallback 较高窗口的 sensitivity；
- raw/centered 定义边界。

Sensitivity 的作用是检验主结论是否依赖某个处理规则，而不是寻找更显著的结果。

### 第五层：trajectory / 非线性与预测

如果主分析提示时间动态明显，再进入：

```text
state × time-to-event
GAMM
subject-level cross-validation prediction
```

机器学习可用于多特征预测，但模型选择必须按 subject 分层交叉验证，不能随机拆 trial 导致同一个人的数据同时进入 train/test。

# OAR、blink/PERCLOS、问卷和 RGB 应该怎样进入，而不破坏主线

## OAR / eyelid state

OAR 已有 production 派生定义，但当前 `10_analysis_ready` 正式契约还没有把 OAR 作为 passthrough 字段纳入。因此现在不能为了方便让统计脚本绕回 production 读取 OAR。

正确扩展顺序是：

```text
production OAR
↓
扩展 10_analysis_ready schema（保留 raw / validity / left-right）
↓
11_analysis_tables 平行生成 OAR trial/probe/time-on-task 特征
↓
再进入同一套 12/20 分析架构
```

只有经过人工效度验证后，连续 OAR 才能进一步转成 closure / blink / PERCLOS 等事件指标。

## Questionnaire

问卷属于 subject-level 外部测量，不应该回写 trial 表。冻结数据契约后，按 subject ID 连接 `subject_level_summary`，用于 construct validity 和个体差异分析。

## RGB multimodal

RGB 不进入当前 NIR validation 内部。未来只通过共同的：

```text
subject
Block
absolute time
trial / probe index
```

连接 multimodal table。这样 NIR、RGB 各自 QC/派生逻辑仍能独立审计。

# 正确 NIR 修复以后，真正的执行顺序

当前最重要的是不要把 validation-only 结果误当成下一步正式统计。正确 NIR 修复以后应按下面顺序一次恢复：

```text
① 修正 NIR 数值来源
        ↓
② 重建 10_analysis_ready
   检查 raw PIR / primary / strict / baseline / source mode
        ↓
③ 重建 11_analysis_tables
   trial / probe / time-on-task / coverage
        ↓
④ 重新运行 12_pipeline_validation
   只验收结构、图、模型接口和数据质量
        ↓
⑤ 基于正确全量数据冻结：
   primary inferential windows
   coverage threshold
   visual covariate set
   Probe raw-code语义
   sensitivity set
        ↓
⑥ 才进入 20_formal_statistics
        ↓
⑦ 44 人只作为 exploratory/development
   约 116 人 final cohort 使用同一冻结代码独立输出
```

这保证未来不会出现“发现一个新指标 → 回头重切时间窗 → 再回头改 validity → 再重跑模型”的循环。
