## 为什么原来的图需要整体重构

早期 `12_pipeline_validation` 的图主要承担工程 smoke test：确认表能 join、模型能拟合、Matplotlib 能落盘。因此出现了三个不适合论文写作的问题。

第一，很多图只展示了一个汇总维度。例如 trial outcome 图把两个 Block 合并，time-on-task 图把两个 Block 都从各自 0 秒开始叠在同一横轴上；这能检查代码，但无法表达整个实验的时序，也无法系统展示 `Block × behavior/probe state`。

第二，早期图的 `figsize`、字体、图例、线宽和 DPI 分散在各函数中，没有统一物理尺寸。这样即使单张图可读，把多张图放进论文时也会出现轴宽不一致、字号变化、图例比例失衡和 panel 对不齐。

第三，原来的所谓 multiscale trajectory 主要是把 `pre_1/3/5/10/20/30/60s` 等窗口汇总值连接起来。它可以用于比较预定义窗口，但不能等同于真正的 event-related trajectory。真正的 trajectory 必须从连续 `10_analysis_ready` 信号按 event onset 重新对齐，再以固定的小时间 bin 汇总。

因此现在不继续修补旧单图，而是建立两个并行输出层：

```text
12_pipeline_validation/
├── figures/
│   ├── diagnostic/          # 工程/调试单图；保留 provenance
│   └── publication/         # Figure 1–10；论文级多面板输出
└── tables/
    ├── ...                  # 原 validation 表
    └── publication_analysis/ # Figure 1–10 的完整分析底表
```

旧图不删除，但不再作为 manuscript Figure 的正式候选。

# Figure 系统先统一“画布”，再谈数据

## 统一物理尺寸

新增：

```text
src/attention_pipeline/nir_pipeline_validation/figure_style.py
```

固定三档物理宽度：

```text
single column : 8 cm
medium        : 14 cm
full width    : 17 cm
```

Figure 1–10 默认使用 17 cm full-width 画布；总高度控制在 20 cm 内。这样每张图进入 Word / LaTeX 后不需要再次任意缩放才能对齐。

## 字体、线宽和 panel

统一使用：

```text
英文：Arial
fallback：DejaVu Sans
主体字号：约 8 pt
panel label：约 10 pt，A/B/C/D
坐标轴、tick、数据线宽统一由 figure_style.py 管理
白色背景
图例无边框
```

颜色不是唯一编码：Block / condition 图尽量同时使用颜色、线型或 marker 区分，以便灰度打印仍能识别。

## 输出格式

publication suite 默认同时输出：

```text
PDF   # 矢量
SVG   # 矢量，文字保持为文字
PNG   # 600 dpi
TIFF  # 600 dpi，LZW 压缩
```

保存时不再使用 `bbox_inches="tight"` 改变不同 Figure 的实际画布边界；所有 Figure 使用固定 canvas，再通过统一 `subplots_adjust` 对齐。

# “条件”到底怎样区分

正式 FocusWave v3.1.3 的实验 `condition` 字段只有 B，不能为了画图虚构一个不存在的 A/B condition。论文图中的条件分层来自真实任务结构：

```text
Block：Block 1 / Block 2

Task type：Go / No-Go

Program outcome：
    Go correct
    Go program omission
    No-Go correct inhibition
    No-Go commission

Omission QC subtype：
    clean omission
    prestimulus-associated omission
    carryover-associated omission
    prestimulus + carryover

Stimulus：
    stimulus identity
    stimulus size
    Go / No-Go stimulus
    luminance / contrast / visible area

Probe：
    probe_response raw option
    probe_vigilance
    probe_response RT
    probe_vigilance RT

Sensitivity track：
    binocular / left / right
    primary / strict
```

因此以后说“不同条件”时，必须说明是哪一层 condition，不能把 Block、trial outcome、Probe option 和视觉刺激混成一个总标签。

# Figure 1｜全实验 PIR landscape

Figure 1 是原来最明显缺失的图：**从 Block1 开始到 Block2 结束的整体 PIR 变化**。

它包含四个 panel。

### A｜Whole-experiment trajectory

横轴不是两个独立的 `time-in-block=0`，而是构造 global experimental time：

```text
Block1 → between-block interval → Block2
```

每名被试保留淡色轨迹；主体是 cohort median + IQR。Block 间区段用明确背景区域标注。这个 panel 回答“从整个实验尺度看，PIR 如何随持续任务推进”。

### B｜Block-aligned time-on-task

将 B1/B2 重新以各自 Block onset 对齐，在同一时间标尺上比较 trajectory。它回答“两个 Block 内部的 time-on-task 漂移是否形状不同”。

### C｜Block distribution

展示 subject-level Block PIR 分布和配对关系，避免只看均值线。

### D｜Block transition / recovery

以 B1 末段和 B2 初段为边界，展示：

```text
B1 end ← -120 ... 0 | 0 ... +120 → B2 start
```

并计算 B2 前 60 秒减 B1 后 60 秒的 subject-level recovery delta。

# Figure 2｜Block 与 time-on-task 的个体差异

Figure 2 从 Figure 1 的群体轨迹进一步进入 subject heterogeneity。

### A｜Block1→Block2 被试内配对

每名被试一条配对线，cohort median 单独强调。

### B｜B1 与 B2 time-on-task slope

每名被试在两个 Block 各估一个简单趋势 slope，二维散点显示：

```text
x = Block1 slope
y = Block2 slope
```

它不用于当前科学解释，只验证未来“持续恶化速度是否具有个体稳定性”的接口。

### C｜Block-transition recovery heterogeneity

按 recovery delta 排序展示 subject variability。

### D｜Block 内前半 vs 后半

比较每个 Block 的 second-half − first-half PIR，作为对 continuous slope 的一个非参数/直观补充。

# Figure 3｜Trial 行为状态：条件必须同时看 Block

旧 trial 图把所有 Block 合并。新 Figure 3 明确展开：

```

并列展示：

```

每个 outcome 下都区分 B1/B2，并使用 subject-level median 避免 raw trial 的伪重复视觉效果。

### B｜Omission subtype × Block

单独比较 clean / prestimulus / carry-over / combined subtype。

### C｜Correct-Go RT across PIR state

只使用正确 Go trial，将 PIR 分箱后显示 RT 的关系，并区分 Block。

### D｜Behavioral error/QC profile

同时展示 commission、program omission、clean omission、ambiguous omission 的 Block-level rate。

# Figure 4｜真正的错误前兆 trajectory

这是本轮最重要的分析升级之一。

旧 `pre_1/3/5/10/20/30/60s` 汇总仍保留，但**不再冒充连续 trajectory**。新代码从 `10_analysis_ready` 只读：

```text
subject × block × unix_ms × centered PIR
```

再以 trial onset 为 t=0，默认从 `-60s` 到 `+2s`，按 1 秒 bin 汇总。

### A/B｜No-Go precursor trajectory

Block1、Block2 分 panel，区分：

```text
correct inhibition
commission
```

这样能看到错误前几十秒的状态是否已经分离。

### C｜Go omission precursor

区分：

```text
go_correct_reference
clean_omission
ambiguous_omission
```

正确 Go reference 使用每个 subject×Block 的确定性等距抽样，避免所有正确 Go 事件造成不必要的巨大重复计算。

### D｜No-Go 前若干 trial 的 RT 前兆

保留原来的离散 trial-lag 分析，用前若干个正确 Go 的 RT 作为另一条行为前兆证据。

因此 Figure 4 同时存在：

```text
连续秒级 physiology trajectory
+
离散 trial-level behavior trajectory
```

# Figure 5｜Probe 状态与状态转移

Probe 不再只画 `vigilance ~ PIR`。

### A｜probe_response distribution × Block

按 raw code 展示每种回答在 B1/B2 的比例。

### B｜probe_response × probe_vigilance

检验两个 Probe 问题的内部结构，而不是把它们当同一个变量。

### C｜continuous pre-Probe PIR trajectory

从 `10_analysis_ready` 以 probe onset 为 t=0，默认向前看 60 秒；不同 `probe_response` raw option 分开。

### D｜Probe sequential transitions

新增：

```text
previous probe_response → current probe_response
previous vigilance → current vigilance
previous PIR → current PIR
```

当前 Figure 先展示 response transition count；底表同时保存 vigilance/PIR delta，正式样本量足够后可以进入 Markov / transition mixed model。

# Figure 6｜视觉刺激与 PLR 控制

Pupil signal 不能在没有视觉控制的情况下全部解释成注意状态。

Figure 6 以版本化 SART visual table 为输入，展示：

### A｜Stimulus size × Go/No-Go × Block

检查刺激大小和任务类型是否对应系统性 PIR 差异。

### B｜Current-stimulus luminance

使用分箱趋势展示当前 central relative luminance 与 PIR 的关系，并区分 Block。

### C｜Current-stimulus contrast

与 luminance 平行。

### D｜Current vs previous visual properties

比较 current / previous stimulus 的 luminance、contrast、visible-area 等协变量与 PIR 的描述性相关。

正式模型应把视觉协变量作为 PLR/confound controls，而不是把 Figure 6 当注意效应结果。

群体平均不能回答“是否由少数被试驱动”。Figure 7 专门展示 subject heterogeneity。

# Figure 8｜Feature structure 与 multiscale stability

随着 PIR feature 增多，必须回答“这些指标是不是高度重复”。

### A｜PIR feature redundancy

对 trial-level PIR features 做 **within-person centering 后的相关矩阵**，包括：

```text
median / mean
MAD / IQR / SD
P10 / P90
slope
successive-difference MAD
successive-difference-rate MAD/s
```

用于识别明显冗余和共线性。

### B｜Within-person NIR–behavior correlation structure

个体内中心化后比较 PIR level/variability/trend 与 RT、commission、omission 等变量。它与简单把所有 trial 混在一起算 Pearson 完全不同。

### C｜Between-person structure

使用 raw PIR subject baseline 与 RT-CV、ex-Gaussian τ、d′、commission、omission 等 subject-level 指标构造独立相关结构。

### D｜Window stability

不是选择“最显著窗口”，而是对预定义 `1/3/5/10/20/30/60s` 展示同一个 contrast 的方向和幅度是否稳定。

当前实现包括：

```text
commission − correct inhibition
program omission − Go correct
PIR per probe_vigilance unit
```

所有当前数值都只是 smoke-test；正式数据回来后才能解释。

# 当前验收标准

这一次验收的不是“图上有没有显著”，而是以下工程标准：

1. Figure 1 的 global time 能真正跨 B1→B2，而不是两个 Block 都从 0 开始重叠；
2. Figure 3/4/5 明确区分 Block、outcome、omission subtype、Probe option 等真实 condition；
3. Figure 4/5 continuous trajectory 来自 `10_analysis_ready` 时间戳小 bin，不是预定义窗口点连线；
4. Figure 8 明确分 within-person 与 between-person；
5. Figure 9 不把 fraction 与 temporal-gap 秒数混用一个比例尺；
6. Figure 1–10 都是固定 17 cm canvas、多 panel 对齐、统一字体/legend/线宽；
7. PDF/SVG 为矢量，PNG/TIFF 为 600 dpi；
8. 所有当前 PIR 图继续标明 `CURRENT NIR VALUES KNOWN INVALID`；
9. 不继续构建 sub-042 以后剩余 33 名 subject；
10. 不进入 `20_formal_statistics`。

达到这些标准以后，这套代码才算是“正确 NIR 回来以后可以直接重跑的论文级分析/绘图框架”，而不仅是能输出若干 CSV 和 Matplotlib 图片的 smoke test。
