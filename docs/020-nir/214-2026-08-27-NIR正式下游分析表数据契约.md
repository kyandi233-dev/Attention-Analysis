# 214｜NIR 正式下游分析表：trial / probe / time-on-task 数据契约

> 2026-08-27｜工作分支：`analysis/multimodal-integration`。本文件定义 `10_analysis_ready` 完成后，如何构造真正供后续统计模型读取的 NIR × Behavior 分析表。当前对象仍是 44 人 exploratory/development cohort；本层不运行显著性检验。

## 2. 为什么先构表而不是直接跑模型

frame-level PIR 是连续时间序列，而科学问题分别发生在 trial、probe 和长期 time-on-task 三个尺度。若直接在统计脚本里临时切窗，会导致窗口定义、coverage、左右眼处理和 provenance 难以复现。

因此本层只做“分析单位构造”，把所有候选窗口和必要 QC 一次性落盘。后续模型只能读取这些表，不应再次临时回到逐帧 CSV 自由切窗。

## 3. Signal track（信号轨道）

同一套时间窗平行生成六条 PIR 轨道：

| track | 含义 | 用途 |
|---|---|---|
| `binocular_primary` | `binocular_PIR` | 正式主分析候选 |
| `left_primary` | 左眼 centered PIR | eye-preserved sensitivity |
| `right_primary` | 右眼 centered PIR | eye-preserved sensitivity |
| `binocular_strict` | strict binocular PIR | strict sensitivity |
| `left_strict` | 左眼 strict-centered PIR | strict + eye sensitivity |
| `right_strict` | 右眼 strict-centered PIR | strict + eye sensitivity |

主分析优先使用 `binocular_primary`。左右眼轨道和 strict 轨道不用于根据显著性挑选“最好结果”，而用于既定稳健性分析。

binocular track 额外保存窗口内：

```text
source_mode_binocular_fraction
source_mode_left_only_fraction
source_mode_right_only_fraction
source_mode_missing_fraction
```

因此某个 trial/probe window 即使有 PIR，也能知道其中有多少比例来自双眼、单左眼或单右眼 fallback。

## 4. Trial-level

`trial_level.csv` 一行 = 一个正式 SART trial。Behavior 继续沿用 frozen FocusWave v3.1.3 BB 读取与既有行为 QC，不改写原始 `correct / commission / omission / rt`。

额外记录每条 NIR track 在该 trial 实际时间段中的：

```text
nir_rows_trial__TRACK
pir_valid_rows_trial__TRACK
```

这些只是 linkage / QC，不在本层形成自动排除。

## 5. Trial PIR windows

`trial_pir_windows.csv` 一行 =：

```text
trial × window × track
```

候选窗口继续沿用已建立的科学设计：

事件邻近窗口：

```text
pre_200ms
post_200ms
post_200_1150ms
```

状态窗口：

```text
pre_1s
pre_3s
pre_5s
pre_10s
pre_20s
pre_30s
pre_60s
```

当前全部生成是为了保留信息，不表示正式推断可以在所有窗口中试完后挑最显著者。最终 primary inferential window 必须在正式模型前冻结。

每个窗口计算 PIR：

```text
n_valid
median
mean
MAD
IQR
SD
P10
P90
binned-median slope per second
successive-difference MAD
successive-difference-rate MAD per second
```

trial 长窗口继续记录：

```text
n_probes_in_window
window_crosses_probe
last_probe_before_trial_ms
time_since_last_probe_sec
```

避免把 probe 中断后的时间误解释为自然持续注意状态。

## 6. Probe windows

`probe_pir_windows.csv` 一行 =：

```text
probe × pre-probe window × track
```

候选窗口：

```text
pre_10s
pre_20s
pre_30s
pre_60s
```

每行同时保留：

1. probe response / vigilance 及其 RT；
2. 同窗 PIR 水平、变异、趋势；
3. 同窗 SART 行为摘要：trial 数、Go/No-Go、Go RT、commission、omission 等；
4. previous-probe contamination 信息。

因此后续可以分析 on-task / mind-wandering / mind-blanking 等主观状态，而不需要再次扫描 frame-level 数据。

## 7. Time-on-task

新增：

```text
sub-XXX_time_on_task_1s.csv
```

默认一行 =：

```text
subject × block × 1-second bin × track
```

1 s bin 只是连续 time-on-task 描述与后续 GAMM / mixed model 的稳定基础网格，不是基础清洗单位，也不是 coverage hard gate。

Block1 / Block2 必须保持分开，并保留相对于 Block 起点的连续时间：

```text
time_in_block_start_sec
time_in_block_mid_sec
```

不能按 Block 分别重新中心化 PIR。

## 8. Coverage 语义

每个 trial/probe window 继续区分：

```text
available_duration_fraction
window_truncated_by_block_start/end
internal_coverage_fraction
max_temporal_gap_sec
pir_valid_fraction
```

含义分别是：

- behavior 设计上有多少时间真正存在；
- 是否被 Block 边界截断；
- 理论可用时段内部 NIR 时间轴是否连续；
- 最大技术缺口；
- 该 track 内真正有效 PIR 的比例。

本阶段**不冻结 coverage threshold**。后续 threshold 应基于时间代表性、测量可靠性和预先定义的 sensitivity 逻辑确定，禁止根据最终 p 值反推。

## 10. Provenance 与重复运行

每名被试 completion identity 至少包括：

```text
analysis-ready CSV SHA256
Behavior source file SHA256
config digest
pipeline/schema version
```

若 identity 完全一致，默认跳过已有 completed output；只有明确使用 `--force` / `--force-tables` 才重建 `11_analysis_tables`。

这使得 44 人 exploratory 与未来约 116 人 final cohort 可以使用同一代码，但写入不同 cohort snapshot。

## 11. OAR 边界

OAR（ocular aperture ratio，眼球可见开合度比率）仍属于后续 robustness / eyelid-state 方向，但当前 `10_analysis_ready` 的正式主契约只冻结 PIR。`11_analysis_tables` 当前版本因此只构造 PIR。

后续若纳入 OAR，必须先把 OAR 作为**只读 passthrough 派生字段**正式加入 analysis-ready schema，再由同一 `11_analysis_tables` 机制读取；禁止为了方便让正式统计脚本重新绕过 `10_analysis_ready` 直接读 production。
