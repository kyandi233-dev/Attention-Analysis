# 08-16 NIR 特写 ROI 调研与选型

> 08-16（Asia/Shanghai）｜三后端在特写画面全灭后，调研瞳孔算法层（RITnet/DeepVOG/Iris）与 ROI 定位层（faceparts/自训练）的替代方案，选定 faceparts 为特写候选 + 全算法封装成可移植包。详细对话原文见 `docs/工作记录/08-16-07`、`08-16-08`。

## 1. 起点：特写画面三后端全灭

正式 sub-011 Block1 画面是双眼/眼镜/鼻梁特写（非完整人脸），60 时点复核 MediaPipe 0/60、YuNet 1/60、YOLO-face 60/60（全假脸）。根因是三者都以"先找完整人脸再推眼"为前提，与"输入域只有部分脸"不匹配。

## 2. 瞳孔算法层调研（先厘清：它们不做眼睛定位）

| 算法 | 机制 | 输入 | 关键结论 |
|---|---|---|---|
| RITnet | OpenEDS-NIR 训练的 DenseNet-UNet，4 类分割（背景/巩膜/虹膜/瞳孔） | 单眼 640×400 | 528 眼实测可用率 **45.3%**（vs 85% 门槛）；中心精度极高（中位 0.9%），但直径/IoU 重尾。首个中位 IoU 过门（73.5%）的候选 |
| DeepVOG | UNet(10×10 大核) 分割 + **3D 眼球几何**（gaze） | 单眼 240×320 | 需相机焦距/传感器标定；keras/TF 旧代码；比 RITnet 多 3D 层、分辨率更低、无虹膜类别 |
| Iris_Landmark | 眼部/虹膜**关键点**回归 | 依赖完整人脸检测 | 输出虹膜非瞳孔；特写画面无全脸时失败 |

**共同点**：三者都是"给定单眼图 → 瞳孔/虹膜提取"，与 PuRe/PuReST 同层，**不解决"双眼特写里眼睛在哪"的上游定位**。DeepVOG master（2D 分割）够瞳孔直径用，3d 版（4 类分割 + 3D 反投影）为 gaze 设计、超出需求。

## 3. ROI 定位层调研（真正的硬门）

文献结论：**不存在"下载现成模型直接用"的路**。"不依赖完整人脸、只在部分可见（双眼+鼻梁）NIR 画面里定位眼睛"是窄问题——NEC 2023（Siamese 粗到精）、Causa 2022（Eye-tiny-yolo）都为此设计，但**均无开源代码/权重**。主流人脸检测器都不是为"只有眼周可见"训练/评估的。

候选：

| 方案 | 机制 | 状态 |
|---|---|---|
| **faceparts**（yolo-face-parts-detector） | 直接检测 eye bbox，不依赖完整人脸，专为 close-up/遮挡设计 | **选定为特写候选**；RGB 训练域、NIR 有域差须实测 |
| 自训练 YOLOv8n-pose 眼部关键点 | 单 eye 类 + 2 眼角关键点，x 排序分左右 | 备选（Tier 2）；需 300-500 帧标注 + CPU 训练 |
| 检测+追踪（CSRT/KLT） | 检测器只做锚点，追踪撑后续帧 | 补充手段，降低逐帧检测成本 |

自训练要点（若 faceparts 不达标再启用）：labelme 本地标注（NIR 生物特征不出网）、按 subject 切 80/20（防泄漏）、`fliplr=0`（固定正面翻转会乱左右）、`hsv_h/s=0`（灰度 NIR 无色调）。

## 4. 决策链

```
三后端全灭（特写）
  → 厘清：瞳孔算法（RITnet/DeepVOG/Iris）不做定位，缺的是 ROI 定位层
  → 无现成开源眼部定位器
  → 选 faceparts（直接检测 eye bbox，任务定义最匹配）+ 自训练作备选
  → 全算法封装成可移植包（本机不选最优，新设备跑完再选型）
```

## 5. 结论

- faceparts 为特写 ROI **新候选**，须在正式特写上实测检出率（conf/imgsz/nano-vs-small 网格），不能凭 README。
- 瞳孔层四路（PuReST/RITnet/DeepVOG/Iris）全封装，待同一批 ROI 上对比。
