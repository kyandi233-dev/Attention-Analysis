# SART 刺激视觉协变量重建

> 2026-08-26｜分支：`amd-DirectML`｜实现：`stimulus-visual-v1.2`。本模块只构造 FocusWave 正式 SART 的数字视觉协变量及报告用重建图，不修改 frozen NIR runtime，也不改变 `nir-behavior-v1.2 / schema 2` 对齐表结构。

## 1. 为什么单独生成视觉表

NIR 的主要瞳孔指标是 `fullclass_pupil_to_iris_diameter_ratio`，但瞳孔除了受注意/警觉影响，也会对屏幕亮度变化产生生理性 pupil light response。因此正式 trial 模型需要保留刺激视觉输入作为协变量。

这里不把水果 PNG 本身的平均像素值直接当作 trial luminance。正式实验实际呈现的是：

```text
刺激.png 背景
    +
按 trial stimulus_size 缩放后的水果 PNG
```

随后 250 ms 刺激阶段结束，进入：

```text
刺激.png 背景
    +
掩蔽刺激.png
```

因此视觉表必须按 FocusWave 的真实绘制规则重建完整画面，并同时计算与 mask 的亮度差。

## 2. 已从 FocusWave formaltest 核对的绘制规则

来源：`FocusWave/formaltest/01-MainProgram/core/sart_task.py` 与 `main_experiment_msmf.py`。

FocusWave 在 PsychoPy 创建窗口前启用 Windows DPI awareness，然后 `sart_task.py` 通过 `_get_screen_size()` 调用 `tkinter` 的 `winfo_screenwidth()` / `winfo_screenheight()` 获取当前实际屏幕像素尺寸，赋给 `WIN_SIZE`；只有获取失败时才 fallback 为 1920×1080。也就是说，正式程序并没有把 2880×1920 写死成通用常量。

北京正式 116 人均使用同一台 Surface Pro，实验期间显示设置未更换；该机器被 FocusWave 运行时实际识别为：

```text
WIN_SIZE = 2880 × 1920
```

因此本项目的 27-condition 表使用 **北京正式 Surface Pro 的历史运行时 display profile** `2880×1920` 重建。这不是分析电脑当前屏幕尺寸，也不是脱离实验记录自行假设的固定分辨率。

正式常量：

```text
SCALE = 1.34
STIM_SCALE = 1.10
BASE_SIZE = int(280 * SCALE * STIM_SCALE) = 412 px
BG_COLOR = #C6BFAE
stimulus pos = (0, -20) PsychoPy pix
stimulus_size = 80 / 100 / 120
```

每个 trial：

```text
actual_size = BASE_SIZE * stimulus_size / 100
```

这里必须区分两套缩放机制：

```text
实际运行时检测 WIN_SIZE
        ↓
PsychoPy fullscreen window
        ├─ 刺激.png / 掩蔽刺激.png：按 win.size[0] 全宽等比例缩放并居中
        └─ 水果 PNG：不按屏幕宽度再次比例缩放，而是固定使用
                     BASE_SIZE × stimulus_size / 100 的像素尺寸
```

因此水果由 `visual.ImageStim(... size=(actual_size, actual_size), pos=(0,-20))` 绘制；背景 `刺激.png` 与 `掩蔽刺激.png` 则通过 `get_adaptive_stim` 按实际窗口宽度等比例缩放并居中。正式刺激阶段先 `bg_img.draw()`，再 `stim_img.draw()`；mask 阶段先画背景，再画 mask。

正式素材：

```text
GO/
  01_mango.png
  02_grape.png
  03_avocado.png
  04_bitter_melon.png
  05_cucumber.png
  06_kiwi.png
  07_kale.png
  08_lime.png

NOGO/
  09_no_go.png
```

`01_no_go.png` 与 `09_no_go.png` 在当前 formaltest 仓库中是同一 blob；行为正式命名使用 `09_no_go.png`。

因此正式条件数为：

```text
9 stimulus identities × 3 sizes = 27 conditions
```

## 4. 北京正式 display profile 与屏幕重建

当前配置显式记录：

```text
display_profile = beijing-formal-surface-pro
resolution_source = focuswave_runtime_detected_screen_size
same_display_for_all_beijing_formal_subjects = true
dpi_aware_runtime = true
screen = 2880 × 1920
```

重建逻辑与正式程序一致：

1. 整个 2880×1920 canvas 先填充 `BG_COLOR=#C6BFAE`；
2. `刺激.png` 按当前窗口宽度 2880 px 等比例缩放，高度保持原始比例并垂直居中；
3. 水果不随屏幕宽度做额外相对缩放，而是严格按 `BASE_SIZE=412 px × stimulus_size/100` 得到约 330/412/494 px 方形 ImageStim；
4. 水果中心使用 PsychoPy `(0,-20)`；
5. mask 参考画面在同一背景上按相同全宽自适应规则叠加 `掩蔽刺激.png`。

这意味着 2880×1920 对北京正式样本是一个统一的历史呈现条件，所以 116 人共用同一张 27-condition 表即可，不需要逐被试重算。

如果以后分析珠海预实验、其他显示器或其他分辨率的数据，必须建立新的 display profile 并重算，不能把北京 Surface Pro 的表静默复用。

当前 `resize_filter=nearest`，用于保持正式像素风素材的硬边界，并尽量接近 PsychoPy ImageStim 未显式启用插值时的呈现。该参数写入 manifest，可以重建和敏感性复算。

## 5. 输出字段

一行 = `stimulus_name × stimulus_size_pct`。

### 5.1 条件与 provenance

包括：

```text
stimulus_name
stimulus_code
is_no_go
stimulus_size_pct
base_size_px
rendered_size_px
stimulus position / screen size / bbox
fruit_source_sha256
```

manifest 额外保存：

- `刺激.png` SHA256；
- `掩蔽刺激.png` SHA256；
- 9 个正式水果源文件 SHA256；
- 如果本地 FocusWave checkout 可读，保存 `core/sart_task.py` SHA256；
- Attention-Analysis config digest 与 renderer 参数；
- 北京正式 Surface Pro 的 display profile、运行时检测来源和 DPI-aware 说明；
- 27 张完整重建图及报告总览图的输出信息与 SHA256。

### 5.2 数字相对亮度

RGB 先从 sRGB 反 gamma 到 linear RGB，然后计算：

```text
Y = 0.2126 R + 0.7152 G + 0.0722 B
```

这是 **digital relative luminance**，范围约 0–1；不是显示器经过光度计校准得到的 cd/m²。

分别输出：

```text
screen_*         整个重建屏幕
central_*        以刺激中心为中心的固定 600×600 ROI
fruit_support_*  resized fruit alpha > 0.05 的实际可见水果区域
```

每个区域包含：

```text
relative luminance mean / median / SD
RMS contrast = SD(Y) / mean(Y)
```

固定 central ROI 而不是随水果大小变化，是为了在 80/100/120% 条件之间保持同一局部视野定义。

### 5.3 与背景和 mask 的亮度步长

正式表额外计算：

```text
delta_screen_rel_lum_vs_background
delta_central_rel_lum_vs_background

delta_screen_rel_lum_vs_mask
delta_central_rel_lum_vs_mask
```

其中 `vs_mask` 特别用于描述从上一 trial 末尾 900 ms mask 到当前水果画面的数字亮度变化方向和大小。后续 PIR 模型可同时保留当前条件和上一 trial 条件，以控制残留 pupil light response。

## 6. 分析边界

1. 这 27 行视觉表是 **刺激级固定协变量**，通过 `stimulus_name + stimulus_size` join 到北京正式 116 人的 trial；由于全部正式样本使用同一台 2880×1920 Surface Pro，不需要每个被试重算。
2. 数字 relative luminance 不能替代实际显示器光度计测量。由于北京实验显示亮度与环境照明大体固定，它适合用于控制 **条件间相对视觉差异**，不用于声称绝对视网膜照度。
3. 当前表不把 probe 图混入 27 conditions。Probe 主分析使用 probe onset 前窗口，因此 probe 自身亮度不会倒因果影响 pre-probe NIR；probe 后恢复 trial 仍由 alignment 中的 probe contamination 信息处理。
4. `掩蔽刺激.png` 作为统一参考画面进入 manifest 和 delta 字段，不作为第 28 个 trial condition。
5. 该模块与 `nir-behavior-v1.2 / schema 2` 解耦。视觉算法若调整，只需重建 27 行表并重新 join，不需要重跑 YOLO/RITnet 或 NIR×Behavior 时间对齐。

## 10. 报告用方法描述

可直接用于正式报告的方法段落：

> 考虑到瞳孔大小除受注意与警觉状态影响外，还会受到视觉刺激亮度变化所诱发的瞳孔光反射（pupillary light response, PLR）影响，本研究进一步对 SART 正式任务中的视觉刺激进行了离线重建，并提取刺激级视觉协变量，用于后续 NIR 瞳孔指标分析中的统计控制。正式任务包含 8 种 Go 刺激和 1 种 No-Go 刺激，每种刺激分别以 80%、100% 和 120% 三种尺寸呈现，共形成 27 种视觉条件。所有正式被试均使用同一台 Surface Pro 完成实验，其运行时检测到的显示分辨率为 2880 × 1920 pixels。刺激重建严格按照正式实验程序的绘制规则进行：任务背景图根据实验窗口宽度等比例缩放并居中呈现，水果刺激固定呈现在屏幕中央附近，其基础尺寸为 412 pixels，并依据试次中记录的 `stimulus_size` 缩放至 80%、100% 或 120%。因此，三种条件对应的刺激边长约为 330、412 和 494 pixels。对于每一种重建条件，分别计算完整实验屏幕、以刺激中心为中心的固定 600 × 600 pixels 区域，以及水果实际可见区域的数字相对亮度和 RMS contrast。相对亮度首先将 sRGB 像素值线性化，再依据 `Y = 0.2126R + 0.7152G + 0.0722B` 计算；RMS contrast 定义为区域内相对亮度的标准差与平均值之比。除此之外，还计算了当前水果画面相对于背景画面及掩蔽画面的亮度变化量，以描述相邻视觉画面之间可能诱发 PLR 的亮度变化。上述数值均为基于数字图像的相对视觉指标，不代表经过光度计校准的物理屏幕亮度。后续 trial-level 分析可根据 `stimulus_name` 和 `stimulus_size` 将上述视觉参数匹配至行为及 NIR 数据，以控制不同刺激身份和尺寸所带来的视觉输入差异。

## 11. 27 条件视觉差异的实际结果

以下结果来自当前正式生成的 `stimulus_visual_properties.csv`，共 27 行。为了避免固定背景稀释水果本身的视觉差异，报告解释优先关注固定 600×600 中央 ROI，同时保留 full-screen 和 fruit-support 指标用于敏感性分析。

### 11.1 中央区域亮度极值

27 条件中：

- `07_kale × 120%` 的 `central_rel_lum_mean` 最低：**0.6525**；
- `04_bitter_melon × 80%` 的 `central_rel_lum_mean` 最高：**0.7829**；
- 极差约为 **0.1303**。

完整屏幕平均亮度的差异明显更小：

- 最低仍为 `07_kale × 120%`：**0.7214**；
- 最高仍为 `04_bitter_melon × 80%`：**0.7299**；
- 极差约为 **0.0085**。

这说明条件间真正有分析价值的亮度差异主要集中在中央刺激区域，而 full-screen 指标会被大面积固定背景显著稀释。

### 11.2 中央区域与水果区域对比度极值

中央 ROI 的 RMS contrast：

- 最低：`02_grape × 80%`，**0.3360**；
- 最高：`07_kale × 120%`，**0.5229**。

水果实际可见区域的 RMS contrast 差异更明显：

- 最低：`09_no_go × 100%`，约 **0.3787**；
- 最高：`07_kale × 100%`，约 **0.9612**。

因此 `07_kale` 是当前 9 种刺激中最明显的视觉异质项：平均亮度相对较低，同时具有较高的局部对比度和较复杂的边缘/纹理结构。

### 11.3 按刺激身份跨三种尺寸平均

中央区域平均亮度：

| 刺激 | 平均 `central_rel_lum_mean` |
|---|---:|
| `07_kale` | 0.6957 |
| `06_kiwi` | 0.7388 |
| `03_avocado` | 0.7395 |
| `08_lime` | 0.7400 |
| `01_mango` | 0.7436 |
| `09_no_go` | 0.7441 |
| `02_grape` | 0.7611 |
| `05_cucumber` | 0.7634 |
| `04_bitter_melon` | 0.7669 |

中央 RMS contrast 的跨尺寸均值中，`07_kale` 最高（约 **0.4661**），而 `02_grape` 较低（约 **0.3517**）。

### 11.4 刺激尺寸存在系统性视觉效应

将 9 种刺激平均后：

| `stimulus_size` | 中央平均亮度 | 中央 RMS contrast | 水果可见面积占中央 ROI |
|---:|---:|---:|---:|
| 80% | 0.7668 | 0.3552 | 8.58% |
| 100% | 0.7447 | 0.3791 | 13.37% |
| 120% | 0.7195 | 0.4059 | 19.23% |

即随着刺激由 80% 增大到 120%，固定中央 ROI 中的水果占比增加，中央平均相对亮度持续下降，而 RMS contrast 持续增加。因此 `stimulus_size` 不只是任务设计标签，本身也系统性改变中央视觉输入。

### 11.5 相对于 mask 的亮度步长

中央区域 `delta_central_rel_lum_vs_mask`：

- 最大：`04_bitter_melon × 80%`，约 **0.2147**；
- 最小：`07_kale × 120%`，约 **0.0843**。

这说明从前一阶段统一 mask 切换到当前水果画面时，不同 trial 的局部数字亮度变化幅度并不完全相同，因此该变量可以作为 PLR 控制的候选量。

## 12. 报告可直接使用的结果描述

推荐正文表述：

> 对 27 种正式刺激条件的视觉特征分析显示，不同刺激身份及呈现尺寸之间存在一定的数字亮度和局部对比度差异。以刺激中心固定 600 × 600 pixels 区域为例，平均相对亮度介于 0.653–0.783 之间，其中 120% 羽衣甘蓝条件最低，80% 苦瓜条件最高；RMS contrast 介于 0.336–0.523 之间，其中 120% 羽衣甘蓝条件最高。进一步按刺激尺寸平均发现，随着刺激由 80% 增大至 120%，中央区域平均相对亮度由 0.767 下降至 0.720，而 RMS contrast 由 0.355 增加至 0.406，说明刺激尺寸操纵本身会系统性改变中央视觉输入。因此，在后续瞳孔指标分析中，将刺激身份、刺激尺寸及其对应的中央区域视觉特征作为候选控制变量，以降低刺激诱发 pupil light response 与注意状态效应之间的混淆。

## 13. 当前视觉协变量优先级

正式表继续完整保留所有视觉字段，不在数据生成阶段提前删除信息。基于当前 27 条件的实际差异，后续统计模型优先考虑：

```text
1. central_rel_lum_mean
2. central_rms_contrast
3. delta_central_rel_lum_vs_mask
```

理由：完整屏幕大部分由固定背景构成，条件间 full-screen luminance 极差仅约 0.0085，而中央 ROI 的 luminance 极差约 0.1303，更能反映 trial 条件真正改变的局部视觉输入。最终是否同时保留三项、如何处理共线性，以及是否加入上一 trial 的视觉协变量，仍须在全样本模型冻结阶段决定，不根据单一视觉表提前锁死统计模型。
