# 029｜PIR 有效性与 usable 筛选定义

> 2026-08-26｜适用于当前北京 NIR full-class `ritnet-fullclass-v1.2-fast-qc` 数据及其下游分析。本文专门冻结 `fullclass_normalization_valid` 与 PIR `usable` 的真实代码判定条件，作为数据质量控制、筛选、方法报告与后续窗口覆盖率计算的依据。

## 1. 为什么必须单独记录

正式瞳孔主指标为：

```text
fullclass_pupil_to_iris_diameter_ratio
```

简称 PIR（pupil-to-iris diameter ratio，瞳孔/外虹膜几何平均直径比）。

**“CSV 中存在一个 PIR 数字”不等于“这一帧 PIR 可以进入正式分析”。**

当前下游分析把一帧 PIR 定义为 usable，必须同时满足：

```text
fullclass_normalization_valid == True
AND
fullclass_pupil_to_iris_diameter_ratio 是 finite 数值
```

因此需要把 `fullclass_normalization_valid` 本身的条件完整展开，而不能只写“有效帧”。

---

## 2. 当前 AMD 44 人正式 full-class 数据的生产路径

当前 44 人使用 `ritnet-fullclass-v1.2-fast-qc` fast production path。

该路径中：

1. 原正式 NIR `eyes.csv` 中已经冻结的 pupil geometry（瞳孔中心、椭圆轴、confidence 等）被复用；
2. full-class extension 使用同一冻结 RITnet 对四分类标签重新获得完整结构信息；
3. `iris_outer = class 2 OR class 3`，即“可见虹膜组织 + 瞳孔孔洞”共同重建外虹膜区域；
4. iris outer 在 320×160 analysis coordinates 中重新拟合椭圆；
5. 再根据 pupil 与 iris outer 的几何关系计算 PIR 和 `normalization_valid`。

这与 validation/reference path 有一点实现差别：reference path 会从当前 label map 重新拟合 pupil；当前正式 fast-production path 则复用 source `eyes.csv` 的正式 pupil geometry。两条路径最终使用相同的 `normalization_valid` 总门控表达式。

---

## 3. PIR 本身如何计算

定义 pupil geometric-mean diameter：

```text
D_pupil = sqrt(pupil_axis_a × pupil_axis_b)
```

定义 iris outer geometric-mean diameter：

```text
D_iris = sqrt(iris_axis_a × iris_axis_b)
```

主 PIR 为：

```text
PIR = D_pupil / D_iris
```

即：

```text
fullclass_pupil_to_iris_diameter_ratio
```

注意：这里的 iris 不是单独 RITnet class 2，而是：

```text
iris_outer = class 2 OR class 3
```

因为 class 2 只表示可见虹膜组织，中央 pupil hole 属于 class 3。如果只用 class 2，会把瞳孔扩大导致的“虹膜组织面积减少”误当成虹膜尺度变化。

---

## 4. `fullclass_normalization_valid == True` 的精确条件

生产代码的逻辑等价于：

```python
normalization_valid = (
    pupil_fit_valid
    and iris_outer_fit_valid
    and not pupil_touches_roi_edge
    and not iris_outer_touches_roi_edge
    and pupil_center_in_iris_outer
    and iris_geom_mean_diameter > pupil_geom_mean_diameter
)
```

也就是说，**下面 6 项必须全部成立**。

### 条件 1｜pupil ellipse 必须有效

当前 AMD fast-production path 复用 source `eyes.csv` 中已经冻结的瞳孔几何。其 `pupil_fit_valid=True` 要求：

```text
ritnet_found == True
AND pupil_center_x 存在
AND pupil_center_y 存在
AND pupil_axis_a 存在
AND pupil_axis_b 存在
AND pupil_axis_a > 0
AND pupil_axis_b > 0
```

含义：原正式 RITnet 必须找到瞳孔，而且椭圆中心与两个轴都存在且为正值。

如果任一项失败，则该帧不能通过 PIR normalization gate。

### 条件 2｜iris outer ellipse 必须有效

full-class extension 先构造：

```text
iris_outer = class 2 OR class 3
```

然后只取该 mask 的**最大外轮廓**。轮廓及椭圆拟合必须依次满足：

```text
存在外轮廓
AND 最大外轮廓面积 >= 5 px²
AND 轮廓点数 >= 5
AND cv2.fitEllipse 得到 axis_a > 0
AND cv2.fitEllipse 得到 axis_b > 0
```

这里的像素坐标是当前正式 full-class 的 320×160 analysis coordinates。

因此，虹膜/瞳孔分割过少、没有形成可拟合外轮廓，或者椭圆轴无效时，该帧不能用于正式 PIR normalization。

### 条件 3｜pupil mask 不能触碰 analysis ROI 边缘

生产代码检查 pupil mask 是否在 320×160 analysis mask 的以下任何位置出现像素：

```text
第一行
最后一行
第一列
最后一列
```

只要触碰任一边，就有：

```text
pupil_touches_roi_edge == True
→ normalization_valid == False
```

原因：瞳孔触边意味着其轮廓可能被 ROI 截断，拟合出的直径不再可靠。

### 条件 4｜iris outer mask 不能触碰 analysis ROI 边缘

对 `iris_outer = class 2 OR class 3` 使用完全相同的边缘检查。

只要外虹膜 mask 触碰 320×160 analysis ROI 的最上/下/左/右边界：

```text
iris_outer_touches_roi_edge == True
→ normalization_valid == False
```

原因同样是：外虹膜尺度参照可能被截断，不能安全作为 pupil normalization 的分母。

**注意：这里的 `pupil/iris_outer_touches_roi_edge` 与生产表中的 `roi_clipped` 不是同一个概念。**

- `roi_clipped`：YOLO 眼框进一步放大后，裁剪 ROI 是否碰到原始视频画面边界；它本身不是自动坏帧条件。
- `pupil_touches_roi_edge` / `iris_outer_touches_roi_edge`：RITnet 分割出的具体结构是否碰到 320×160 analysis ROI 边界；这两项直接参与 `normalization_valid`。

不能把二者混为一谈。

### 条件 5｜pupil center 必须位于 iris outer contour 内部或边界上

当 pupil 与 iris outer 都拟合成功后，代码使用 OpenCV：

```python
cv2.pointPolygonTest(iris_contour, pupil_center, False) >= 0
```

即：

```text
pupil_center_in_iris_outer == True
```

要求瞳孔椭圆中心位于外虹膜最大轮廓内部，或者恰好落在轮廓边界上。

如果瞳孔中心落在外虹膜轮廓之外，说明 pupil 与 iris outer 的空间关系明显不符合正常嵌套结构，不能把两者直径直接组成 PIR。

### 条件 6｜外虹膜几何平均直径必须大于瞳孔几何平均直径

要求：

```text
D_iris > D_pupil
```

即：

```text
sqrt(iris_axis_a × iris_axis_b)
>
sqrt(pupil_axis_a × pupil_axis_b)
```

如果外虹膜直径不大于瞳孔直径，结构关系不合理，因此：

```text
normalization_valid == False
```

该条件也保证正式有效 PIR 在正常几何关系下应小于 1。

## 5. `finite PIR` 为什么还要单独检查

PIR 数值的生成条件比 `normalization_valid=True` 宽松。

只要：

```text
pupil_fit_valid == True
AND iris_outer_fit_valid == True
AND D_iris > 0
```

代码就可以计算：

```text
PIR = D_pupil / D_iris
```

此时即使：

- pupil touches ROI edge；
- iris outer touches ROI edge；
- pupil center 不在 iris outer contour 内；
- D_iris <= D_pupil；

CSV 中仍可能已经存在一个 PIR 数字。

因此下游不能用“PIR 列不是空值”作为正式有效性标准。

下游另外执行：

```python
pir_finite = np.isfinite(pir)
pir_usable = normalization_valid & pir_finite
```

其中 finite 用于排除 NaN、+inf、-inf 等非有限数值，是最后一层数值安全检查。

---

## 6. 最终的 frame-level PIR usable 定义

正式定义：

```text
PIR usable frame
=
[pupil fit valid]
AND [iris outer fit valid]
AND [pupil 不触碰 analysis ROI edge]
AND [iris outer 不触碰 analysis ROI edge]
AND [pupil center 位于 iris outer contour 内/边界]
AND [D_iris > D_pupil]
AND [PIR 是 finite 数值]
```

这才是当前 cohort QC 中所谓的 **PIR usable**。

它不是：

- RITnet 找到眼睛；
- RITnet 找到瞳孔；
- PIR 列有数字；
- `roi_clipped=False`；
- OAR 可用；

其中任何一个单独条件的同义词。

## 7. 三个容易混淆的 cohort QC 比例

对一个 `subject × eye × Block`，分母都是该 eye×Block 中的全部 NIR 行。

### `pir_numeric_finite_fraction`

```text
PIR 为有限数值的帧数 / 全部 NIR 帧数
```

只说明“PIR 数值算出来了多少”，不代表几何关系可靠。

### `pir_normalization_valid_fraction`

```text
fullclass_normalization_valid == True 的帧数 / 全部 NIR 帧数
```

说明通过上述 6 项几何门控的比例。

### `pir_usable_fraction`

```text
(normalization_valid == True AND PIR finite) 的帧数 / 全部 NIR 帧数
```

这是正式 PIR 分析真正使用的帧级可用比例。

正常情况下 `normalization_valid` 已经隐含可靠的正直径关系，因此 `usable` 与 `normalization_valid` 会非常接近；但下游仍保留 finite 检查作为数值安全门。

---

## 8. 如何解释“finite 很高但 usable 很低”

例如当前 cohort QC 中出现过某些 eye×Block：

```text
pir_numeric_finite_fraction ≈ 1
pir_usable_fraction ≈ 0.01
```

这不表示“只有 1% 的帧算出了 PIR”。相反，它表示：

> 几乎每帧都有一个数值 PIR，但约 99% 的帧没有通过完整的 pupil–iris 结构有效性门控。

这种模式需要理解为**几何有效性问题**，而不是简单的数据缺失。

如果需要进一步解释某个被试为什么大量失败，应继续分解对应帧的：

```text
pupil_fit_valid
iris_outer_fit_valid
pupil_touches_roi_edge
iris_outer_touches_roi_edge
pupil_center_in_iris_outer
D_iris > D_pupil
```

各自失败比例，而不能仅凭 `pir_usable_fraction` 猜测原因。

---

## 9. 与后续 trial / probe / time-bin 筛选的关系

本文冻结的是**帧级** PIR usable 定义。

后续正式分析还需要第二层筛选：例如一个 trial 前 10 s、probe 前 60 s 或一个 60 s time-on-task bin 中，有多少帧是本文定义的 usable PIR。

因此：

```text
第一层：frame-level structural validity
        ↓
本文定义 PIR usable frame
        ↓
第二层：analysis-window coverage
        ↓
决定具体 trial / probe / time-bin 能否进入对应模型
```

第二层 coverage 阈值必须针对具体分析单位在正式建模前冻结，不能根据哪一个阈值得到更显著结果再选择。
