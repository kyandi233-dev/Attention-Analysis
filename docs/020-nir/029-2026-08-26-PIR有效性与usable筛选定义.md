# 029｜PIR 有效性、usable 筛选与正式报告口径

> 2026-08-26｜适用于当前北京 NIR full-class `ritnet-fullclass-v1.2-fast-qc` 数据及其下游分析。本文冻结 `fullclass_normalization_valid` 与 PIR `usable` 的真实代码判定条件，并明确其作为正式数据筛选条件及后续报告方法部分的统一口径。

## 1. 为什么必须单独记录

正式瞳孔主指标为：

```text
fullclass_pupil_to_iris_diameter_ratio
```

简称 PIR（pupil-to-iris diameter ratio，瞳孔/外虹膜几何平均直径比）。

**“CSV 中存在一个 PIR 数字”不等于“这一帧 PIR 可以进入正式分析”。**

当前下游分析把一帧 PIR 定义为 usable，必须同时满足：

```text
fullclass_normalization_valid == True
AND
fullclass_pupil_to_iris_diameter_ratio 是 finite 数值
```

因此必须把 `fullclass_normalization_valid` 本身的条件完整展开，并在正式报告中明确将其作为数据筛选条件，而不能只写成笼统的“有效帧”。

正式分析前，PIR 采用两层筛选：

```text
RITnet full-class 原始逐帧结果
        ↓
第一层：帧级结构有效性筛选
        ↓
PIR usable frames
        ↓
第二层：具体分析单元的有效覆盖率筛选
        ↓
可进入 trial / probe / time-bin / baseline 等模型的数据
```

**第一层条件已冻结；第二层 coverage 条件必须在对应正式分析建模前冻结。**

---

## 2. 当前 AMD 44 人正式 full-class 数据的生产路径

当前 44 人使用 `ritnet-fullclass-v1.2-fast-qc` fast production path。

该路径中：

1. 原正式 NIR `eyes.csv` 中已经冻结的 pupil geometry（瞳孔中心、椭圆轴、confidence 等）被复用；
2. full-class extension 使用同一冻结 RITnet 对四分类标签重新获得完整结构信息；
3. `iris_outer = class 2 OR class 3`，即“可见虹膜组织 + 瞳孔孔洞”共同重建外虹膜区域；
4. iris outer 在 320×160 analysis coordinates 中重新拟合椭圆；
5. 再根据 pupil 与 iris outer 的几何关系计算 PIR 和 `normalization_valid`。

这与 validation/reference path 有一点实现差别：reference path 会从当前 label map 重新拟合 pupil；当前正式 fast-production path 则复用 source `eyes.csv` 的正式 pupil geometry。两条路径最终使用相同的 `normalization_valid` 总门控表达式。

## 3. PIR 本身如何计算

定义 pupil geometric-mean diameter：

```text
D_pupil = sqrt(pupil_axis_a × pupil_axis_b)
```

定义 iris outer geometric-mean diameter：

```text
D_iris = sqrt(iris_axis_a × iris_axis_b)
```

主 PIR 为：

```text
PIR = D_pupil / D_iris
```

即：

```text
fullclass_pupil_to_iris_diameter_ratio
```

注意：这里的 iris 不是单独 RITnet class 2，而是：

```text
iris_outer = class 2 OR class 3
```

因为 class 2 只表示可见虹膜组织，中央 pupil hole 属于 class 3。如果只用 class 2，会把瞳孔扩大导致的“虹膜组织面积减少”误当成虹膜尺度变化。

---

## 4. `fullclass_normalization_valid == True` 的精确条件

生产代码的逻辑等价于：

```python
normalization_valid = (
    pupil_fit_valid
    and iris_outer_fit_valid
    and not pupil_touches_roi_edge
    and not iris_outer_touches_roi_edge
    and pupil_center_in_iris_outer
    and iris_geom_mean_diameter > pupil_geom_mean_diameter
)
```

也就是说，**下面 6 项必须全部成立**。

### 条件 1｜pupil ellipse 必须有效

当前 AMD fast-production path 复用 source `eyes.csv` 中已经冻结的瞳孔几何。其 `pupil_fit_valid=True` 要求：

```text
ritnet_found == True
AND pupil_center_x 存在
AND pupil_center_y 存在
AND pupil_axis_a 存在
AND pupil_axis_b 存在
AND pupil_axis_a > 0
AND pupil_axis_b > 0
```

含义：原正式 RITnet 必须找到瞳孔，而且椭圆中心与两个轴都存在且为正值。

如果任一项失败，则该帧不能通过 PIR normalization gate。

### 条件 2｜iris outer ellipse 必须有效

full-class extension 先构造：

```text
iris_outer = class 2 OR class 3
```

然后只取该 mask 的**最大外轮廓**。轮廓及椭圆拟合必须依次满足：

```text
存在外轮廓
AND 最大外轮廓面积 >= 5 px²
AND 轮廓点数 >= 5
AND cv2.fitEllipse 得到 axis_a > 0
AND cv2.fitEllipse 得到 axis_b > 0
```

这里的像素坐标是当前正式 full-class 的 320×160 analysis coordinates。

因此，虹膜/瞳孔分割过少、没有形成可拟合外轮廓，或者椭圆轴无效时，该帧不能用于正式 PIR normalization。

### 条件 3｜pupil mask 不能触碰 analysis ROI 边缘

生产代码检查 pupil mask 是否在 320×160 analysis mask 的以下任何位置出现像素：

```text
第一行
最后一行
第一列
最后一列
```

只要触碰任一边，就有：

```text
pupil_touches_roi_edge == True
→ normalization_valid == False
```

原因：瞳孔触边意味着其轮廓可能被 ROI 截断，拟合出的直径不再可靠。

### 条件 4｜iris outer mask 不能触碰 analysis ROI 边缘

对 `iris_outer = class 2 OR class 3` 使用完全相同的边缘检查。

只要外虹膜 mask 触碰 320×160 analysis ROI 的最上/下/左/右边界：

```text
iris_outer_touches_roi_edge == True
→ normalization_valid == False
```

原因同样是：外虹膜尺度参照可能被截断，不能安全作为 pupil normalization 的分母。

**注意：这里的 `pupil/iris_outer_touches_roi_edge` 与生产表中的 `roi_clipped` 不是同一个概念。**

- `roi_clipped`：YOLO 眼框进一步放大后，裁剪 ROI 是否碰到原始视频画面边界；它本身不是自动坏帧条件。
- `pupil_touches_roi_edge` / `iris_outer_touches_roi_edge`：RITnet 分割出的具体结构是否碰到 320×160 analysis ROI 边界；这两项直接参与 `normalization_valid`。

不能把二者混为一谈。

### 条件 5｜pupil center 必须位于 iris outer contour 内部或边界上

当 pupil 与 iris outer 都拟合成功后，代码使用 OpenCV：

```python
cv2.pointPolygonTest(iris_contour, pupil_center, False) >= 0
```

即：

```text
pupil_center_in_iris_outer == True
```

要求瞳孔椭圆中心位于外虹膜最大轮廓内部，或者恰好落在轮廓边界上。

如果瞳孔中心落在外虹膜轮廓之外，说明 pupil 与 iris outer 的空间关系明显不符合正常嵌套结构，不能把两者直径直接组成 PIR。

### 条件 6｜外虹膜几何平均直径必须大于瞳孔几何平均直径

要求：

```text
D_iris > D_pupil
```

即：

```text
sqrt(iris_axis_a × iris_axis_b)
>
sqrt(pupil_axis_a × pupil_axis_b)
```

如果外虹膜直径不大于瞳孔直径，结构关系不合理，因此：

```text
normalization_valid == False
```

该条件也保证正式有效 PIR 在正常几何关系下应小于 1。

## 5. `finite PIR` 为什么还要单独检查

PIR 数值的生成条件比 `normalization_valid=True` 宽松。

只要：

```text
pupil_fit_valid == True
AND iris_outer_fit_valid == True
AND D_iris > 0
```

代码就可以计算：

```text
PIR = D_pupil / D_iris
```

此时即使：

- pupil touches ROI edge；
- iris outer touches ROI edge；
- pupil center 不在 iris outer contour 内；
- D_iris <= D_pupil；

CSV 中仍可能已经存在一个 PIR 数字。

因此下游不能用“PIR 列不是空值”作为正式有效性标准。

下游另外执行：

```python
pir_finite = np.isfinite(pir)
pir_usable = normalization_valid & pir_finite
```

其中 finite 用于排除 NaN、+inf、-inf 等非有限数值，是最后一层数值安全检查。

## 6. 最终的 frame-level PIR usable 定义：正式数据筛选条件

正式定义：

```text
PIR usable frame
=
[pupil fit valid]
AND [iris outer fit valid]
AND [pupil 不触碰 analysis ROI edge]
AND [iris outer 不触碰 analysis ROI edge]
AND [pupil center 位于 iris outer contour 内/边界]
AND [D_iris > D_pupil]
AND [PIR 是 finite 数值]
```

这 7 项共同构成正式分析前的**帧级 PIR 数据筛选条件**。其中前 6 项组成 `fullclass_normalization_valid`，第 7 项是下游数值安全检查。

它不是：

- RITnet 找到眼睛；
- RITnet 找到瞳孔；
- PIR 列有数字；
- `roi_clipped=False`；
- OAR 可用；

其中任何一个单独条件的同义词。

不通过上述条件的 PIR：

```text
不改写为 0
不强行插补
不以邻近帧替代原值
不因此删除对应 Behavior trial
不自动删除整只眼
不自动删除整个 Block
不自动删除整名被试
```

其状态统一理解为：该时间点 PIR unavailable。

## 7. 三个容易混淆的 cohort QC 比例

对一个 `subject × eye × Block`，分母都是该 eye×Block 中的全部 NIR 行。

### `pir_numeric_finite_fraction`

```text
PIR 为有限数值的帧数 / 全部 NIR 帧数
```

只说明“PIR 数值算出来了多少”，不代表几何关系可靠。

### `pir_normalization_valid_fraction`

```text
fullclass_normalization_valid == True 的帧数 / 全部 NIR 帧数
```

说明通过上述 6 项几何门控的比例。

### `pir_usable_fraction`

```text
(normalization_valid == True AND PIR finite) 的帧数 / 全部 NIR 帧数
```

这是正式 PIR 分析真正使用的帧级可用比例。

正常情况下 `normalization_valid` 已经隐含可靠的正直径关系，因此 `usable` 与 `normalization_valid` 会非常接近；但下游仍保留 finite 检查作为数值安全门。

---

## 8. 如何解释“finite 很高但 usable 很低”

例如当前 cohort QC 中出现过某些 eye×Block：

```text
pir_numeric_finite_fraction ≈ 1
pir_usable_fraction ≈ 0.01
```

这不表示“只有 1% 的帧算出了 PIR”。相反，它表示：

> 几乎每帧都有一个数值 PIR，但约 99% 的帧没有通过完整的 pupil–iris 结构有效性门控。

这种模式需要理解为**几何有效性问题**，而不是简单的数据缺失。

如果需要进一步解释某个被试为什么大量失败，应继续分解对应帧的：

```text
pupil_fit_valid
iris_outer_fit_valid
pupil_touches_roi_edge
iris_outer_touches_roi_edge
pupil_center_in_iris_outer
D_iris > D_pupil
```

各自失败比例，而不能仅凭 `pir_usable_fraction` 猜测原因。

---

## 9. 6 条 gate 失败比例：筛选结果的诊断，不是新的筛选阈值

`pir_usable_fraction` 只能告诉我们一个 eye×Block 最终有多少帧可用，不能说明为什么失败。因此 cohort QC 增加独立审计：

```text
scripts/nir_pir_gate_failure_qc.py
```

按 `subject × eye × Block` 分别统计：

```text
gate_pupil_fit_failure_fraction
gate_iris_outer_fit_failure_fraction
gate_pupil_not_edge_failure_fraction
gate_iris_outer_not_edge_failure_fraction
gate_pupil_center_in_iris_failure_fraction
gate_iris_larger_than_pupil_failure_fraction
```

并同时保留：

```text
pir_numeric_finite_fraction
pir_normalization_valid_fraction
pir_usable_fraction
normalization_gate_mismatch_fraction
```

默认输出：

```text
D:/_AttentionData/Beijing-NIR/analysis/nir-behavior-v2/cohort-44-exploratory/
└── 01_qc/
    └── screening_review/
        └── pir_gate_failure_qc/
            ├── pir_gate_failure_by_eye_block.csv
            ├── pir_gate_failure_distribution.csv
            ├── pir_gate_failure_top_records.csv
            └── README.md
```

这些失败比例用于回答“被筛掉的帧主要违反哪一条既定条件”。它们本身**不生成新的 subject / eye / Block 排除阈值**。同一帧可能同时违反多条 gate，因此各 failure fraction 不能简单相加解释为互斥原因比例。

## 10. 第二层：analysis-specific coverage 筛选

本文第 4–6 节只回答：

> 某一帧 PIR 本身是否结构可靠？

正式分析还必须回答：

> 一个 trial / probe 前窗口 / 60 s time-bin 中，有没有足够多的可靠 PIR 帧？

因此每一种正式分析都需要单独冻结 coverage rule，例如：

```text
trial-level PIR window
probe 前 10/20/30/60 s window
60 s time-on-task bin
subject×eye baseline period
```

这些分析单元的最低有效覆盖率目前**尚未冻结**，不能在看到显著性结果之后选择。冻结后，应在正式报告中明确报告：

- 候选分析单元数；
- 因 PIR coverage 不足被排除的分析单元数；
- 最终进入模型的分析单元数；
- 实际被试 N；
- 每名被试贡献的数据单元范围。

因此本项目最终采用的是：

```text
frame-level structural screening
+
analysis-specific coverage screening
```

而不是先制定一份“一刀切删除某些被试”的名单。

## 11. 正式报告中的方法结构

正式论文/竞赛报告的数据质量部分至少应区分三个小节。

### 11.1 NIR 数据预处理与 PIR 构建

说明：

- YOLO 定位眼睛 ROI；
- RITnet 四分类分割 background / sclera / iris / pupil；
- `iris_outer = iris OR pupil`；
- pupil 与 iris outer 使用椭圆几何；
- PIR 使用 pupil/iris geometric-mean diameter ratio。

这一部分解释“变量怎么得到”。

### 11.2 PIR 数据质量控制与帧级筛选

说明本文第 4–6 节的 6 项结构 gate + finite 检查。

这一部分解释“哪些 PIR 数据被认为可靠并保留”。

### 11.3 分析单元覆盖率与最终样本量

针对每一个 trial / probe / time-bin 模型说明对应 coverage rule 以及筛选后的有效 N。

这一部分解释“可靠帧如何进一步组成最终统计样本”。

不要把这三步合并成一句“删除异常值”。

## 12. 可直接用于正式报告的方法表述（当前版本）

下面文本作为正式报告方法部分的基础版本。最终分析冻结 coverage threshold 后，只需补第二段中的具体阈值和最终有效 N。

### 12.1 PIR 帧级筛选

> 对近红外眼部数据，首先依据 RITnet 四分类分割结果构建瞳孔–虹膜直径比（pupil-to-iris diameter ratio, PIR）。为避免将结构截断或几何关系异常的分割结果纳入统计，PIR 在逐帧层面进行质量筛选。仅当瞳孔椭圆与外虹膜椭圆均可有效拟合、二者均未触及分析 ROI 边界、瞳孔中心位于外虹膜轮廓内部或边界上，且外虹膜几何平均直径大于瞳孔几何平均直径时，该帧被标记为 normalization-valid。随后进一步要求 PIR 为有限数值（finite）。只有同时满足上述结构有效性条件与数值有效性条件的帧才被定义为 usable PIR frames，并进入后续汇总与建模；无效帧不被置零或强行插补。

### 12.2 分析单元筛选

> 由于逐帧缺失可能局限于单眼或局部时段，本研究不依据单个坏帧或单个 eye×Block 的总体可用率直接删除整名被试。对于 trial、probe 前时间窗及 time-on-task 时间窗等分析，分别依据预先设定的 PIR 有效覆盖率标准筛选对应分析单元，并报告筛选前候选单元数、因覆盖率不足而排除的单元数及最终进入模型的有效样本量。具体覆盖率标准在查看相应效应结果前预先冻结，以避免结果导向的阈值选择。

上述“预先设定的 PIR 有效覆盖率标准”目前仍是待冻结部分。正式报告最终版必须替换为实际使用的数值，不得留作模糊描述。

## 13. 正式报告建议提供的筛选流程表

最终报告建议保存一张筛选流程表，而不是只报告最后 N：

| 层级 | 候选数据量 | 筛选条件 | 排除/不可用数量 | 保留数量 |
|---|---:|---|---:|---:|
| 原始 NIR frame | 待最终统计 | full-class 数据存在 | 待统计 | 待统计 |
| PIR structural-valid frame | 待最终统计 | 6 项 normalization gate | 待统计 | 待统计 |
| PIR usable frame | 待最终统计 | structural-valid + finite | 待统计 | 待统计 |
| trial/probe/time-bin | 按分析分别统计 | 对应 coverage rule | 待统计 | 待统计 |
| subject | 44 人探索样本；正式样本后续更新 | 仅不可恢复结构错误才做全局排除 | 当前 0 | 当前 44 |

44 人数字只用于当前 exploratory/development cohort；正式约 116 人数据完成后必须重新生成最终报告数字，不能直接复制当前 44 人结果。
