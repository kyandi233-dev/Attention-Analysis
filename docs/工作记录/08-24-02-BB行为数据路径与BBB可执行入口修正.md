## 本轮确认

用户进一步确认了正式数据在不同硬盘上的实际根目录：E 盘包含 `E:/正式实验` 与 `E:/Data`，F 盘对应 `F:/Data`。以 `sub-031_` 为例，最终 FocusWave v3.1.3 行为目录包含 `sub-031_Block1_B_beh.csv` 与 `sub-031_Block2_B_beh.csv`，NIR 目录包含 `sub-031_nir.avi` 与 `sub-031_nir_timestamps.csv`。该结构与当前最终正式实验的 BB 两 block 设计一致。

本轮将 `configs/behavior_formal.yaml` 与 `runtime/nir-formal/config.yaml` 的数据根统一为 `E:/正式实验`、`E:/Data`、`F:/Data`，避免 Behavior 与 NIR 在不同机器上使用互相矛盾的盘符约定。当前 BB reader 已支持 `sub-XXX_` / `sub-XXX` 两种目录名，并严格要求 Block1、Block2 两个正式行为 CSV 同时存在。

## BBB 历史实现保留策略

用户明确要求：v3.0 BBB 行为分析程序虽然不属于当前正式口径，但应继续保留可执行版本，方便以后直接重跑，而不是只留下报告或依赖 Git checkout 后重新恢复代码。

因此主线新增独立历史入口 `scripts/sart_bbb_v3_0_analysis.py`，配置为 `configs/sart_bbb_v3_0.yaml`，其实现冻结在 `src/attention_pipeline/behavior_bbb_v3_0/`。该包复制自 2026-08-16 BBB 分析时期的 `behavior_formal` 实现，并与当前 `src/attention_pipeline/behavior_formal/` 完全分离。这样以后修改最终 v3.1.3 BB 的统计方法时，不会静默改变历史 BBB 的复现结果。

当前正式行为入口仍是 `scripts/sart_formal_analysis.py` + `configs/behavior_formal.yaml`；历史 BBB 入口在文件名、配置名、包名和文档中均显式带 `bbb_v3_0` 标记，不允许作为当前正式分析解释。
