当前项目已经完成正式 NIR 全量分析，不再处于“准备正式分析”阶段。当前正式 NIR 主链为：


## 五、`models/` 与 RITnet 整理原则

### 1. 当前正式模型链路

YOLO26n：

```text
datasets/nir-eye-v1/
→ training/nir-eye-yolo/
→ training/nir-eye-yolo/runs/yolo26n_eye_100epoch/weights/best.pt
→ runtime/nir-formal/models/nir-eye-yolo26n-best.pt
```

RITnet 正式权重：

```text
runtime/nir-formal/models/ritnet-best_model.pkl
```

### 2. 为什么训练结果放 `training/` 而不是 `models/`

`training/` 保存的是本项目自己的训练 provenance：数据划分、训练过程、runs、best/last 权重和评价关联。它不是可以随意归档掉的“临时过程目录”，因为当前正式 YOLO 模型的来源必须能够从这里追溯。

### 3. RITnet 源代码的最终位置

RITnet 与 DeepVOG / pye3d / face-parts 等历史候选不同：RITnet 是当前正式 NIR 主链的一部分。

当前 `runtime/nir-formal/` 已经包含：

```text
runtime/nir-formal/ritnet/
runtime/nir-formal/ritnet_runtime.py
runtime/nir-formal/models/ritnet-best_model.pkl
```

因此正式运行所需要的冻结 RITnet 源码应继续保存在 `runtime/nir-formal/ritnet/`。

**不建议放进 `tools/`。** `tools/` 应保存独立辅助工具，而 RITnet 是正式 runtime 的直接算法依赖。

需要进一步区分：

- `runtime/nir-formal/ritnet/`：正式运行实际依赖的冻结 / 精简源码，建议保留。
- `models/external/ritnet/`：完整上游 RITnet 仓库副本；是否继续保留待审计。

如果后续确认 runtime 内已经具备：

- 正式运行所需代码；
- 模型权重；
- 上游来源 URL；
- 使用版本 / commit 或可识别版本信息；
- 必要 license / attribution；
- 本项目做过的必要适配说明；

那么完整的 `models/external/ritnet/` 不再是新设备运行的必要条件，可以在单独获得删除许可后从 `main` 删除。

### 4. 已淘汰第三方模型源码

当前 `models/external/` 中仍包括 DeepVOG、DeepVOG-3D、pye3d、YOLO face-parts 等完整第三方源码；`models/historical/` 中还有 MediaPipe / YuNet / YOLO-face 等历史候选模型文件。

后续原则：

- 已明确淘汰、且可从公开来源重新获取的第三方源码，不必仅为了“曾经用过”永久堆在当前 `main`。
- 删除前必须先在 README / decisions / worklog 中记录：来源、版本或 commit、当时用途、验证结果、淘汰原因。
- tracking 时代 / 多算法时代完整仓库状态通过历史 tag 保留后，当前 `main` 可以进一步精简。
- 正式 runtime 直接需要的文件不因 `models/` 精简而删除。

## 六、`artifacts/` / `archive/` 当前判断

暂时不直接把 `artifacts/` 整体改名为 `archive/`。

需要先区分两种“过程资产”：

### A. 当前正式结果的必要 provenance

例如：

- `datasets/`
- `training/`

它们虽然来自研究过程，但当前正式 YOLO 模型仍直接依赖其 provenance，因此属于当前一等资产，不应归入 archive。

### B. 已结束路线留下的检查 / 比较证据

当前 `artifacts/` 中主要包括：

- `gate1-24eyes/`：早期 12 帧 / 24 眼准入审批包。
- `preview/`：早期视觉 / 网页预览输出。
- `roi-compare/`：不同 ROI 方法的早期比较结果。
- `roi-selection-smoke-sub011/`：很短的小规模 ROI 冒烟测试。
- `roi-selection-smoke3s-sub011/`：3 秒输入域 / 后端失败检查。

术语说明：

- Gate：阶段准入检查点，用来决定是否允许进入下一阶段。
- QC（Quality Control）：质量控制，不是当前 `artifacts/` 中的固定目录名。
- Benchmark：在统一条件下比较多个方法或配置，不是当前 `artifacts/` 中的固定目录名。
- Preview：用于人工查看的快速可视化预览。
- Smoke test：极小规模快速运行，用来确认程序 / 输入 / 环境有没有明显问题。

后续计划：

1. 对 `artifacts/` 每个目录逐项审计。
2. 判断其是否仍值得在当前 `main` 长期保留。
3. 对“已经退役但仍值得保存”的证据，可考虑统一进入 `archive/`。
4. 对完全可重新生成、且工作记录已经足够保留结论的临时输出，可提出删除建议，但必须逐项获得许可。
5. 在完成逐项判断前，不机械执行 `artifacts → archive`。
