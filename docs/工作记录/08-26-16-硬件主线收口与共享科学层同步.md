# 08-26-16 硬件主线收口与共享科学层同步

## 目标

项目长期分支从“按模态拆分”收口为“按硬件拆分”：

- `amd-DirectML`：长期 AMD 主线；包含 Behavior、NIR、RGB 及共享科学层，硬件执行器使用 DirectML/ONNX Runtime。
- `nvidia-cuda`：长期 NVIDIA 主线；包含 Behavior、NIR、RGB 及共享科学层，硬件执行器使用 PyTorch/CUDA（必要时保留 ORT-CUDA 作为可选 benchmark/profile）。

`rgb-dev` 与 `rgb-nvidia-cuda` 仅作为开发期 feature branch，待主线同步和验证完成后再删除；历史文件和工作记录不得删除。

## 已冻结的输出安全规则

正式科研输出不得依赖 Git working tree。NIR、RGB、Behavior 以及跨模态下游分析默认写入仓库外独立数据根；仓库内 `/outputs/` 仅允许临时/历史用途，并加入 `.gitignore`。

Git pull / branch merge 因此只更新代码和配置，不覆盖仓库外已有正式分析结果。重新运行分析脚本时仍需遵循各 runner 的 completion/resume/输出版本规则，避免人为指定同一路径造成业务层覆盖。

## 共享科学层同步原则

共享并保持一致：

- SART Behavior 与 NIR-Behavior alignment；
- trial / probe / phase / coverage / QC / diagnostics；
- stimulus visual covariates；
- RGB 数据发现、时间轴、Motion/Pose/Face 科学定义；
- Face 15 Hz timestamp-driven sampling；
- primary-face / EAR / eyelid derived / QC schema；
- 输出字段和跨硬件 parity 规则。

硬件特异部分保持分离：

- AMD DirectML / ONNX Runtime provider、模型导出与 batch profile；
- NVIDIA PyTorch/CUDA runtime、CUDA 环境和 batch profile；
- 各自硬件 benchmark、模型缓存和 workstation-specific data roots。
