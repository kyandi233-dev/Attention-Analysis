# 08-27-01 RITnet 原生分割落盘与几何链审计

## 任务结论

本轮把 full-class 补全从 `ritnet-fullclass-v1.2-fast-qc` 的 320×160 快速派生路径，升级为独立的 `ritnet-fullclass-v2-native640` 原生证据生产器。旧 v1.2 保留，不覆盖、不删除；v2 以 640×400 hard label store 为原始证据，CSV 为可重算派生数据，QC PNG 为人工审计材料。

已确认旧路径的核心问题包括：native label 被立即缩到 320×160；production pupil 复用旧 `eyes.csv` 而 iris 重新拟合，几何不统一；全量 label 没落盘；CSV 直接写最终文件；completion skip 没有重算产物哈希；`.onnx.data` 未进入模型身份；`pupil_confidence` 名称容易被误解为校准正确率；文档错误地把 CSV 描述为完整数值证据。

## v2 已落地的设计

- 新 extension：`ritnet-fullclass-v2-native640`，schema=2；
- 新文件名/label store 路径与 v1.2 完全分离；
- native metrics 只接受 `uint8 [400,640]` 且值域 `{0,1,2,3}`；
- pupil 与 iris_outer 从同一 label 的最大外轮廓重新拟合；
- 保存四类像素、component、whole-mask edge、largest-contour edge、ellipse、PIR、center offset、OAR；
- 不定义新的 primary valid/confidence cutoff；只保存 `gate_*`/`diagnostic_*`；
- pupil probability 摘要随 chunk 一起 checkpoint，避免恢复时重跑已经提交的 ROI；
- label chunk 原子提交、SHA256 校验；metadata tear 可由已提交 chunk 重建；
- CSV 使用 UUID `.partial`，从 label store 可重建；
- resume identity 覆盖 source eyes、video identity、ONNX、ONNX external data、input/class/preprocess、ROI source、schema、Git commit、config digest、chunk format；
- completion 重新核验 CSV、label index、所有 chunk 与 manifest 哈希后才写 complete；
- 四分类 confidence summary 候选 ONNX 与 production ONNX 分离，未通过 DirectML parity/performance 前标记 unavailable。

## 审计中新增发现

### 1. “native”不能等同“官方自带”

官方 RITnet 提供网络定义、冻结权重、四分类语义与必要预处理；当前 AMD ONNX 的 `labels_u8` 和 `pupil_probability` 是 Attention-Analysis 在 logits 后增加 ArgMax/Softmax/Gather 后得到的确定性接口。所有 ellipse、PIR、component、OAR、gate、QC、label store、completion 都是项目派生层。

### 2. 640×400 存在非等比例几何拉伸

YOLO ROI 会 resize 到固定 640×400，因此 native 坐标不等于 source ROI 无畸变坐标。v2 必须逐行保存 scale_x/scale_y/aspect_scale_ratio，并把 geometry coordinate system 明确写为 `ritnet_native_label`。后续若 source-coordinate geometry 更合适，应从保存的 hard label 映射重算，而不是重新跑 RITnet。

### 3. hard label 单独落盘仍不足以无损恢复概率摘要

hard label 无法反推 class-3 softmax map。若概率摘要只存在未完成 CSV 中，中断后只能重新推理。v2 因此在每个 chunk 同步保存 probability availability 和 6 个 pupil probability 摘要。

### 4. chunk rename 与 metadata 更新之间也可能断电

仅“chunk 临时文件→rename”仍有 metadata tear 风险。v2 在打开既有 store 时以 committed chunk 为事实源，能够重建 label index/chunk manifest；若 chunk 本身缺失或 hash 错误则拒绝恢复。

### 5. source CSV 必须先验证键与顺序

v2 在开始前拒绝重复 `(frame_idx, eye)`，并要求 `frame_idx` 非递减；否则 row ordinal 与视频顺序无法形成确定、可恢复的一一对应关系。也拒绝 source CSV 已经包含 `native_*`/`gate_*`/`diagnostic_*` 等 v2 保留字段，避免静默覆盖列。

### 6. 权重 provenance 的哈希算法必须写清

上游 `best_model.pkl` 的 `f0864e...` 是 Git blob SHA-1，不是 SHA256。v2 manifest 使用 `official_weights_git_blob_sha1`；运行模型本体 `.onnx` 与 `.onnx.data` 另存内容 SHA256。

## 当前验证状态

已在本地 CPU 环境完成 native metrics、label store、completion 的单元测试，覆盖 shape/dtype/domain、统一 pupil/iris 几何、edge/component、概率摘要、断点恢复、chunk 哈希损坏、CSV/index 交叉校验和 metadata tear 恢复。DirectML runtime、experimental evidence ONNX parity/性能、真实 `sub-031` 压缩率与吞吐仍需在 AMD 机器执行；在这些结果出来前，不启动 44 人全量重跑，也不冻结 `chunk_rows=128` 为最终参数。
