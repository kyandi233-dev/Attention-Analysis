## 2. 输入/输出契约（已实测验证）

- **输入**：单通道灰度，形状按 torch 为 `(1,1,640,400)`，即 numpy 里是 `(640,400)`（高640×宽400）。模型是全卷积，尺寸其实任意，但**贴近 640×400 训练分布效果最好**；维度建议为 16 的倍数（下采样5层/4次池化）。
- **输出**：`(1,4,640,400)` 的 logits → `argmax(1)` 得 `(640,400)` 类别图，**与输入同分辨率**（密集分割，无下采样损失）。
- **实测结果**：`best_model.pkl` 109 keys → `load_state_dict` OK，随机输入前向通过，输出 `(1,4,640,400)`。

## 3. 使用步骤（含最小推理代码）

预处理顺序必须和 `dataset.py` 完全一致（gamma→CLAHE→归一化），这是官方 README 明确写的：

```python
import numpy as np, cv2, torch
from densenet import DenseNet2D

# ── 1. 从1080p帧裁剪单眼ROI（灰度），缩放到 640x400（高x宽）──
# crop = 你的眼角ROI裁剪（cv2.resize, 保持16倍数即可，建议400,640）
crop = cv2.resize(crop_gray, (400, 640))

# ── 2. 预处理（与训练一致）──
table = (255.0*(np.linspace(0,1,256)**0.8)).astype(np.uint8)  # ① gamma 0.8
img = cv2.LUT(crop, table)
img = cv2.createCLAHE(clipLimit=1.5, tileGridSize=(8,8)).apply(img)  # ② CLAHE
x = torch.from_numpy(img).float()[None,None]        # (1,1,640,400)
x = (x/255.0 - 0.5)/0.5                              # ③ 均值0.5 std0.5

# ── 3. 推理 ──
model = DenseNet2D(dropout=True, prob=0.2)
model.load_state_dict(torch.load('best_model.pkl', map_location='cpu', weights_only=True))
model.eval()
with torch.no_grad():
    logits = model(x)                                # (1,4,640,400)
pred = logits[0].argmax(0).numpy()                   # (640,400)，3=瞳孔

# ── 4. 瞳孔后处理（拟合椭圆）──
pupil = (pred == 3).astype(np.uint8)*255
cnts,_ = cv2.findContours(pupil, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
if cnts:
    c = max(cnts, key=cv2.contourArea)
    if len(c) >= 5:
        (cx,cy),(MA,ma),ang = cv2.fitEllipse(c)      # 中心/长短轴/角度
        px_diam = (MA+ma)/2                          # 瞳孔直径(px)
```

性能：模型只有 24.9 万参数，CPU 上单眼 ~640×400 一次前向在几到几十 ms 量级，**30fps×双眼完全够用**。

## 4. 针对你工况的适配要点与风险

你的硬件描述（1080p/30fps/940nm窄带+940nm补光/30cm/正面仰拍鼻眼区）拆成四个适配问题：

1. **940nm NIR ✅ 匹配**：OpenEDS 就是 NIR 眼图，RITnet 的 CLAHE+gamma 预处理对暗光/补光不均本身有鲁棒性。但注意你的是**窄带滤光后的纯 940nm**，如果瞳孔是暗瞳（940nm 通常暗瞳），与 OpenEDS 分布一致；若出现镜片反光/补光局部过曝，官方训练时专门加了 `starburst_black.png` 和随机白线增强来处理镜片反光——这就是为什么它比普通分割模型更耐反光。
2. **距离30cm vs 训练假设（近距填满画面）⚠️ 这是最大域差**：RITnet 训练时眼睛几乎占满 640×400。你的画面眼睛占比小，必须**裁剪+放大**，且裁剪要带足眼周上下文（periocular），不要只切眼球——分割需要周围线索。
3. **仰拍视角 ⚠️ 中等域差**：OpenEDS 是头戴式近似正对；你是从下方仰拍，眼睑开合度、虹膜可见区域会变，瞳孔可能被下眼睑部分遮挡。RITnet 有开合度敏感性，**不要指望它替代眼睑门控**——你的管线里 EAR/开合度门控仍要保留在它之前。
4. **补光灯位置**：你的补光与相机分离、向下照（项目记忆里的正式采集约束）→ 眼窝可能产生阴影，瞳孔与虹膜对比度下降。RITnet 的 CLAHE 有一定帮助，但要在你的数据上验证，不能假设。

**没有内置置信度**：RITnet 输出没有 outline_confidence 之类。弱置信度可取自 pupil 区 softmax 最大概率，但阈值必须在你的 528 眼真值上校准。

## 6. 与现有管线衔接（简短）

你的 `configs/preexperiment.yaml` 里 NIR 段已经预留了 `fallback_order: [DeepVOG, RITnet]`——即 RITnet 在计划里是**六算法检测失败时的深度学习兜底**。这意味着：RITnet 不应作为独立竞争算法参加准入基准，而是走 `detector_missing` 分支的兜底；它的产出仍是像素掩膜→椭圆，可以进同一个椭圆 IoU/中心误差/直径误差的准入口径，但要按兜底分支单独记录，不能污染六算法 raw/CLAHE 基准。

另一个更关键的衔接点：**正式画面是"双眼/鼻梁特写"，而 MediaPipe、YuNet、当前 YOLO-face 三个 ROIn 都栽在"正确双眼 ROI 定位"上（0/60）**。RITnet 本身也不做眼睛定位——它假设你已经给了裁剪。所以在 RITnet 能起作用之前，你的硬门仍是**一个新的、能对双眼特写给出正确眼睛 ROI 的定位器**。这个没解决，RITnet 也只是"分割器没有输入可喂"。

> 可以讲解一下RITnet是什么分析思路吗

好，用大白话 + 代码里实际看到的细节讲一遍 RITnet 的**分析思路**。核心一句话：**它把"找瞳孔"从"找图像里最暗的椭圆"（几何启发式），改写成"逐像素分类"（学习式语义分割）**。这一步转变是它比经典算法强的根本原因。

## 1. 先看经典算法怎么做的（为什么容易失败）

Starburst / PuRe / ElSe 这类算法的分析思路是**自底向上的特征假设**：

```
"瞳孔比虹膜暗" → 找暗区域边缘 → 沿边缘撒射线采样 → 最小二乘拟合椭圆
```

一旦假设被打破就崩：反光让瞳孔不再是均匀最暗、睫毛/眼睑遮挡让边缘断裂、阴影伪造边缘。你项目里六算法全灭（最好 17.2% IoU）就是这么来的——它们在干净的 OpenEDS 上不错，但遇到你这种补光不均 + 眼镜 + 低开睑的画面就失灵。

## 2. RITnet 的转变：像素级分类（自顶向下学习）

RITnet 不问"瞳孔在哪"，而是问**"每个像素属于哪一类"**：

```
输入：单眼灰度图 (640×400)
输出：同样大小的一张类别图
  0=背景  1=巩膜  2=虹膜  3=瞳孔     ← 每个像素一个类别
```

好处：

- 模型自己从数据里学"什么算瞳孔"，不用人写规则；
- 输出的是**整块瞳孔区域**而不是单个椭圆，反光/睫毛挡住一部分也能从上下文补全；
- 顺带把虹膜/巩膜也分割出来——虹膜是瞳孔的天然边界约束，后续可以拿"瞳孔必须被虹膜包围"来校验。

## 3. 网络结构：DenseNet-UNet（编码器-解码器）

```
   640×400 输入
     │
  ┌──▼─────────────┐
  │ 下采样×4  Dense │  编码器：不断降分辨率、提特征
  │  (密集连接)     │        "这是什么结构"
  └──┬─────────────┘
     │  跳跃连接（skip）──┐   ← UNet 的关键
  ┌──▼─────────────┐    │
  │ 上采样×4       │    │
  │ 与下采样拼接    │────┘   解码器：逐步还原分辨率
  │ (最近邻插值)   │        "细节在哪"
  └──┬─────────────┘
     ▼
   4类类别图 (640×400)
```

两个设计意图值得记住：

- **Dense 密集连接**：每层能看到前面所有层的特征 → 特征复用、参数极少（**全模型仅 24.9 万参数**，这就是它"实时"的资本）。
- **UNet 跳跃连接**：下采样会把瞳孔边界细节磨糊，跳跃连接把高分辨率特征直接拼回来，**保证输出掩膜的边缘是锐的**。瞳孔直径测量恰恰靠的就是这条边界。

## 4. 预处理为什么是"gamma→CLAHE→归一化"

```
① gamma 0.8    : 把暗部提亮。瞳孔在 NIR 里极黑，gamma 让瞳孔内部"
                 不再是一坨饱和死黑，模型能看到里面的结构。
② CLAHE(1.5,8×8): 局部对比度均衡。处理补光不均/单侧反光——"
                 让"局部对比"代替"全局亮度"说话。
③ 归一化(0.5,0.5): 标准做法，稳定训练。
```

这套组合的核心意图是**让模型对亮度变化不敏感**——对 940nm 补光 + 阴影的场景是刻意设计的，不是随手选的。

## 5. 损失函数：为什么用三个损失叠加（这是最值得品的设计）

RITnet 不是单一 loss，而是三个专门针对"眼部分割会怎么失败"来设计的：

| 损失                     | 惩罚什么          | 背后的分析                                                                                                                                         |
| ------------------------ | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **边界加权交叉熵** | 瞳孔/虹膜边界糊掉 | 对标签做 Canny 边缘+膨胀，边界处权重×20。分割网络最常见的就是"边界被平均掉"，这个损失逼它在**边界像素上**必须准——而直径测量恰恰最依赖边界 |
| **广义 Dice**      | 类别不平衡        | 背景像素占绝大多数，纯交叉熵会学成"全都预测背景"。Dice 直接优化区域重叠                                                                            |
| **Surface loss**   | 边界偏移          | 用距离变换加权，让误分割的惩罚随距离平滑变化，减少边缘伪阳性                                                                                       |

训练时用一个随时间变化的权重 `alpha` 调度这三个损失——前期侧重哪、后期侧重哪都调过。**一句话：损失函数设计就是在回答"这个任务的错误会以什么形态出现"**。

## 6. 数据增强：每一招都对应一个真实失败源

训练时随机注入：

- **Starburst 星爆光斑**（20%）→ 模拟眼镜/VR 反光，让模型学会"看见亮斑不当回事"；
- **随机白线**（20%）→ 模拟睫毛/头发遮挡；
- **高斯模糊**（20%）→ 模拟失焦；
- **平移**（20%）→ 模拟裁剪对不准。

这是**领域感知的数据工程**：把真实世界会遇到的坑先装进训练数据。

## 7. 推理：全卷积 → 掩膜 → 椭圆

推理时模型是全卷积的（无全连接层），所以**输入尺寸可以任意**（这也是我敢喂 640×400 的原因）。流程：

```
图 → 4通道logits → argmax → 类别图 → 取类别3(瞳孔) → 最大连通域 → fitEllipse
                                                                    → 中心/长短轴/角度
```

## 8. 一句话总结它的"分析思路"

> **RITnet = 用"学习"替代"假设"。** 它把瞳孔检测从一个"手工规则的几何问题"重构成一个"数据驱动的像素分类问题"，并通过 ①边界加权损失保边界、②Dice/Surface 损失抗不平衡、③针对性增强抗反光遮挡，来专门应对眼部分割的真实困难。

这也解释了我实测里的一个现象：**为什么它中心准（中位误差 0.9%）但直径/IoU 有重尾**——它学会了"眼睛结构在哪"（学习先验强），但在反光/遮挡严重的帧上，**边界**（决定直径）会跑偏，而**定位**（决定中心）几乎不受影响。直径精度恰好是你测量的目标，所以这个坑躲不掉。

读完了。DeepVOG 的分析思路和 RITnet **同源（都是"学习式分割"）但走向完全不同**——RITnet 停在"像素分类"，DeepVOG 继续往"3D 几何反投影"走了一层。下面基于你仓库里的实际代码讲。

## 1. 核心思路：从"分割"到"几何"

DeepVOG 的完整管线是**四段式**（你仓库 `inferer.py` 里能完整看到）：

```
视频帧
  │
  ├─① 分割网络（UNet）      → 输出"瞳孔概率图"（每个像素是瞳孔的概率）
  │
  ├─② 椭圆拟合               → 从概率图抠出瞳孔轮廓 → 2D椭圆（中心/长短轴/角度）
  │
  ├─③ 3D眼球模型反投影       ←★ DeepVOG 的灵魂
  │      把2D椭圆反投影到3D，用一个"眼球是球体"的几何先验约束
  │      输出：3D眼中心、眼球半径、瞳孔3D位置
  │
  └─④ 视线角 + 置信度        → gaze_x/y（水平/垂直视线角）+ confidence + consistence
```

**关键差别在③**：RITnet 只做①，拿到椭圆就结束；DeepVOG 把椭圆当成"观测"，再叠一个**几何模型**去校验和精化。这就是"DeepVOG **3D**"里 3D 的含义——指**3D 眼球模型拟合**，不是 3D 卷积。

## 2. 分割网络：UNet + 大卷积核（"看全局的像素分类"）

```python
DeepVOG3D_Net(input_shape=(240, 320, 1), filter_size=(10, 10))
```

- **输入 240×320 灰度**（比你 RITnet 的 640×400 低很多分辨率）；
- 标准 UNet：编码器 16→32→64→128 通道下采样，解码器 256→…→32 上采样 + skip 拼接（`Concatenate`）；
- **标志性设计：10×10 大卷积核**。瞳孔在 240×320 里是很小的结构，大核让每个像素有足够大的感受野、能看到"瞳孔周围的整片眼区"再决定——这是 DeepVOG 原作者特意选的，不是随手参数。

输出通道（3D 版）：`Conv2D(4) + sigmoid` → **4 通道多标签**（每个通道一个结构，比如 pupil/iris/sclera/…），配合 `dice_coef_multilabel(numLabels=4)` 的 Dice 损失。v1 版则是 `3 通道 softmax`，只有 pupil/non-pupil 二分类。

## 3. 3D 眼球模型：把"图像里的椭圆"变成"几何里的椭圆"（最值得讲的一层）

`inferer.py` 里用 `SingleEyeFitter`（`eyefitter.py`），思路是：

```
已知相机参数（焦距 flen、sensor 尺寸、视频分辨率）
  → 建立 mm↔px 换算（mm2px_scaling）
  → 假设眼球是半径为 r 的球体，球心固定
  → 2D瞳孔椭圆 = 球面上的瞳孔圆在相机上的投影
  → 反投影求：瞳孔圆在3D球面上的法向量 = 视线方向
```

为什么这层有价值：

- **几何约束天然抗噪声**：单帧分割有噪声、有误差，但"瞳孔必须落在眼球球面上"这条物理约束能把离谱的椭圆拉回来或直接标记为不可信；
- **得到的是 3D 视线角，不只是 2D 坐标**——这正是 DeepVOG 号称能做 gaze estimation 的原因；
- **有明确的质量机制**：每个椭圆有 `ellipse_confidence`（来自 `CheckEllipse` 椭圆置信度），拟合阶段只收 `confidence > 0.96` 的帧；推理输出还有 `consistence`（与 3D 模型的一致度）。这是 RITnet 完全没有的——RITnet 没有内置置信度。

## 4. 与 RITnet 的本质对比

| 维度           | RITnet                               | DeepVOG                                            |
| -------------- | ------------------------------------ | -------------------------------------------------- |
| 分割类别       | **4类**（背景/巩膜/虹膜/瞳孔） | **二值/多标签**（主要是 pupil vs non-pupil） |
| 输入分辨率     | 640×400                             | 240×320（更低）                                   |
| 网络           | DenseNet-UNet，3×3 卷积，24.9万参数 | 简单 UNet，**10×10 大核**，参数更多         |
| 输出           | 类别图 → 椭圆                       | 概率图 → 椭圆 →**3D 眼球模型 → 视线角**   |
| 内置置信度     | ❌ 无                                | ✅`ellipse_confidence` + `consistence`         |
| 时序           | 单帧                                 | 单帧（但 3D 模型跨帧拟合）                         |
| 直径测量直接性 | 高（虹膜/瞳孔边界都有）              | 低（只有瞳孔，直径从 3D 模型反算）                 |

一句话总结 DeepVOG 的分析思路：

> **DeepVOG = 学习式瞳孔分割 + 几何后验。** 用 UNet 大核在低分辨率下把瞳孔切成概率图，再把椭圆反投影到一个 3D 眼球球体上，用物理几何约束来稳定结果、产出置信度——它是"分割网络 + 几何先验"的组合，而不是纯分割。

# 一、第一阶段：为什么优先 030 BlazeFace、144 YuNet、387 YuNetV2？

## 1. 这三个本质上都是“人脸检测器”

它们的基本输入输出是：

```text
输入：整帧图像
输出：人脸框 + 人脸关键点
```

例如 YuNet 的输出包括：

```text
face_bbox
right_eye
left_eye
nose_tip
right_mouth_corner
left_mouth_corner
confidence
```

OpenCV 的 YuNet 接口明确返回人脸框和 5 个关键点，包括双眼、鼻尖和嘴角。

所以 Gemini 推荐它们的推理是：

```text
1080p 全帧
  ↓
人脸检测
  ↓
得到人脸框/双眼关键点
  ↓
围绕双眼关键点裁出左眼、右眼 ROI
  ↓
交给第二阶段瞳孔算法
```

### 030 BlazeFace

BlazeFace 是 MediaPipe 体系里的轻量人脸检测器，设计目标就是移动端实时人脸区域定位。原论文强调它用于实时人脸检测，并作为后续 2D/3D 面部关键点、面部区域分割等模型的 ROI 提供器。

它的优点是：

- 速度快；
- 模型小；
- 适合视频跟踪；
- 后续可以接 Face Mesh 或 Iris Landmark；
- 适合“先找一个脸，再在脸里做精细分析”。

### 144 YuNet

144 YuNet 是比较早的一版轻量人脸检测模型。PINTO 的目录中注明它的典型输入规格为 `120×160`，并提供 FP32、FP16、INT8 等转换版本。

它的优点是：

- 很轻；
- CPU 运行友好；
- OpenCV 生态集成较好；
- 输出人脸框和五官关键点；
- 适合低算力设备和实时初定位。

### 387 YuNetV2

387 YuNetV2 是更新一代的 YuNet 版本，PINTO 目录中注明典型输入为 `640×640`，同样提供 FP32、FP16、INT8 和 ONNX 等格式。

它通常被推荐作为更稳妥的候选，原因可能是：

- 输入分辨率更高；
- 对较小人脸或复杂尺度更有机会；
- 更新版本通常在检测结构、训练数据或导出方式上更现代；
- 更适合把 1080p 全帧缩放后做统一检测。

但这里要注意：**输入 640×640 不等于它一定能识别你的眼睛特写**。如果图像中根本没有完整人脸，模型面对的仍然是分布外输入。

# 二、为什么不是优先推荐其他算法？

不是说其他模型“不好”，而是它们解决的问题不同。

PINTO 的“4. 2D/3D Face Detection”其实混合了几类模型：

| 类型             | 代表模型                            | 主要输出           | 是否适合直接找眼睛 ROI       |
| ---------------- | ----------------------------------- | ------------------ | ---------------------------- |
| 人脸检测         | BlazeFace、YuNet、RetinaFace、SCRFD | 人脸框、部分关键点 | 间接适合                     |
| 人脸关键点       | Face_Landmark、FaceMesh             | 468/若干面部点     | 需要人脸先被找到             |
| 虹膜关键点       | Iris_Landmark                       | 眼周/虹膜点        | 适合第二阶段                 |
| 头姿态           | Head Pose、WHENet                   | yaw/pitch/roll     | 不能直接给眼睛框             |
| 3D 人脸/头部模型 | SynergyNet、其他 3D 模型            | 3D 面部结构        | 对当前任务偏重               |
| 重型人脸检测     | DSFD、RetinaFace、SCRFD             | 人脸框             | 可能更强，但速度和复杂度更高 |

## 1. 032 FaceMesh 为什么不作为第一优先？

Face Mesh 可以输出 468 个三维面部关键点，开启 refine landmarks 后还能增强眼睛、嘴唇和虹膜附近的点。Google 的官方流程是：

```text
BlazeFace 人脸检测
  ↓
Face Mesh 人脸关键点
  ↓
从面部网格中提取眼睛区域
```

MediaPipe 官方文档也明确说，Face Mesh 的输入是裁剪后的人脸图像，并且内部依赖人脸检测；视频中后续帧还能利用跟踪减少重复检测。

所以 Face Mesh 不是最初的“全帧找眼睛”模型，而是：

```text
先有一个可用的人脸 ROI
再在人脸 ROI 内做高密度关键点
```

如果你的视频只有眼睛、鼻梁和部分脸，Face Mesh 可能没有足够的完整脸结构来稳定工作。这正是你们之前 MediaPipe 在正式特写上 0/60 的可能原因之一。

## 2. 043 Face_Landmark 为什么不是优先？

它和 Face Mesh 一样，更像：

```text
已知有一张脸
→ 预测脸上的关键点
```

不是专门的局部眼睛检测器。

对于你的正式视频，如果是完整脸，它可以试；如果是鼻梁+双眼特写，它不一定比专门的“眼睛框检测器”有优势。

## 3. RetinaFace、SCRFD、DSFD 为什么不是第一选择？

这些模型可能比 BlazeFace/YuNet 更强，尤其在：

- 小人脸；
- 多人脸；
- 遮挡；
- 复杂姿态；
- 低质量图像；

方面可能更有优势。

但它们的缺点是：

- 通常更重；
- 部署复杂度更高；
- 仍然输出“脸框”，不是“眼框”；
- 解决的是人脸检测，不是眼睛局部检测；
- 不一定适合纯 940nm NIR；
- 可能需要更多显存或更长推理时间。

因此 Gemini 把它们放到后面，应该是基于“先用轻量模型快速试”的工程排序，而不是说它们理论上不推荐。

# 三、对你这个项目，第一阶段真正应该怎么分层？

我认为不能只做一条路线，而应该分三类测试：

## 路线 A：完整人脸检测器

适用于预实验或未来完整人脸画面：

```text
BlazeFace / YuNet / YuNetV2
→ 人脸框
→ 关键点中的双眼位置
→ 扩展成单眼 ROI
```

候选顺序可以是：

```text
387 YuNetV2
→ 144 YuNet
→ BlazeFace
```

但需要在你的 NIR 数据上实测，而不是凭名称决定。

## 路线 B：直接眼睛局部检测器

适用于你的正式“双眼/鼻梁特写”：

```text
全帧
→ 直接检测 left_eye / right_eye
→ 单眼 ROI
→ 瞳孔算法
```

你找到的 `yolo-face-parts-detector` 反而更接近这条路线。

它的 README 明确说明，这个项目不是检测完整人脸，而是直接检测脸部部位，目标包括：

- eyes；
- mouth；
- nose；
- eyebrows。

作者特别强调，它就是为了处理：

- close-up images；
- heavily occluded faces；
- 不包含完整人脸的图像。

它使用 YOLOv8，把已有的人脸关键点标注转换成眼睛、鼻子、嘴巴等部位的 bounding box。

这和 MediaPipe Face Mesh 的设计方向不同：

```text
Face Mesh：
需要脸 → 推算脸部关键点

YOLO face-parts：
直接学“眼睛这个局部区域在哪里”
```

对于你的正式特写画面，这个方向理论上更匹配。

不过它也有两个重要风险：

1. 它主要在普通 RGB 人脸图像上训练，不是 940nm NIR；
2. 作者自己也说，眼睛、嘴巴和鼻子效果较好，但需要更多近距离、遮挡样本来增强泛化。

所以它不是“直接可用”，而是**比完整人脸检测器更值得优先验证的 ROI 候选**。

# 四、第二阶段：049 Iris_Landmark 到底是什么？

049 Iris_Landmark 的本质不是瞳孔分割器，而是：

> **眼部关键点回归模型。**

它的流程是：

```text
眼睛 ROI
  ↓
Iris Landmark 网络
  ↓
输出眼睑轮廓点 + 虹膜/眼睛关键点
  ↓
根据点的位置估计虹膜中心、大小、眼睛开合
```

MediaPipe Iris 官方流程是：

```text
BlazeFace
  ↓
Face Mesh
  ↓
提取眼睛 patch
  ↓
Iris Landmark 模型
```

它最终输出 478 个三维关键点，其中：

- 468 个来自 Face Mesh；
- 10 个是新增的虹膜关键点；
- 每只眼睛 5 个虹膜点。

官方还明确说明，Iris Landmark 模型的输入是眼睛图像 patch，输出包括眼睑区域和虹膜区域的关键点。

# 五、049 Iris_Landmark 和 RITnet 的区别

这是最容易混淆的地方。

## RITnet：像素分割

```text
眼睛图像
  ↓
每个像素分类
  ↓
瞳孔区域 mask
  ↓
椭圆拟合
  ↓
瞳孔中心、长短轴、直径
```

RITnet 直接回答：

> 哪些像素属于瞳孔？

因此它对你的核心指标“瞳孔直径/面积”在形式上更直接。

## Iris_Landmark：关键点定位

```text
眼睛图像
  ↓
预测若干关键点
  ↓
根据关键点拟合圆/椭圆
  ↓
虹膜中心、虹膜边界、眼睛轮廓
```

它回答的是：

> 虹膜边界和眼睛结构上的几个重要点在哪里？

它不直接输出瞳孔的完整像素 mask。

因此：

| 方面             | Iris_Landmark          | RITnet                     |
| ---------------- | ---------------------- | -------------------------- |
| 输出             | 少量关键点             | 每像素类别 mask            |
| 直接检测对象     | 虹膜/眼周结构          | 瞳孔、虹膜、巩膜           |
| 直径测量         | 由关键点间接估计       | 由瞳孔 mask 直接估计       |
| 对边界遮挡       | 可能依赖关键点是否稳定 | 依赖整块分割是否完整       |
| 速度             | 通常很快               | 中等                       |
| 可解释性         | 点位置直观             | mask 更完整                |
| 适合实时         | 很适合                 | 需要优化                   |
| 是否原生支持 NIR | 主要面向 RGB           | OpenEDS NIR 训练背景更匹配 |

# 六、049 Iris_Landmark 和我们之前算法的区别

## 1. 和 pupil-detectors 的区别

`pupil-detectors` 更像一个传统算法集合/调用框架，其中可能包含多种基于图像几何的瞳孔检测方法。

典型思路：

```text
灰度/对比度
→ 找暗区域或边缘
→ 轮廓/射线/阈值
→ 椭圆拟合
```

优点：

- 不需要神经网络；
- CPU 运行；
- 对 NIR 画面有传统经验；
- 结果直接是瞳孔椭圆；
- 参数透明。

缺点：

- 很依赖“瞳孔是暗色、边界连续”的假设；
- 对眼镜反光、睫毛遮挡、过曝、阴影敏感；
- 会出现中心漂移、椭圆拟合到眼睑或反光区域的问题。

049 Iris_Landmark 则是：

```text
学习眼睛结构
→ 预测关键点
```

两者不是同一类方法。

## 2. 和 PuRe / PuReST 的区别

PuRe/PuReST 属于经典瞳孔检测路线，输出通常是：

```text
瞳孔椭圆
中心
长短轴
角度
置信度/连续性
```

其中 PuReST 增加了时序连续性或序列恢复能力，适合视频。

它们和 Iris_Landmark 的区别是：

|                         | PuRe/PuReST      | Iris_Landmark                                        |
| ----------------------- | ---------------- | ---------------------------------------------------- |
| 方法                    | 传统图像分析     | 深度学习关键点                                       |
| 输出                    | 瞳孔椭圆         | 虹膜/眼睑关键点                                      |
| 是否直接测瞳孔          | 是               | 不完全是                                             |
| 是否依赖训练数据        | 低               | 高                                                   |
| 是否需要 RGB/NIR 域匹配 | 主要依赖图像质量 | 很依赖训练域                                         |
| 时序能力                | PuReST 有        | 原始 landmark 模型主要是逐帧，视频跟踪由外层框架提供 |

对你的任务，PuRe/PuReST 的优点是“目标就是瞳孔”，而 Iris_Landmark 的优点是“对眼睛结构有更强的学习先验”。

## 3. 和 RITnet 的区别

RITnet 是：

```text
眼睛 ROI → 4 类语义分割 → 瞳孔 mask → 椭圆
```

它对瞳孔直径测量更直接。

我们之前在预实验的已裁剪 NIR ROI 上测试得到：

- 中心中位误差很小；
- 但整体端到端可用率只有约 45.3%；
- 不可见眼存在伪阳性；
- 不同被试表现差异明显。

所以 RITnet 的问题不是完全不会定位，而是边界和失败帧的长尾比较严重。

## 4. 和 DeepVOG 的区别

DeepVOG 也是学习式分割，但后面加了一层几何模型：

```text
眼睛图像
  ↓
神经网络分割瞳孔
  ↓
椭圆拟合
  ↓
3D 眼球模型/视线几何
  ↓
置信度和 gaze 相关结果
```

因此 DeepVOG 更像：

```text
分割网络 + 3D 眼球几何约束
```

而 RITnet 更像：

```text
多类别分割网络 + 2D 椭圆拟合
```

对你的目标“瞳孔直径时间序列”来说，DeepVOG 的 3D 眼球模型未必天然更有优势，因为：

- 需要相机焦距、传感器尺寸等参数；
- 更偏向 gaze estimation；
- 3D 眼球拟合可能引入额外模型误差；
- 原仓库依赖旧版 TensorFlow/Keras；
- 还没有在你的 528 眼上实际验证。

# 七、为什么 Gemini 会推荐 049 Iris_Landmark？

我认为它的推荐逻辑是：

```text
第一阶段：
找到脸/眼睛 ROI

第二阶段：
用 Iris Landmark 直接得到眼周和虹膜结构关键点

第三阶段：
由虹膜/瞳孔相关点估计中心和大小
```

推荐 049 的主要原因应该是：

1. 它本身就是眼睛/虹膜专用模型；
2. 输入是眼部 patch，不需要再处理完整脸；
3. 速度快，适合 30fps；
4. 输出点比传统阈值算法更稳定；
5. 可以同时给出眼睑轮廓和虹膜结构；
6. 在眼睛 ROI 已经准确的前提下，工程链路简单。

但是不能把它理解为：

> 049 一定比 RITnet、PuReST、DeepVOG 更适合测瞳孔直径。

更准确的说法是：

> 049 是一个非常值得测试的“眼部关键点路线”，和 RITnet 的“像素分割路线”、PuReST 的“经典椭圆检测路线”、DeepVOG 的“分割+几何路线”互补。

# 八、对你的 940nm NIR 数据，049 最大的风险

MediaPipe Iris 的官方目标是**单 RGB 摄像头实时虹膜跟踪**。官方文档还说明它使用 Face Mesh、眼部 patch 和虹膜 landmark 模型完成处理。

你的输入却是：

- 940nm 窄带；
- 红外补光；
- 黑白/NIR 成像；
- 可能有镜片反光；
- 低开睑；
- 仰拍；
- 约 30cm；
- 眼睛局部特写。

这存在明显域差：

```text
MediaPipe Iris 训练/设计：
RGB、自然肤色、普通光照

你的数据：
940nm NIR、单色、补光、反射、眼镜、局部特写
```

所以 049 可能出现两种结果：

### 可能的优势

- 关键点模型依赖形状，不完全依赖颜色；
- 对部分遮挡可能比简单阈值法稳；
- 输出少量点，后处理简单；
- 速度快。

### 可能的失败

- 把虹膜边界当成瞳孔边界；
- 在 NIR 反光处产生错误关键点；
- 眼睛过窄时关键点塌缩；
- 输入 ROI 风格与 MediaPipe 预期不一致；
- 只输出几个点，无法知道完整边界是否被遮挡；
- 高置信度错误点仍然可能发生。

因此，049 不能直接作为“瞳孔真值替代品”，必须和人工椭圆真值比较。

### 对完整人脸视频

## 第二阶段：眼内测量

建议并行保留四条路线：

```text
A. PuReST
   经典瞳孔椭圆路线，直接测瞳孔，适合视频

B. RITnet
   NIR 语义分割路线，直接输出瞳孔 mask

C. DeepVOG
   分割 + 几何/时序路线，但部署复杂

D. Iris_Landmark
   眼部关键点路线，速度快，但目标更偏虹膜/眼周结构
```

它们不是简单的“谁替代谁”，而是测量机制不同：

```text
PuReST       直接找瞳孔椭圆
RITnet       分割瞳孔区域
DeepVOG      分割后加眼球几何约束
IrisLandmark 预测眼睛/虹膜关键点
```

## 1. 它和我们之前试过的 MediaPipe/YuNet 有什么不同？

这个项目的目标不是：

```text
先找到完整人脸
→ 再预测人脸关键点
→ 再从关键点推算眼睛位置
```

而是：

```text
整帧图像
→ YOLOv8 直接检测眼睛、鼻子、嘴巴、眉毛等脸部部位
→ 输出每个部位的 bounding box
```

作者明确区分了“检测完整人脸”和“检测脸部部位”，并说明这个项目就是为近距离、遮挡、缺少完整人脸的图像设计的。它将不同人脸关键点数据集中的眼睛、嘴巴、鼻子等关键点转换成 YOLO 格式的部位框进行训练。

这和我们之前遇到的问题非常对应：

```text
正式视频：
只有双眼、鼻梁和部分脸

MediaPipe/YuNet：
想找一个完整的人脸
→ 失败

YOLO face-parts：
直接找眼睛区域
→ 理论上更匹配
```

## 2. 它实际输出什么？

从上游的 `run.py` 看，它做的是：

```text
YOLOv8 推理
→ 读取每个检测框
→ 根据 model.names 转换类别名
→ 保存 image_name、detection、x1、y1、x2、y2
```

也就是说，它输出的是：

```text
类别 + 矩形框
```

很可能包括：

```text
eye
mouth
nose
eyebrow
hair
```

但它不是：

- 眼睛轮廓分割；
- 瞳孔检测；
- 虹膜关键点；
- 眼球椭圆；
- 眼睛 3D 姿态。

所以它只能解决第一阶段：

```text
1080p 全帧
→ 找到左眼框和右眼框
→ 扩展眼框
→ 裁剪成单眼 ROI
→ 交给 PuReST/RITnet/DeepVOG/Iris Landmark
```

它不替代第二阶段的瞳孔分析。

## 3. 为什么它比 030 BlazeFace / YuNet 更值得试正式视频？

因为它的训练目标不同。

### BlazeFace/YuNet

目标是：

```text
检测 face
```

输出：

```text
人脸框 + 人脸关键点
```

它们假设图像中存在“脸”这个整体结构。YuNet 还会输出双眼、鼻尖、嘴角等关键点，但前提仍然是先成功检测到一个 face。

### YOLO face-parts detector

目标是：

```text
检测 eye
```

输出：

```text
眼睛矩形框
```

它不要求画面里必须有完整脸，至少从项目设计目标看，专门考虑了：

- close-up；
- profile；
- partial face；
- occlusion；
- missing face parts。

作者也明确说，传统人脸关键点方法在近距离或脸部严重缺失时效果不好，而这个项目就是针对这种情况开发的。

因此对于你的正式视频：

```text
双眼/鼻梁特写
```

它的任务定义比 MediaPipe Face Mesh、BlazeFace、YuNet 更接近。

## 4. 但它有一个很大的风险：它可能是 RGB 模型，不是 NIR 模型

这是目前不能忽略的问题。

上游项目训练数据来自：

- Helen；
- Menpo2D；
- AFW；
- LaPa；
- FASSEG；
- Pexels。

这些都是普通可见光人脸数据，不是 940nm NIR 数据。

因此它在你的 NIR 上存在明显域差：

```text
训练：
RGB、肤色、自然光照

你的输入：
940nm 窄带、黑白、红外补光、眼镜反光、仰拍
```

这可能导致：

- 眼睛框检不出来；
- 把眼睑/眉毛/鼻梁当成眼睛；
- 左右眼框混淆；
- 框过窄，只包住眼球；
- 框过宽，把鼻梁和眼镜一起包进去；
- 置信度不稳定。

所以它的优势是“任务定义更匹配”，但不代表“对你的 NIR 已经可靠”。

## 5. 它的训练数据和“你的眼睛 ROI”还有一个尺度问题

上游仓库的目标是脸部部位检测，不是专门的眼动仪 ROI 生成。

它输出的眼睛框可能只是：

```text
包含眼睛大致位置的 box
```

而我们的第二阶段需要的 ROI 更严格：

```text
必须包住完整瞳孔
最好保留眼睑、虹膜和少量周围上下文
不能裁掉上下边界
不能混入过多鼻梁/眉毛/眼镜
```

因此即使 YOLO 框检测正确，也不能直接把框原样交给 RITnet。我们还需要做一个扩展策略，例如：

```text
检测框
→ 左右扩展 20%～40%
→ 上下扩展 30%～60%
→ 限制在图像边界内
→ 统一 resize 到第二阶段输入尺寸
```

这个扩展比例要在人工真值上校准。

## 6. 上游项目本身的能力边界

上游作者报告说：

- 对眼睛、嘴巴、鼻子的检测效果较好；
- 对眉毛相对较弱；
- 希望继续增加更多近距离和遮挡样本；
- 数据中还存在多脸但标注不完整等噪声问题。

这说明它不是一个经过严格医学/眼动测量验证的 ROI 模型，而是一个比较实用的实验性 YOLOv8 face-parts detector。

对我们来说，它最合理的定位是：

> 一个值得在 NIR 数据上做 ROI 入围测试的候选，不是已经验证通过的生产模型。
