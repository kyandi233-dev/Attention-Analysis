# NIR正式管线审计工作记录

> 08-16（Asia/Shanghai）｜本记录只整理三个Luna审计结论与当前决策，不运行正式数据，不修改代码。

## 总结

当前NIR管线可以继续作为研究开发基础，但不能标记为“正式生产链已定稿”。PuReST仍是生产候选；阶段4/4b的部分质量结论受椭圆轴与角度标准化错误影响，需要独立复核；阶段5只保留为历史连续性证据，不作为正式准确率或参数定稿依据；正式实验ROI尚未选择。

当前正式采集条件已记录为新的数据域：NIR相机距被试约30 cm，位于近桌面向上拍摄；补光灯与摄像头水平距离约60 cm、高度约63 cm，并向下照射人脸，以减少眼镜正面镜面反光。这个条件可能使瞳孔更大、更清晰，但仍需检查仰拍透视、眼睑遮挡、左右眼照明不对称和镜片局部亮斑。

## 1. 审计范围与停止点

本轮只做文档、源码逻辑和运行环境审计结论整理；没有读取 `E:\正式实验`，没有运行正式视频，也没有修改代码。

审计覆盖三条证据链：

1. 项目总览、配置、已有阶段产物与当前代码是否一致；
2. PuRe/PuReST论文、C++实现、Python绑定与v2外层状态机是否一致；
3. 模型、Python环境、动态库、wheel和绝对路径是否足以支持迁移。

本记录对应的审计监督结论来自三个Luna任务。Luna结果作为审计输入，由主任务合并，不把“子任务完成”直接等同于“管线通过”。

## 2. 用户提问—回答—证据—决策

### 2.1 PuReST是否已经可以定稿？

**用户提问**：当前PuRe/PuReST是不是最好的，能否直接定稿？

**回答**：PuReST仍是最有希望的连续检测候选，但目前不能定稿为正式生产算法。核心C++逻辑基本符合论文设计，v2外层适配仍有轴角度、px参数语义、失败行、插值和状态可观测性问题。

**证据**：

- PuReST源码包含上一帧状态、局部追踪和失败后的PuRe重检逻辑；
- 本机PyPupilEXT绑定的首帧和追踪阶段并不能保证用户传入的`minPx/maxPx`全程严格生效；
- 当前测试没有覆盖首帧、reset、px边界、失败恢复和左右眼状态隔离；
- 现有阶段5结果只说明连续序列表现有优势，不能证明正式条件下的准确率。

**决策**：PuReST标记为“生产候选”；PuRe保留为抽样质控和诊断对照；在专项修复和正式条件验证前，不写成已冻结算法。

### 2.2 阶段4/4b的结果是否可以直接使用？

**用户提问**：六算法单帧基准和参数调优结果是否已经可信？

**回答**：返回率等不依赖椭圆绘制方向的指标可以作为历史参考；涉及椭圆mask、光度对比、IoU、叠加图和几何解释的指标必须复核。

**证据**：

- v2将`size`的两个轴排序为`major/minor`，但没有同步把`angle`旋转90度；
- 合成椭圆复现中，正确表示的IoU约为1.0，当前“排序轴＋原角度”约为0.49；
- 因此阶段4/4b中部分质量判断可能不是算法本身造成，而是外层椭圆表示错误造成。

**决策**：不覆盖历史结果；修复后单独生成轴角度复核结果，并在总览中把阶段4/4b标为“部分指标待复核”。

### 2.3 阶段5结果应该如何解释？

**用户提问**：阶段5的恢复速度、连续性和门控结果能否作为正式依据？

**回答**：阶段5保留为历史连续性证据，不能直接作为正式准确率、正式px参数或生产阈值的证明。

**证据**：

- 阶段5使用了预实验序列和EAR/openness代理标签；
- 代理标签只能说明眼睛开合状态，不能提供瞳孔椭圆真值；
- 插值与缺失状态的实现还需要严格检查是否跨越闭眼、无脸或ROI失败；
- PuReST在绑定层存在px参数语义限制。

**决策**：保留历史覆盖率、跳变和恢复速度数字及其原始产物；不据此冻结正式生产阈值，不把它写成正式准确率验证。

### 2.4 正式实验条件是否与预实验相同？

**用户提问**：正式实验的NIR位置和补光方式改变后，原结论能否直接迁移？

**回答**：不能直接视为同一数据域。正式条件更接近近距离眼部采集，瞳孔可能更大、更清晰，但仰拍和补光几何会引入新的遮挡、透视和反光模式。

**证据**：用户给出的正式条件是相机约30 cm、近桌面向上拍；补光灯水平离相机约60 cm、高约63 cm，向下照射人脸。该几何与预实验不同。

**决策**：正式ROI必须在正式数据上重新比较；预实验的`minPx/maxPx`、ROI尺度、覆盖率和恢复结果不能直接复用为正式定稿参数。

### 2.5 是否已经选定ROI？

**用户提问**：MediaPipe、YuNet、YOLO中哪一个进入生产？

**回答**：尚未选定。MediaPipe目前同时承担ROI和EAR/openness；YuNet提供人脸框与五点；当前YOLO模型只有人脸框，眼区靠比例估计，不能写成完整眼部关键点模型。

**证据**：模型输出和现有脚本职责审计显示，YuNet/YOLO与MediaPipe的输出能力不同，且现有ROI脚本还有坐标、失败行、输出目录和配置一致性问题。

**决策**：先修复比较工具和记录契约，再用正式条件的Block 1连续片段比较；在比较完成前不复制或冻结最终ROI模型。

## 3. 严重问题清单

| 严重度 | 问题 | 影响 | 当前决策 |
|---|---|---|---|
| 严重 | 椭圆轴排序后没有同步修正角度 | 椭圆叠加、IoU、mask和光度评价可能错误 | 必须先修复并复核阶段4/4b |
| 严重 | PuReST首帧和追踪阶段不保证严格使用用户px上下限 | 不能把`px_min/px_max`解释成全程硬约束 | Python层增加后置px接受门并记录语义 |
| 严重 | 坏帧、图像读取失败或算法异常可能丢失结果行或中断序列 | 分母、恢复速度和缺失类型不可信 | 每个帧×眼别保留失败记录，逐帧隔离异常 |
| 严重 | 插值屏障不足 | 可能跨闭眼、无脸、ROI失败或真实缺帧补值 | 只允许满足可见、连续、有限时间和端点约束的缺口 |
| 严重 | ROI比较后端可能重复缩放YuNet关键点 | YuNet眼区位置可能错误，质量结果无效 | 先核对输出坐标并补范围测试 |
| 重要 | 三种ROI默认输出可能互相覆盖 | 比较结果不可追溯 | 后端独立目录和唯一运行标识 |
| 重要 | ROI脚本绕过主配置并写死模型/输出路径 | 迁移和复现容易使用不同参数 | 统一配置来源 |
| 重要 | 连续视频可能每帧重新打开、seek和关闭 | 速度测量被I/O方式污染 | 使用连续FrameReader |
| 重要 | `evaluate_tuned()`/报告函数存在未定义`force` | 调优评估可能直接运行失败 | 修复后再复核历史结果 |
| 重要 | 门控校准仍引用旧目录/配置键 | 阶段5校准无法稳定重现 | 统一真值目录与配置 |
| 重要 | 当前无法观察PuReST内部tracker与PuRe fallback的具体来源 | 不能把所有PuReST输出解释成同一种模式 | 只记录外层可观察状态，不猜测内部状态 |
| 一般 | 测试覆盖不足且有测试夹具缺少`sequence_id` | 关键状态和序列边界没有回归保障 | 补测试并修正夹具 |

## 4. 当前算法链的逻辑判断

当前实际候选链可概括为：

```text
视频与时间戳
→ MediaPipe或候选ROI后端
→ 统一眼部ROI
→ EAR/openness门控
→ PuReST连续检测
→ 几何/光度/轮廓/px后置质量门
→ 原始观测与拒绝状态
→ 独立插值副轨
→ QC与报告
```

其中必须区分：

- `valid(0.0)`只表示绑定层认为存在有效几何和正置信度，不等于人工确认正确；
- `confidence`和`outline_confidence`不是同一个量，不能直接把`outline_confidence>=0.5`称为论文置信度阈值；
- PuReST内部已有追踪和PuRe重检，但绑定未暴露内部来源，外层不能虚构`tracking/fallback`标签；
- 眼睑门控只能表示开合状态，不是瞳孔椭圆真值；
- 插值是派生数据，不能覆盖原始观测，也不能用于准确率评价。

## 5. 环境与模型风险

当前运行链依赖两个环境：主环境负责视频、MediaPipe、ROI、EAR和评估；Python 3.10的`venv-pupil`负责PyPupilEXT/PuRe/PuReST。PuRe/PuReST没有外部权重，但依赖编译后的`.pyd`和其运行库。

已确认的迁移风险：

- `face_landmarker.task`、YuNet和YOLO模型目前在v2仓库外；
- PyPupilEXT wheel在旧v1目录外，不能只迁移v2目录就重建瞳孔环境；
- 主环境存在多个OpenCV发行版并存风险；
- 配置、ROI脚本和历史路径仍有绝对路径/旧目录引用；
- 当前没有真正统一的单命令生产入口；
- YOLO当前模型只输出人脸框，眼区为比例估计；
- DeepVOG、RITnet、Torch不是当前实际NIR运行时依赖。

决策：等ROI和门控链定稿后，在v2内建立`models/`和`runtime/`。`models/`放完整生产链实际用到的模型，其中ROI候选只复制最终选中的ROI模型；`runtime/`保存双环境依赖和PyPupilEXT wheel。当前不修改环境、不复制模型。

## 6. 停止门

### 停止门A：代码进入历史复核前

- 椭圆轴角度标准化有合成图IoU测试；
- PuReST的px语义、首帧、reset和后置门记录清楚；
- 每个输入帧×眼别都有成功或失败行；
- 异常帧不终止整段序列；
- 插值不跨闭眼、无脸、ROI失败、序列边界或NaN时间戳；
- ROI比较不覆盖结果，且三种后端使用同一帧和同一schema；
- 历史阶段4/4b受影响指标已被单独标记。

### 停止门B：正式ROI比较前

- 正式条件和Block 1时间范围可以由时间轴定位；
- ROI脚本从统一配置读取模型和输出；
- YuNet坐标、YOLO输出和MediaPipe复用方式有测试；
- 速度统计区分加载、稳态推理和端到端耗时；
- 输出包含源图仿射映射和失败原因。

### 停止门C：生产定稿前

- 正式条件下完成ROI质量和速度比较；
- 正式眼图重新确定瞳孔px范围；
- PuReST连续检测和门控结果经人工抽样检查；
- 模型、wheel、环境和配置可以迁移；
- 只有达到质量门槛才冻结ROI和生产链；否则报告“暂无合格方案”。

## 7. 当前结论与下一步

当前结论：

1. PuReST是候选，不是定稿；
2. 阶段4/4b的轴角度相关质量指标需要复核；
3. 阶段5只保留历史连续性证据；
4. 正式数据属于新的近距离仰拍NIR条件；
5. ROI尚未选择；
6. 在停止门A满足前不运行正式视频。

本记录只描述审计结果和决策，不构成代码已修复或正式数据已分析的声明。
