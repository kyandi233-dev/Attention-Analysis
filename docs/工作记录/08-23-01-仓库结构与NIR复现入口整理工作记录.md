# 08-23-01｜仓库结构与 NIR 复现入口整理工作记录

> 2026-08-23｜正式 NIR 全量分析已经完成。本轮不重新运行正式数据，不删除历史文件；目标是整理仓库当前状态、核验 YOLO/tracking/RITnet 的真实代码与模型血缘，并修正文档中仍停留在候选/准备阶段的入口说明。

## 一、本轮边界

本轮遵循以下约束：

- 不删除任何已有文件；涉及删除必须另行取得用户明确同意。
- 不批量改写历史工作记录正文。
- 可以更新当前入口、目录索引、架构说明和明显错误/过时的路径描述。
- frozen runtime package 本体不直接改写，避免破坏 ZIP / SHA256 一致性。
- 不根据聊天记忆或默认配置臆造正式 full-run 最终参数；优先核验仓库实体。

## 二、关键核验结果

### 1. YOLO26n 正式训练资产

正式训练目录确认为：

```text
yolotrain/runs/yolo26n_eye_100epoch/
```

最终权重真实路径为：

```text
yolotrain/runs/yolo26n_eye_100epoch/weights/best.pt
```

而不是顶层 `yolotrain/weights/best.pt`。

正式 run 的 `args.yaml` 记录 YOLO26n、100 epochs、imgsz=640、batch=16、CPU、workers=0、seed=0、deterministic=true。第 100 epoch validation 记录 precision=0.99922、recall=1.00000、mAP50=0.99500、mAP50-95=0.71810。

### 2. 冻结 held-out test

2026-08-22 工作记录明确记载 test 已真实执行：7 名被试、85 张图、169 个 eye boxes。Ultralytics 原生 test 指标为 precision=0.9754、recall=0.9645、mAP50=0.9913、mAP50-95=0.6589。

当时机器可读评价产物曾保存于：

```text
artifacts/yolo-eye-evaluation/yolo26n_eye_100epoch/
```

包括 `overall_metrics.json/csv`、`per_image_predictions.csv`、`per_subject_metrics.csv`、`failure_index.csv`、`native_test/` 和 `run_manifest.json` 等。但当前分支的 `artifacts/` 实际只剩 `README.md`，因此这是一个“历史上生成过、当前 Git 路径未保留”的 provenance 缺口。

### 3. 完整 YOLO + tracking + RITnet 实现位置

已核验完整 portable 实现位于：

```text
runtime/nir-yolo-tracking-ritnet-v1/run_pipeline.py
```

该脚本并非只能处理短视频：默认 60 秒是 package 创建时的准入保护，显式 `--full-video` 可以处理整段视频。

实现包括：

- YOLO26n eye bbox；
- `none` / CSRT / KCF；
- 周期重新检测；
- tracker 失败、非法 bbox、中心异常跳变时立即回退 YOLO；
- bbox 扩展与 320×160 单眼 ROI；
- RITnet；
- `frames.csv` / `eyes.csv`；
- overlays；
- `summary.json`；
- `run_manifest.json`；
- 模型 SHA256 与环境记录。

### 4. YOLO 模型血缘

runtime 中：

```text
runtime/nir-yolo-tracking-ritnet-v1/models/nir-eye-yolo26n-best.pt
```

与训练目录：

```text
yolotrain/runs/yolo26n_eye_100epoch/weights/best.pt
```

Git blob SHA 均为：

```text

```

文件大小也同为 5,403,247 bytes。因此两者是逐字节同一权重。

### 5. RITnet 模型血缘

runtime 中：

```text
runtime/nir-yolo-tracking-ritnet-v1/models/ritnet-best_model.pkl
```

与：

```text
models/RITnet-master/best_model.pkl
```

Git blob SHA 均为：

```text
f0864e6651f578525a9101c7ca787e23d2d201d7
```

因此 portable runtime 同时冻结了正式 YOLO 权重和当前 RITnet 权重。

### 6. RITnet runtime 实际逻辑

`ritnet_runtime.py` 读取 320×160 灰度 ROI，再缩放到 package 配置的 640×400 网络输入；执行 gamma=0.8、CLAHE、归一化后进入 DenseNet2D。类别 3 被解释为 pupil mask，最大轮廓通过最小点数/面积后使用 `fitEllipse()`，输出中心、两轴、角度、mask area、等效直径与 pupil confidence。

package 当时 `pupil_confidence_min=null`，即输出 confidence 但未把它作为 production 拒绝阈值。

### 7. final full-run provenance 仍未闭合

当前仓库可以确认：

- 正式 NIR 全量已经完成；
- 完整实现在哪里；
- 两个模型的精确身份；
- portable package 的代码和默认配置。

但当前分支没有找到正式全量运行最终生成的 `run_manifest.json` / `summary.json` / 全量输出目录，也没有 2026-08-22 之后的 committed NIR 工作记录。因此不能把 package 默认的：

```text
CSRT
redetect_interval=10
horizontal expansion=0.30
vertical expansion=0.45
```

自动写成正式 full-run 最终冻结参数。

当前结论是“分析已完成，但仓库缺 final-run 轻量复现证据”，而不是“正式分析尚未开始”。

## 三、源码与目录边界整理

### `src/attention_pipeline/`

核验后不进行强制搬移。

- `behavior/`：早期 behavior evidence / compatibility 层，旧 CLI 仍依赖。
- `behavior_formal/`：后续正式 BBB SART 分析层，包含 extract / metrics / stats / figures / report。
- `nir/`：ROI 几何、时间轴以及历史 review / benchmark / sequence 实现。
- `cli.py`：旧统一 CLI，主要连接早期 behavior 和 NIR review/benchmark/sequence；不是后来 portable YOLO + tracking + RITnet full-run 入口。

`behavior/` 与 `behavior_formal/` 没有因为名字相近而合并，因为二者职责和数据口径不同。

### `models/`

未移动任何模型。历史 `configs/formal.yaml` 仍直接引用多个现有模型路径，强拆 `trained/pretrained/external` 会破坏历史复现路径。因此只新增角色说明，不做物理重排。

### `runtime/`

新增外层 `runtime/README.md` 解释当前状态，但不修改 `nir-yolo-tracking-ritnet-v1/` 内部 frozen 文件，从而保持 package ZIP / SHA256 的历史一致性。
