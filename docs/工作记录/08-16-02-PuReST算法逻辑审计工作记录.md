## 2. 用户提问—回答—证据—决策

### 2.1 “PuReST专项审计”是否只检查API细节？

**用户提问**：专项审计还要检查整个代码逻辑，参考网络说明、教程、源代码example，而不是只检查细节。

**回答**：审计范围扩展为“论文设计—源码执行—绑定语义—v2状态机—正式数据假设”五层对照。

**证据**：仅确认`runWithConfidence()`和`valid(0.0)`无法判断追踪状态、fallback、ROI尺度和失败恢复是否符合原算法；C++源码显示PuReST内部有previous pupil、局部追踪和PuRe重检。

**决策**：PuReST不以“API调用成功”作为通过条件，必须先完成逻辑级审计和合成序列回归。

### 2.2 当前PuRe/PuReST代码是否完全错误？

**用户提问**：当前PuReST代码质量和整个调用逻辑是否可靠？

**回答**：核心调用方向基本正确，但外层实现存在会影响结果解释和生产可靠性的高严重度问题。

**证据**：v2使用了`runWithConfidence()`、读取`outline_confidence`、调用`valid(0.0)`并维护连续实例；但合成图发现轴角度表示错误，源码对照发现PuReST的px参数不能全程按用户理解生效，序列坏帧会丢行，插值屏障不足。

**决策**：不推翻PyPupilEXT核心算法；修复v2适配层，保留PuReST作为候选，并重新复核受影响历史指标。

### 2.3 `minPx/maxPx`是否是PuReST全程硬约束？

**用户提问**：正式数据瞳孔变大，能否直接把`minPx/maxPx`作为PuReST的像素范围？

**回答**：不能直接这样描述。PuRe每帧的px重载行为较清楚；PuReST首帧和追踪阶段存在绑定层限制。

**证据**：源码对照确认：首帧会进入PuRe逻辑并绕过用户px；追踪时用户`minPx`不按预期使用，`maxPx`被复用；失锁重检也不能简单解释成严格px搜索。`minPupilDiameterMM=0.5`只能作为首帧兼容设置。

**决策**：算法内部使用宽松搜索；Python外层对输出执行严格px后置门，超界记录为`diameter_rejected`；报告中分开写“内部搜索参数”和“生产接受范围”。

### 2.4 椭圆轴和角度是否可以先排序再直接画？

**用户提问**：瞳孔不是圆的，长短轴和角度怎么统一？

**回答**：可以建立canonical的major/minor表示，但交换轴时必须同步旋转角度90度；否则会得到方向错误的椭圆。

**证据**：PyPupilEXT示例保留原始`size`轴顺序与原始`angle`；v2排序后没有同步修角；合成椭圆正确IoU约1.0，错误组合约0.49。

**决策**：输出同时保留原始轴顺序和canonical字段；所有绘图、mask、IoU和光度评价优先依据一致的轴角度表示。

### 2.5 PuReST内部能否标注为tracker或PuRe fallback？

**用户提问**：连续追踪时间线能否区分PuReST追踪与PuRe重检？

**回答**：当前Python绑定没有暴露足够状态，不能从结果反推内部机制。

**证据**：源码有局部追踪、outline tracker和失败后PuRe重检；绑定输出主要是Pupil字段，没有内部路径标志。

**决策**：普通输出只记录外层可观察状态，例如`first_after_reset`、`continuing_session`、`algorithm_invalid`、`quality_rejected`和`session_reset`。不伪造`tracker/fallback`来源标签。

## 3. 原始算法逻辑

### 3.1 PuRe

```text
灰度NIR眼图
→ 强度归一化/预处理
→ 边缘提取
→ 边缘片段筛选
→ 瞳孔候选组合
→ 椭圆拟合
→ 尺寸、长短轴比、边缘支持和对比检查
→ Pupil与置信度
→ 有效椭圆或拒检
```

### 3.2 PuReST

```text
序列首帧或无previous pupil
→ PuRe全图检测

后续帧且previous pupil有效
→ 以上一帧结果构造局部追踪范围
→ 搜索和组合局部边缘
→ 椭圆拟合与质量检查
├─ 成功：更新previous pupil
└─ 失败：进入PuRe重检路径
```

这里的“tracking/fallback”是源码内部逻辑；当前绑定没有可靠地把内部路径作为输出字段暴露给v2。

## 5. 严重问题

### 5.1 椭圆轴—角度错配

这是当前最直接影响阶段4/4b质量判断的问题。若`w<h`时把轴交换为`major=h、minor=w`，椭圆主轴方向也必须从原角度旋转90度。错误组合会影响：

- 叠加图；
- 椭圆mask；
- IoU；
- 环内/环外光度对比；
- 映射回原图后的人工判断。

### 5.2 PuReST的px语义限制

当前不能把配置中的`px_min/px_max`写成每帧硬限制。正式生产中应采用：

```text
PuReST连续检测（内部宽松搜索）
→ Python层diameter/geometry/photometric/outline接受门
→ 观测或拒绝
```

`minPupilDiameterMM=0.5`只解决绑定层首帧小瞳孔门槛，不能解释成眼睛的物理毫米尺度。

### 5.3 状态污染与失败行

必须确认：

- 每个被试、Block、序列和眼别独立实例；
- 视频断点和大时间戳缺口reset；
- 坏帧保留行并有错误码；
- 单帧异常不能结束整个序列；
- 低质量结果不进入下一帧追踪种子或至少在外层被标记。

### 5.4 插值越界

插值必须同时检查中间帧的face、ROI、openness、闭眼状态、有限且单调时间戳，并检查两端major、minor和中心变化。插值不能跨序列边界，也不能把闭眼或无脸段伪装成连续观测。

### 5.5 正式条件的算法假设

正式条件约为30 cm近桌面向上拍摄，补光灯离相机水平约60 cm、高约63 cm向下照明。相对于预实验，这可能带来：

- 瞳孔像素直径变大；
- 仰拍造成的椭圆偏斜和眼睑遮挡；
- 左右眼亮度不对称；
- 镜片局部亮斑仍可能出现；
- 逐帧ROI轻微抖动对PuReST追踪的影响。

论文中的眼角几何尺度是软假设，不能直接把预实验ROI尺度和mm换算迁移到正式条件。正式数据需重新校准ROI尺度和px范围。

## 6. 环境与输入假设

当前主环境负责视频和MediaPipe，Python 3.10的`venv-pupil`负责PyPupilEXT。迁移风险包括：

- PyPupilEXT编译wheel不在v2内；
- 模型文件不在v2内；
- 主环境多个OpenCV发行版并存；
- 绝对路径和旧目录引用；
- 没有统一的一键生产入口；
- 非MediaPipe ROI后端不能自动提供EAR；
- YOLO当前是人脸框＋比例眼区，不是眼部关键点模型。

这些是生产打包阶段的问题，不在本次文档整理中修改。
