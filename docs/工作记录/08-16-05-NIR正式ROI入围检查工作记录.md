# 08-16｜NIR正式ROI入围检查工作记录

> 08-16（Asia/Shanghai）｜sub-011 Block 1正式NIR是双眼/鼻梁特写而非完整人脸；MediaPipe、YuNet和当前YOLO-face均未通过正确人脸/双眼硬门，按计划停止尺度调优与生产冻结。

## 总结

行为时间轴定位Block 1前120秒为NIR帧9441–13040，共3600帧、119934 ms，首帧相对行为起点晚45 ms。先做0.2秒与3秒冒烟检查，再在全120秒均匀抽取60个时点并形成12组联系表。正式画面稳定覆盖双眼、眼镜和鼻梁，但不含完整脸部轮廓。

MediaPipe FaceLandmarker为0/60；YuNet为1/60，该一次把单侧眼区误判为脸；当前bbox-only YOLO-face为60/60“返回”，但所有框都锁住单侧眼镜/眼区，两个比例眼点落在同一只眼内。三者正确双眼ROI均为0/60，违反“错误人脸/眼别为0”和“人工可用率≥95%”硬门。

因此没有运行30秒×3尺度×3算法，也没有运行后90秒PuReST排名；这不是任务遗漏，而是执行预先规定的“无算法达标则停止”。

## 计划

1. 用正式行为/NIR时间戳定位Block 1真实起点。
2. 先进行极短冒烟，防止对不适用模型进行大规模计算。
3. 若冒烟异常，补首、中、末与60时点复核。
4. 只有正确人脸和双眼身份硬门通过，才进入尺度校准、PuReST覆盖与速度排名。

## 失败原因与下一步边界

现有三个候选都是“先找完整人脸，再推眼睛”。正式相机移动后，输入域已经变成“固定相机下的双眼特写”，所以失败来自模型任务定义与输入域不匹配，不是简单调阈值或`corner_span`能解决。

下一轮必须重新定义ROI候选，例如专用双眼/眼角模型、固定几何＋运动跟踪，或重新调整相机使完整脸进入画面。该选择超出本计划已批准的三种人脸后端，不能静默加入并直接定稿。
