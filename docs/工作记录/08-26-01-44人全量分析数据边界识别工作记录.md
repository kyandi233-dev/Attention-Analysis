# 08-26-01｜44 人全量分析数据边界识别工作记录

## 总结

本次任务核验了用户指定的本机 NIR 结果目录、SART 问卷模板/原始 Excel/派生分析目录，以及 GitHub `kyandi233-dev/Attention-Analysis` 的当前仓库与分支状态，并将路径和数据形态说明写入当前仓库。没有复制原始数据、全量 CSV、问卷原文、手机号或开放题到 GitHub，也没有删除或改写历史工作记录。

## 原计划

背景是后续要对本机已生成的 44 人数据进行全量分析，用户当前要求先完成资料识别和路径登记，分析计划另行提供。执行目标为：

1. 读取项目入口文档和引用对话，确认当前 NIR/Behavior 口径；
2. 识别本机 NIR 和问卷资料的文件形式、规模、字段层次和数据边界；
3. 核验 GitHub 仓库、远端和当前分支；
4. 新增本地资料说明和 provenance 工作记录；
5. 将同一说明同步到 GitHub，并复核远端结果。

主要风险是把历史候选口径误当成当前结果、把 44 人问卷答卷误当成 44 个被试、把外部数据复制到仓库，或把同一被试的并存输出目录静默拼接。

## 执行与决策过程

### 1. 当前项目口径

读取根 README、docs 入口、NIR README、正式 runtime 文档、安装文档和 NIR decisions。当前仓库正式 NIR 逻辑为 FocusWave v3.1.3 phase windows → 逐帧 YOLO26n → ROI → RITnet → 指标/QC。当前 checkout 是 `amd-DirectML-ritnet512` 候选分支，但稳定 AMD 口径是 `amd-DirectML` / `amd-v0.1.1` 的 640×400 RITnet。

引用的“确认数据边界”对话说明：GitHub 能确认代码、schema 和方法，但不能替代本机 `D:\_AttentionData` 的真实 cohort 核验；44 人 full-class 数据不能被假设为已经在 GitHub 中。

### 2. NIR 本机核验

扫描 `D:\_AttentionData\Beijing-NIR\amd-directml` 得到约 7.4 GB、7,772 个文件：CSV 177、JSON 315、PNG 6,568、JPG 712。根目录有 45 个 `sub-` 目录，但解析 completion marker 后得到 44 个唯一 subject，44/44 个 `ritnet-fullclass-v1.2-fast-qc` marker 为 complete。

44 个 subject 的编号集合为：

```text
sub-031 ... sub-055, sub-061, sub-137, sub-141, sub-144, sub-146,
sub-150, sub-153, sub-156, sub-163, sub-164, sub-165, sub-167,
sub-168, sub-171, sub-172, sub-173, sub-174, sub-176, sub-177
```

44 个 fast-QC CSV 共 3,538,056 行，单被试 74,233–87,215 行；summary 中的 decoded frames 总数为 2,047,733。`normalization_valid_fraction` 跨被试约 0.2691–0.9853，中位数约 0.7736，说明“marker complete”不能被解释为“所有观测都有效”。

实际 marker 还确认了这批结果全部使用同一模型哈希、RITnet 640×400 输入、320×160 分析尺寸、DirectML `dml:0`、FP32、batch=16，并复用 source pupil。由此决定：本次登记的真实 44 人数据按 640×400 稳定 AMD 结果记录，不能因为当前 checkout 名称含 `ritnet512` 就改写成 512×320。

发现 `sub-035_formal_v3.1.3_yolo_b16_fp32` 与 `sub-035_formal_v3.1.3_yolo-b8_ritnet-b16_fp32` 并存。前者只有 completion/phase 文件，没有 full-class fast-QC 产物；后者才有 complete marker 和 full-class 文件。因此只将后者作为 `sub-035` 完成结果，旧目录作为并存的历史/不完整输出记录。

逐被试 full-class CSV 存在可处理的 schema 差异：`sub-031`–`sub-034` 为 106 列，其余 40 份为 107 列；后 40 份在 `ritnet_found` 前增加 `yolo_batch_size`。最终决定后续必须按列名对齐，不按列位置静默读取。

### 3. SART 问卷核验

两份 TXT 被识别为问卷模板，而不是答卷：合并版正式模板 26 题，北京版模板 25 题。5 个原始 Excel 均为单 sheet，实际答卷行数分别为 3、7、24、110、2，合计 146。

问卷派生目录已有 `questionnaire_derived_data.csv`（146×67）和 `subject_repeat_registry.csv`（146×23），并按珠海预实验 1/2、珠海正式、北京正式组织了阶段和地点字段。派生数据标记了重复参与和身份冲突，不应静默合并。44 个 NIR 编号均出现在问卷派生 CSV 的非空 `experiment_id` 集合中，但这只证明编号交集，不替代后续正式联结审计。

### 4. GitHub 核验与保存策略

本地 remote 为 `https://github.com/kyandi233-dev/Attention-Analysis.git`，当前 checkout 为 `amd-DirectML-ritnet512`，HEAD 与 origin 分支起点一致；工作区在任务开始前已有大量用户未提交改动和未跟踪文件，因此本次只新增专用资料说明、工作记录和 README 链接，不触碰其他改动。

为遵守研究 provenance 与隐私边界，决定只在 GitHub 保存本说明和路径/规模/schema 元数据，不上传外部 NIR 结果、原始问卷、问卷 TXT、手机号或开放题原文。
