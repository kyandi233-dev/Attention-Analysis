# 031 正式 BB 行为分析流程

## 1. 适用范围

本文档描述 FocusWave v3.1.3 最终正式实验的行为分析流程。正式任务包含两个 B block，不沿用早期 v3.0 BBB 的三 block 推断结构。当前 BB 实现已经建立，入口为 `scripts/sart_formal_analysis.py`。

```text
正式数据候选根
→ 忽略不存在的路径并发现编号 ≥31 的完整正式被试
→ 检查同一被试是否跨根重复
→ 读取 B1 / B2 behavior CSV
→ schema 与跨被试完整性校验
→ trial-level 派生变量
→ block / cycle-bin / probe 指标
→ B2-B1 被试内统计
→ block 内时间趋势
→ 图表与 Markdown 报告
```

## 2. 数据根与被试发现

正式原始数据在逻辑上位于 `正式实验` 与 `Data` 目录。两块外接存储设备在部分 Windows 机器上可能被分配为 `E:` / `F:`，NVIDIA 工作站当前也可能把正式 `Data` 挂载为 `J:/Data`。`configs/behavior_formal.yaml` 与 NIR formal config 统一声明以下候选根：

```text
E:/正式实验
F:/正式实验
E:/Data
F:/Data
J:/Data
```

reader 会忽略不存在的候选根，并在所有有效根中发现被试；`include: []` 表示不写死被试名单，而是自动发现编号达到正式版本下限的被试。reader 同时接受 `sub-031_` 和 `sub-031` 两种目录名。

同一被试若只在一个有效根中存在，则正常读取该位置；若同一被试的 `beh/` 目录同时存在于多个有效根，程序直接报错并列出重复位置，不按配置顺序静默选择。这样可以避免备份盘、复制数据或盘符变化造成来源歧义。

一个被试只有在 B1、B2 行为文件都存在时才属于可分析集合。发现任何正式编号被试存在不完整 block 时，提取阶段直接报错，不静默跳过。

## 3. 输入文件

以 `sub-031_` 为例，最终正式数据结构为：

```text
<active-root>/sub-031_/
├── beh/
│   ├── esc_keypresses.csv
│   ├── master_timeline.csv
│   ├── SART_031_Practice_run1.csv
│   ├── sub-031_Block1_B_beh.csv
│   ├── sub-031_Block2_B_beh.csv
│   └── subject_summary.csv
└── nir/
    ├── sub-031_nir.avi
    └── sub-031_nir_timestamps.csv
```

当前行为主分析直接读取 `sub-XXX_Block1_B_beh.csv` 和 `sub-XXX_Block2_B_beh.csv`。每个 CSV 必须满足当前行为 schema；若最终 v3.1.3 的实际 schema 与 reader 定义不同，应依据真实文件更新 reader，而不是向旧 BBB 格式强行兼容。

`master_timeline.csv` 与 `sub-XXX_nir_timestamps.csv` 用于行为—NIR 时序对齐；practice、esc keypresses 和 subject summary 保留作 QC/provenance，不混入两个正式 B block 的主要行为指标。共享 `block_windows()` 已设计为按 timeline 实际 block 数解析，因此既能保留历史多 block 数据，也能处理最终 B1/B2 timeline。

## 4. 当前与历史的关系

当前实现位于 `src/attention_pipeline/behavior_formal/`，只处理最终 v3.1.3 BB。旧 v3.0 BBB 作为独立历史实现保留在 `src/attention_pipeline/behavior_bbb_v3_0/`，运行入口为 `scripts/sart_bbb_v3_0_analysis.py`，配置为 `configs/sart_bbb_v3_0.yaml`。历史结果材料位于 `docs/030-behavior/history/BBB-v3.0/`。
