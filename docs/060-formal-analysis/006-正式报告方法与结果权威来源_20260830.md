# 正式报告方法与结果权威来源（2026-08-30）

本文用于说明正式竞赛报告第 4.5 节与第 5 章后续写作所依据的分析来源。它是分析仓库内部说明，不是正式报告正文。

## 1. 本仓库负责的正式分析范围

当前唯一继续维护的正式分析分支为 `codex/formal-analysis-v2-portable`。本文件建立时远端 HEAD 为 `3a7ce93c0f4330e9d5be0f1e0d9c0847a3d849c1`。

本仓库作为以下三类分析的权威代码来源：

- Behavior：SART 行为、思维探针、重复参与者处理、探针前窗口与多尺度统计；
- NIR：pupil-only 直接瞳孔几何、视觉条件调整、事件相关变化、任务时间变化与静息可观测性；
- RGB：当前正式范围已经收缩为整体运动、曝光/亮度变化控制、必要的姿态确认/方向候选和眨眼候选事件。

RGB 当前不再把 AU、情绪、rPPG、PERCLOS、完整头姿分析、RGB 独立预测或正式多模态融合作为 active formal scope。PERCLOS 保留历史记录但当前关闭。Pose 主要用于辅助确认运动方向，径向前后运动只作为复合候选，不能解释为真实物理位移。

## 3. 报告中的术语转换

仓库内部可以保留 contract、gate、runner、not_estimable、fallback、model-ready 等执行术语，但正式报告正文必须转换为研究方法语言。例如：

- participant-disjoint LOSO → 每次以一名参与者的全部观测作为独立测试集，其余参与者用于训练；
- matched cohort → 仅在相同参与者和相同探针窗口上进行模型间比较；
- quality gate → 按预先定义的数据质量标准形成可分析观测；
- fallback baseline → 当预定参考阶段数据不足时不把替代值解释为静息基线；
- model-ready → 数据、时间窗口和特征定义已经满足建模前提，不等同于模型已经训练或获得结果。

## 4. 当前正式报告固定口径

1. 正式实验总体仍按完整研究资料书写为 63 名参与者、119 次实验；阶段性已合并的数据量不能替代总体样本。
2. Go omission 在报告中使用简洁名称：`Go 遗漏率`、`无时序歧义遗漏率`、`时序歧义遗漏率`。第一次出现时解释后二者是依据按键时序特征对 Go 遗漏作的进一步区分；不把“无时序歧义遗漏”直接称为注意遗漏。
3. NIR 主分析不依赖静息瞳孔基线。实验过程中的典型瞳孔水平用于描述个体内相对变化，事件相关分析使用事件前短时水平作为参照；3 min 静息阶段仅在眼部具有足够可观测数据时作为探索性参考。
4. RGB 正式报告按已经确定的轻量范围写，不等待旧的大而全实现。
5. 毫米波和多模态方法按 greenboo 最新 main 的科学证据写；其结果只有在对应真实分析完成后才能进入第 5 章。
6. 多模态贡献比较必须使用相同参与者、相同探针窗口和相同外层验证划分。主要比较采用可解释的特征级融合与参与者独立验证；更复杂 AI 融合作为后续/次要分析，不能替代基本增量贡献分析。

## 5. 状态边界

当前 RGB 轻量管线已经完成代码收缩并有自动化测试证据，但尚不能据此宣称真实眨眼识别准确率、运动指标与毫米波伪影关系或注意效度。毫米波最新证据已经纠正 frame-time 语义，并表明旧 Python-time 窗口与新 DLL-time 窗口不可互换；HR/BR 仍需保留当前验证边界，HRV/IBI 不能作为已经验证的正式生理指标。多模态 matched cohort 和 LOSO 设计已经具备建模前提，但不能把“可建模”写成“模型已经得到正式结果”。
