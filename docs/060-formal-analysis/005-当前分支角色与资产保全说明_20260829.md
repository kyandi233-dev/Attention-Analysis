# 当前分支角色与资产保全说明（2026-08-29）

本文件用于说明 `kyandi233-dev/Attention-Analysis` 当前主要分支的角色、正式分析边界、历史来源关系与删除安全性。它是仓库治理文件，不是科学结果，不替代具体 PR、commit、运行记录或正式证据库。

## 1. 核心原则

1. **正式分析主线已经收口，不等于其他分支的所有文件都原样存在于正式主线。**
2. `codex/formal-analysis-v2-portable` 负责的是 Behavior + NIR + RGB + mmWave 外部接入/融合的正式下游分析合同；生产提取、恢复工具、benchmark、历史实验实现可以具有独立价值，不应仅因不属于 formal v2 就删除。
3. “分支可以删除”必须满足以下至少一种条件：
   - 该分支已经成为保留分支的 Git 祖先；或
   - 其仍有价值的代码/文档已经逐项迁入保留分支，并有 commit/PR/治理文档可回溯；或
   - 经审计确认其独有内容属于明确废弃实现，且没有独立生产、恢复、benchmark 或证据价值。
4. **禁止仅根据分支名称、PR 是否关闭、或“正式 v2 已完成”推断分支可删除。**
5. 删除 branch ref 不删除 Git commit 历史，但未被其他 ref/PR/文档稳定引用的独有资产仍可能变得难以发现，因此删除前必须先做资产保全审计。

## 9. 后续分支清理流程

以后任何分支删除必须按以下顺序：

1. 记录分支完整 40 位 HEAD；
2. 与目标保留分支执行 commit/ref compare；
3. 列出 unique commits；
4. 列出 unique files；
5. 将每项独有内容分类为：
   - 正式分析必须迁移；
   - 生产/runtime 必须迁移；
   - 独立工具/benchmark，应长期保留或归档；
   - 历史证据，应保留文档/SHA/PR 入口；
   - 明确 rejected，可删除；
6. 对“选择性迁移”分支做功能等价矩阵，而不是只看文件名是否相同；
7. 只有所有有价值资产都有稳定归宿后，才删除 branch ref；
8. 删除后在本文件或后续治理文件中记录删除日期与最终归档位置。
