# 身份键与正式管线连续性联合审计（2026-08-30）

> 审计基线：`codex/formal-analysis-v2-portable@600f128820de750ac71bc28bd97410a02a3f3af5`  
> 性质：代码/合同审计记录，不是科学结果，不表示真实数据已经重跑。  
> 目的：把三层身份键兼容、Behavior/NIR/RGB 当前执行链、NIR/RGB 已发现断点以及多模态 deferred 边界统一写清，避免后续任务继续把兼容别名误判为新身份来源，或把未修复问题误写成已完成。

## 1. 先纠正两个容易误解的结论

第一，当前代码**没有证据表明 `participant_key` 被替换成 `session_id`**。正式身份协调逻辑明确把 `session_id` 作为实验/采集场次键，把参与者聚类键单独处理；RGB 也有显式的 `participant_identity_unresolved_no_session_id_fallback` 门。后续任何模块都不得新增 `session_id -> participant` 回退。

第二，当前问题不能简单概括为“三套身份都在并行分析”。Behavior 已经存在协调层：`participant_key` 和旧 `repeat_participant_id` 先进入 `reconcile_cohort_identity()`，得到 `participant_group_id`，随后为了兼容 science-v3 旧函数签名，再把协调结果回写到列名 `repeat_participant_id`。因此 Behavior 中后续出现的 `repeat_participant_id` 多数情况下是**兼容列名**，其数值语义已经是协调后的组键。

## 2. 当前身份字段的准确语义

| 字段 | 当前准确含义 | 当前角色 | 目标状态 |
|---|---|---|---|
| `session_id` / `subid` | 一次实验/采集场次 | 跨模态定位、时间和数据成员关系 | 永远不是参与者聚类键 |
| `participant_key` | 问卷/重复登记中已核验的匿名参与者键 | 最高优先级身份来源；问卷缺失时保持缺失 | 作为来源字段长期保留 |
| `repeat_participant_id` | 旧 `cohort_manifest` 的匿名重复组列；Behavior 兼容层仍大量读取 | 旧 manifest 输入、历史来源；协调后在 Behavior 内被回写为统一组键 | 逐步收缩为 legacy input/provenance，不再作为跨模块内部标准名 |
| `participant_group_id` | 身份重协调后供正式推断、cluster bootstrap、GroupKFold/participant-disjoint prediction 使用的统一接口 | 当前正式统一统计键的设计目标 | 成为 Behavior、NIR、RGB 与后续正式推断唯一内部统计键 |
| `analysis_group_token` | staged NIR pupil-only 路线保留的分析组兼容别名 | NIR analysis-ready/tables 的历史接口，不是第四种身份来源 | 通过显式桥接/一致性测试映射到 `participant_group_id`，不再形成独立身份语义 |

因此正式目标不是删除 `participant_group_id`，也不是把 `participant_key` 改名，而是固定以下单向关系：

```text
participant_key（已核验来源，若存在）
        +
legacy repeat_participant_id（仅在治理验证通过时允许补足）
        ↓
reconcile_cohort_identity()
        ↓
participant_group_id（唯一内部统计/分折接口）
```

`participant_key` 缺失时不得反向伪造。`participant_group_id` 无法解析时，session 仍可保留用于单模态 QC/覆盖率输出，但参与者级推断、聚类重抽样和 participant-disjoint prediction 必须 `not_estimable + reason`。

## 3. 当前已确认正确的部分

### 3.1 Behavior 的身份顺序本身不是“协调前必然 require_groups”

`prepare_behavior_runtime_config()` 当前顺序是：加载 cohort → 读取 repeat registry → `reconcile_cohort_identity()` → `included_cohort(..., require_groups=True)`。因此不能把 RGB 的顺序缺陷泛化成 Behavior 的事实。

Behavior 后续的 science-v3 仍使用 `repeat_participant_id` 作为函数参数/列名，但该列在协调后已经被赋值为 `participant_group_id`。这属于兼容接口，不是三套独立分组算法。

### 3.2 禁止 `session_id` 伪造 participant 的合同已经存在

`reconcile_cohort_identity()` 在没有 `participant_key` 和可用旧组时返回 unresolved；RGB 的 participant inference gate 明确禁止 session fallback。NIR 当前也没有从 `sub-XXX` 场次编号推断参与者身份的逻辑。

### 3.3 问卷仍然只能 LEFT JOIN

问卷/重复登记是身份和协变量来源，不决定正式 cohort 成员关系。缺问卷不能删除 session，也不能通过补造问卷行来制造 `participant_key`。

## 4. 身份层仍未修复的真实缺陷

### 4.1 legacy fallback 缺少治理状态 gate

`reconcile_cohort_identity()` 目前会检查“同一个 legacy group 是否映射到多个 `participant_key`”，但对于**完全没有 questionnaire overlap 的 legacy group**，只要旧 `repeat_participant_id` 非空，就会生成 `legacy:<id>` 并标记为 `governed_cohort_fallback_no_questionnaire_identity`。

当前代码没有把 `cohort_manifest` 中类似 `identity_status` 的治理状态作为允许 fallback 的必要门。因此“有旧组”还没有严格等价于“该旧组已被验证可用于参与者聚类”。后续修复应新增允许状态白名单/显式布尔合同；未通过时保留 session，但 `participant_group_id=NA`、`participant_identity_source=unresolved_or_unvalidated_legacy`。

### 4.2 RGB 的身份协调顺序仍然错误

`rgb_formal.runner._governed_identity()` 当前先执行 `included_cohort(cohort, require_groups=True)`，之后才读取 registry 并运行 `reconcile_cohort_identity()`。因此未来如果某个合法 session 旧 `repeat_participant_id` 为空、但问卷存在可靠 `participant_key`，它会在协调前被错误拒绝；同样，这也与“unresolved identity 只阻断 participant inference，不删除 lightweight QC session”的注释不一致。

RGB 应改为与 Behavior 同一顺序：先按 `include=true` 保留 session → reconcile → QC 可继续 → 只有参与者级 inference gate 才要求 `participant_group_id` resolved。

### 4.3 需要跨模块一致性测试

必须增加同一 synthetic cohort 同时走 Behavior/NIR/RGB 的 contract test，至少覆盖：

1. 有 `participant_key` + 有旧组：三模块最终统计组完全一致；
2. 有 `participant_key` + 旧组缺失：session 保留，最终使用 `participant_key`；
3. 缺问卷 + 已验证无歧义旧组：session 保留，允许 legacy fallback；
4. 缺问卷 + 未验证/冲突旧组：session QC 保留，participant inference `not_estimable`；
5. 任意情况下禁止 `session_id` 进入 participant grouping；
6. 当前 44 session / 38 group / 6 双场是当前 manifest 快照；新增兼容场次后必须重新映射并重新生成 participant-disjoint folds，不能把 38 组写成永久常量。

## 5. NIR 当前存在的两个执行合同冲突

### 5.1 NIR 正式路线仍引用旧 `behavior_formal.yaml`

当前 `scripts/sart_formal_analysis.py` 的正式 Behavior 入口默认使用 `configs/behavior_formal_v2.yaml`，并通过 path registry 注入机器路径；但 `configs/nir_formal_analysis.yaml` 仍把 Behavior 输入指向旧 `configs/behavior_formal.yaml`，而该旧配置含 D:/E:/F: 机器路径和旧 formal-v1 输出路径。

这会形成：

```text
Behavior 正式 science-v3 → behavior_formal_v2.yaml
NIR 加载 Behavior trial → behavior_formal.yaml（旧路径/旧配置）
```

修复时不能只把文件名字符串替换成 v2；NIR 应复用 `prepare_behavior_runtime_config()` 或等价统一 adapter，确保 cohort、identity reconciliation、path registry、trial reader 与 Behavior 正式入口同源。

### 5.2 `nir_source_manifest` 同一 path key 被两种格式竞争使用

当前 `nir_analysis_ready.pupil_only` 读取 `@path:nir_source_manifest` 时要求 JSON object + `sessions[]`，每个 session 包含 `source_csv / analysis_group_token / source_schema_version` 等；而 `scripts/formal_multimodal_analysis.py nir-adapt` 对同一个 `nir_source_manifest` path key 使用 `pd.read_csv()`，要求 `session_id/status/eye_metrics_csv/schema_version`。

一个 logical path key 不应同时代表 JSON 和 CSV 两个不兼容合同。后续必须明确：

- staged `nir_formal_pipeline.py -> nir_analysis_ready.pupil_only` 是否为唯一正式 materialization 入口；
- `formal_multimodal_analysis.py nir-adapt` 若仅保留历史/兼容用途，应改为不同 path key、不同输出命名并标记非 authoritative；
- 两条路径不得互相声称产生对方可以直接消费的 schema。

## 6. RGB lightweight 当前还存在的函数级问题

RGB 轻量化提交 `3a7ce93c0f4330e9d5be0f1e0d9c0847a3d849c1` 已把默认范围收缩为 Motion + exposure control → Pose confirmation/direction → independent Blink candidates；当前分支继续包含这一路线。但联合审计仍确认以下问题未完成：

1. **身份顺序**：见 4.2。
2. **Motion validity**：`derive_motion_qc()` 当前主要以 motion energy 是否非空决定 observable，没有把 producer 已保存的 `motion_valid / gap_before / irregular_dt` 完整并入 `body_motion_qc_valid` 门。
3. **Blink bilateral consistency**：已经计算 `bilateral_eye_consistent`，但 `blink_closed_bilateral_candidate` 当前没有显式要求该条件，因此左右眼严重不一致的帧仍可能进入闭眼候选。
4. **Blink component status 传播**：runner `_component_row()` 当前优先读取 generic `status`，再读 `blink_status`；Blink 的 primary-face status 与 blink estimability 同时存在时，可能把 `not_estimable` 误写成 generated。应优先 `blink_status/blink_reason`。
5. **Pose radial 命名**：`pose_radial_proximity_candidate_per_sec` 实际由多个方向分量的符号一致性平均得到，语义更接近方向一致性候选/score，不应使用 `/sec` 暗示物理速度。

这些仍属于工程/合同缺陷，不代表 RGB 指标无效，也不能据此形成科学结论。

## 7. 配置与文档权威漂移

`configs/README.md` 仍把 `behavior_formal.yaml` 标记为“当前行为配置”，但正式 science-v3 runner 实际默认 `behavior_formal_v2.yaml`。旧配置仍含机器绝对路径，不能再作为 current formal 配置示例。文档必须明确：机器路径只允许出现在 `configs/paths.local.yaml`；旧配置作为历史/兼容资产可以保留，但不得继续被标成正式权威入口。

历史代码/测试不能因为不在当前主线就直接删除。比如旧 PIR materialize 已以 `legacy_*` 名称隔离并用于 provenance/regression，这属于历史资产保全。治理目标应是“active path 收口 + legacy path 明确隔离”，而不是物理清除所有历史实现。

## 8. 多模态 merge 的当前状态：deferred scaffold，不是已统一生产接口

当前 `formal_analysis.merge.UNIT_KEYS` 仍以 `repeat_participant_id` 作为 participant key；Behavior 的该列是 reconciled key 的兼容别名，staged NIR 仍保留 `analysis_group_token`，RGB 输出使用 `participant_group_id`。因此当前不能声称三个模态已经可以零转换直接 merge-ready。

在正式融合恢复前应先统一 identity bridge，并把 participant grouping 与 row location key 分开：

- row/event 定位继续由 `session_id + block/trial/probe/window/time` 决定；
- `participant_group_id` 作为合并后的 grouping metadata 与 inference/prediction cluster；
- 不得为满足 merge key 而用 session 编号制造 participant；
- RGB/mmWave 既定 session/window 时间键继续保留；
- 多模态仍为 deferred，不能把“合同具备”写成“已生成正式融合结果”。

## 9. 下一轮代码修复验收顺序

建议按依赖关系修复，而不是按模态各自继续叠补丁：

1. **Identity contract**：legacy validation gate + `participant_group_id` 统一接口 + Behavior/NIR/RGB cross-module tests；
2. **Behavior/NIR shared loader**：NIR 不再读取旧机器路径版 Behavior config；
3. **NIR source manifest authority**：消除同一路径键双格式竞争；
4. **RGB residual fixes**：identity order、motion validity、bilateral blink gate、status propagation、pose naming；
5. **Config/docs authority**：current/legacy 标识与 path registry 规则统一；
6. **Merge bridge**：单模态全部通过后再恢复正式 multimodal merge/fusion。

每一项都必须区分：代码已写、合成/CI 已通过、代表性真实 smoke 已通过、44-session 全量已完成、科学结论已形成。任何前一层通过都不能自动升级为后一层。
