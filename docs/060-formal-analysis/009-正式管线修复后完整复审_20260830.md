# 正式管线修复后完整复审｜2026-08-30

## 1. 复审对象与结论

本文件记录 `codex/formal-analysis-v2-portable` 在身份合同、Behavior science-v3、NIR pupil-only staged downstream、RGB lightweight downstream、路径注册表、环境 bootstrap、legacy/deferred 边界完成修复后的第二轮完整复审。复审不等同于真实 44 场正式运行；本轮证据仍分为代码实现、synthetic/CI、真实本机 smoke、全量运行和科学结论五个层级。

本轮复审后的主结论：当前正式单模态链已经形成清楚的权威入口；Behavior、NIR、RGB 不再依赖历史机器路径作为当前运行条件；NIR 的 PIR/iris geometry 与 ocular-aperture QC 已从代码接口、science config 和 manifest 语义上分开；RGB 已把整场/组件缺失作为模态 availability/QC，而不是 cohort 或 participant identity 的异常。多模态融合仍明确禁用。

## 3. cohort、participant 与模态 availability

当前实验事实需要区分三个轴：

1. `session_id`：一次实验/采集场次；
2. `participant_group_id`：正式统计和 participant-disjoint prediction 的参与者分组；
3. modality availability：这一场的 NIR/RGB/mmWave 是否实际录到并可用。

本项目并不存在因为缺 RGB 或 mmWave 就需要制造“伪参与者”的情形。某个已知 participant/session 没有某个模态，只改变该模态的 availability/QC，不改变 participant identity，也不能删除 Behavior 或其他模态的数据。

因此当前合同冻结为：

```text
governed cohort
  -> participant identity
  -> each modality independently checks source availability and QC
       available       -> derive modality outputs
       source_missing  -> explicit missing/not_estimable
       invalid         -> explicit structural/QC failure
  -> future paired multimodal analysis may select common-available subset explicitly
     but must report original cohort and each modality coverage
```

不得把 missing modality 填 0，不得用缺失模式重新编号 participant，也不得拿某一模态的 source manifest 反向定义整个实验 cohort。

## 4. Behavior science-v3 复审

本轮未再改 Behavior 科学公式，因为前一轮已经完成科学与实现复核，且用户澄清现实问题是模态缺失而非未知参与者。当前关键点仍成立：

- Go omission 与 No-Go commission 使用不同机会数作为分母；
- RT 仅使用正确 Go 反应；
- 输出均值、中位数、SD、MAD、IQR、CV 和 Theil–Sen 时间斜率；
- d′、criterion c、β 使用预定义 SDT 口径；
- probe 主分析严格使用 probe 之前的行为试次，锚定 trial 被排除，不跨 Block；
- 10/20/30 秒是 sensitivity windows，不被重复计为独立主样本；
- Q1 名义四分类与 Q2 有序四等级建模分开；
- participant grouping 用于聚类/重抽样/预测 fold，session 不被当作独立 participant；
- model failure 写入失败表，不能用空表冒充成功。

当前 44 sessions / 38 participant groups / 6 double-session repeat groups 是当前队列快照，不应写成永久 study total。

## 5. NIR staged pupil-only 复审

### 5.1 当前主信号

正式生理主信号仍是 pupil geometry；可靠性不足的 iris geometry 不进入正式 PIR 计算。当前 staged chain 为：

```text
fullclass-final source
  -> pupil-only contract/adaptation
  -> 10_analysis_ready
  -> 11_analysis_tables
  -> pupil-only validation
```

正式 downstream 不允许为了补统计结果自动重跑 YOLO/RITnet，也不允许用 frame index 伪造正式时间。

### 5.2 OAR/PIR 历史混名已修复

`fullclass_ocular_aperture_ratio_median` / `p90` 的权威解释是 visible ocular mask（sclera + iris + pupil）height/width 的眼睛开合 QC candidate。它们：

- 可以作为 NIR eye-opening QC 保留；
- 不是 PIR；
- 不是 iris diameter；
- 不是 MediaPipe EAR；
- 不是 blink event；
- 不是 PERCLOS；
- 当前不自动成为 formal physiological endpoint。

本轮已把旧的 `pir_oar_allowed` / `pir_oar_refused` 混合语义拆开。权威接口和配置现在表达为：

```text
PIR / iris geometry refused
ocular-aperture QC preserved
ocular-aperture formal endpoint = false
```

历史 materializer 内旧字段可为 provenance/legacy test 保留，但当前 package-level authoritative `run_materialization` 会规范化返回 summary 和 persisted manifest，避免正式输出继续传播旧混名。

### 5.3 legacy PIR 代码

历史 PIR validation/materialize 模块仍物理存在，以便 provenance 和兼容测试；当前 package default validation 与当前 CLI 已指向 pupil-only。现阶段不因“不是当前入口”就删除这些历史文件。

## 6. RGB lightweight downstream 复审

当前 RGB 正式下游只做：

- Motion QC，并与曝光变化分轨；
- Pose confirmation/direction candidate；
- 独立 algorithm-defined blink candidates。

PERCLOS、AU、emotion、rPPG、复杂 prediction、多模态综合 risk score 均为 disabled/deferred。

缺数据的传播逻辑复审通过：如果某 governed session 没有 RGB subject directory，runner 会保留该 session 的 QC 行，记录 `rgb_source_absent`，Motion/Pose/Blink 分别为 `not_estimable`；不会从 cohort 删除，也不会自动触发昂贵 producer。某一个 component 的文件缺失也不会阻断已完成的其他 component。

## 7. mmWave 接口边界

mmWave 的正式 producer/analysis authority 不在本仓库。本仓库只冻结跨模态接口原则：

- 结构性缺失必须是 explicit missing/invalid；
- 不能填 0；
- 不能写成 success；
- 缺 mmWave 的 session 不能因此从 Behavior、NIR、RGB 中删除；
- 后续 multimodal common-cohort 分析必须把 mmWave coverage 一并报告。

## 8. 路径、环境和新电脑可移植性复审

### 8.1 路径注册表

`configs/paths.example.yaml` 当前为 version 3，loader 支持 version 1/2/3，未知未来版本 fail closed。机器路径必须进入本机 `configs/paths.local.yaml` 或由 `ATTENTION_ANALYSIS_PATHS_CONFIG` 指向的等价文件。

新电脑最危险的接口之一是两个 NIR manifest 串线：

- `nir_analysis_ready_source_manifest_json`：当前 staged JSON manifest；
- `nir_source_manifest`：历史 CSV adapter manifest。

JSON/CSV 不能混用。

### 8.2 环境 bootstrap

正式下游使用三个隔离环境：

- `attention-behavior-formal`
- `attention-nir-formal`
- `attention-rgb-formal`

`setup_formal_environment.py` 会创建/保留环境、执行 `pip install -e .` 并做依赖 import check。本轮额外把 `pyarrow` 加入 NIR bootstrap 自检，使 Arrow/Parquet 依赖问题在环境初始化阶段暴露，而不是推迟到真实数据读取时。

### 8.3 仍需真实新电脑验证的项目

以下项目只能靠新电脑 representative smoke 最终确认，CI 不能证明：

- 本机数据盘和输出盘实际挂载位置；
- Windows 文件权限/Excel 占用导致的 `PermissionError` / WinError 32；
- 第三方程序对长路径、中文路径的兼容性；
- source manifest 中记录的路径是否对应新机器；
- session 文件夹名、文件名与表内 `session_id` 是否一致；
- 本机 PowerShell 是否已 `conda init`；
- 大文件读取时磁盘空间、内存和 IO 是否足够。

这些不是代码 CI 能替代的证据。

## 9. deprecated / historical / deferred 审查

当前保留的历史代码大体分为三类：

1. 历史 NIR PIR/materialize/validation：provenance/legacy tests；
2. 旧 Behavior config 与 preexperiment/formal config：历史运行记录；
3. historical multimodal merge scaffold：deferred audit only。

复审原则是“明确降级，不主动删除”。如果以后确定需要清理文件，必须先做引用审计和 provenance 迁移，不应在本轮直接删除。

## 10. 当前仍需关注但不是 release blocker 的事项

- 历史 pandas `stack` 等代码可能产生 FutureWarning；只要位于 legacy 路线且不影响 current authority，可先记录而不是为了消 warning 改变历史输出。
- synthetic statsmodels 测试可能出现 rank/convergence warning；模型失败本身已经有 fail-closed/failure-table 合同。
- 根 README 仍包含大量 AMD 历史运行手册和绝对路径，不能作为本分支正式 portable 指南；正式新电脑入口必须从仓库根 `ANALYSIS_SETUP_FIRST.md` 开始。
- multimodal fusion 尚未放行；当前只能谈单模态 availability、QC 和未来接口，不应生成“融合正式结果”。
