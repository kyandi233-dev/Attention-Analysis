# NIR 正式运行输出目录与覆盖参数说明

> 适用分支：`codex/formal-analysis-v2-portable`
>
> 适用入口：`scripts/nir_formal_pipeline.py`
>
> 本文只说明 **NIR pupil-only downstream（仅瞳孔下游分析）** 的输出边界。该入口不会重新运行 YOLO，也不会重新运行 RITnet，不会写回生产提取根目录。

## 1. 正式 NIR 下游有两级输出

当前权威执行链为：

```text
已有 fullclass-final / pupil-only producer 输出（只读）
    ↓
10_analysis_ready
    ↓
11_analysis_tables
```

这两个目录都不是硬编码盘符，而是由本机 `configs/paths.local.yaml` 解析：

- `@path:nir_analysis_ready_root` → `10_analysis_ready`
- `@path:nir_analysis_tables_root` → `11_analysis_tables`

任何电脑上都可以用下面命令确认真实落盘位置：

```powershell
$nirReadyRoot = python -c "from attention_pipeline.config import load_config; c=load_config(r'configs/nir_analysis_ready.yaml', paths_config=r'configs/paths.local.yaml'); print(c.path_value('output_root'))"
$nirTablesRoot = python -c "from attention_pipeline.config import load_config; c=load_config(r'configs/nir_formal_analysis.yaml', paths_config=r'configs/paths.local.yaml'); print(c.path_value('output_root'))"

"NIR analysis-ready root = $nirReadyRoot"
"NIR analysis-tables root = $nirTablesRoot"
```

不要把某台电脑的 D:/E:/F:/J:/ 等绝对路径写进 science config；机器路径只放在本机 `configs/paths.local.yaml`。

## 2. `10_analysis_ready` 会生成什么

`configs/nir_analysis_ready.yaml` 的 `output_root` 指向 `@path:nir_analysis_ready_root`。`materialize` 阶段会把既有 NIR producer 结果转换成正式分析可直接消费的 pupil-only 表，不重新调用模型。

核心目录结构包括：

```text
10_analysis_ready/
├─ frame_level/
│  └─ <session_id>/
│     └─ <session_id>_nir_analysis_ready.csv
├─ baselines/
│  ├─ <session_id>_eye_baselines.csv
│  └─ session_eye_baselines.csv
├─ qc/
│  ├─ session_load_failures.csv
│  ├─ session_eye_block_inclusion.csv
│  └─ cohort_inclusion_summary.json
└─ provenance/
   ├─ source_files.csv
   └─ analysis_ready_manifest.json
```

此外，当前 staged pipeline 还会生成候选指标 sidecar，供后续 candidate validation（候选指标验证）使用；这些仍然属于 `10_analysis_ready` 派生层，而不是 producer 原始层。

### `--overwrite-derived` 的边界

当运行：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage all `
  --paths-config "configs/paths.local.yaml" `
  --overwrite-derived
```

`--overwrite-derived` 只允许 `materialize` / candidate materialize 重新写 **`10_analysis_ready` 内的派生结果**。它用于解决已有派生文件导致的 `FileExistsError`，例如：

```text
derived output already exists: ...\10_analysis_ready\qc\session_load_failures.csv
```

它不会：

- 删除或覆盖 fullclass-final producer 原始输出；
- 重新运行 YOLO；
- 重新运行 RITnet；
- 修改原始 NIR AVI；
- 把 PIR / iris geometry 重新引回正式分析。

## 3. `11_analysis_tables` 会生成什么

`configs/nir_formal_analysis.yaml` 的 `output_root` 指向 `@path:nir_analysis_tables_root`。`tables` 阶段只消费已经生成好的 `10_analysis_ready` 和正式 Behavior trial 数据，生成正式分析表、审计结果、统计候选结果和图表。

这一层包含的工作包括：

- trial / probe / time-on-task 等 NIR 分析表；
- participant identity audit（参与者身份审计）；
- baseline contract（基线合同）与 resting observability audit（静息期可观测性审计）；
- probe contract repair（探针窗口合同修复/验证）；
- candidate validation（候选指标验证）；
- repeat-visit sensitivity（重复参与敏感性分析）；
- event-response candidates（事件响应候选分析）；
- reference-adjusted models（参考变量调整模型）；
- adjustment audit（调整变量审计）；
- NIR figure pack（图表包）及 adjustment figures（调整模型图）。

`--stage all` 时，整个 runner 的 `execution_manifest.json` / `execution_steps.csv` 执行账本以 `11_analysis_tables` 为 ledger root（执行账本根目录），因此判断整条 `all` 管线是否完成，应优先检查 `11_analysis_tables` 侧的 execution manifest，而不是只看 `10_analysis_ready`。

### `--force-tables` 的边界

当运行：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage all `
  --paths-config "configs/paths.local.yaml" `
  --force-tables
```

`--force-tables` 只允许重新生成 **`11_analysis_tables` 内的派生分析表/审计/图表结果**。它不会触碰 producer 原始 NIR 输出，也不会重新运行 YOLO/RITnet。

## 4. 已有旧派生结果时的正式重跑命令

如果 `10_analysis_ready` 和/或 `11_analysis_tables` 已经存在旧版本结果，并且本轮明确要按当前代码重新生成下游派生结果，使用：

```powershell
python scripts/nir_formal_pipeline.py `
  --stage all `
  --paths-config "configs/paths.local.yaml" `
  --overwrite-derived `
  --force-tables
```

含义严格为：

```text
已有 producer 输出（只读，不动）
    ↓
允许重建 10_analysis_ready
    ↓
允许重建 11_analysis_tables
```

不要把这条命令理解成“重跑 NIR 模型”。它只是重跑下游 materialization（物化）、表构建、审计、统计候选分析和图表。

## 5. 当前正式科学边界

当前 NIR 正式信号语义仍是 pupil geometry（瞳孔几何）为主：

- PIR / pupil-to-iris ratio：禁止作为正式派生；
- iris geometry（虹膜几何）：禁止重新构造；
- `fullclass_ocular_aperture_ratio_median/p90`：可保留为 NIR 眼睛开合 QC（质量控制）候选，但不是 EAR、blink 或 PERCLOS，也不是自动正式 endpoint；
- producer 输出只读；下游缺文件不能自动触发 YOLO/RITnet 重跑。

因此，`--overwrite-derived` 与 `--force-tables` 的安全边界可以概括为：**只覆盖 downstream（下游）派生层，不覆盖 producer（生产提取）层。**
