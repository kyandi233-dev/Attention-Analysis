### 1.1 为什么 `cohort_manifest_115.csv` 不能作为全局 cohort

`mapping/cohort_manifest_115.csv` 的 115 个 `include=true` 与 `rgb_source_map.csv` 的 115 个 `rgb_status=available` 完全一致；它把 `sub-099` 和另外 33 个 RGB 缺失场次标为不纳入。因此它实际表示 **RGB complete-case 子集**，不是模态无关的研究总体。

旧 `mapping/cohort_manifest.csv` 曾把 149 场全部标为 `include=true`，其中 33 场没有当前匿名身份键。2026-08-30 已备份该版本，并将活动 canonical manifest 修正为保留 149 条登记、116 场 `include=true`、33 场 `include=false`。旧 `cohort_manifest_115.csv` 已从活动映射目录移出；为避免不可恢复删除，保存在 `mapping_backup_before_pipeline/cohort_manifest_rgb_available_115_historical_20260830.csv`，不再被任何当前 path key 引用。

正确治理方式是：

```text
模态无关 canonical cohort
  -> session_id / participant_group_id
  -> Behavior availability
  -> NIR availability
  -> RGB availability
  -> mmWave availability
  -> 某项 paired analysis 再显式选择 common-available subset
```

不能因为 `sub-099` 缺 RGB/NIR 就把它从行为总体中删除。`sub-102` 有登记/到场证据但无当前有效问卷；当前 E/J 原始根未发现它的行为 session 目录，因此它保留在 149 条登记全集中并标记 `include=false`，不能补造空问卷或传感器数据。后续若补齐真实行为/传感器场次，应按 session 主表左连接问卷缺失，再重新冻结 cohort 和身份分组。

## 5. 推荐的正式分析流程

### Step 0：冻结 cohort 与路径

输入：背景登记、问卷派生表、重复登记表、各模态 availability。  
动作：建立一个模态无关 canonical cohort；验证 `session_id` 唯一、身份键一致、重复分组正确；修正 `paths.local.yaml`。  
输出：canonical cohort、identity audit、modality availability 表、路径 preflight。  
通过标准：116 个身份已解析场次与 61 个参与者组可追踪；`sub-099` 保留且 NIR/RGB 明确 missing；`sub-102` 保留在 149 条登记全集中，当前因无问卷且 E/J 未发现行为 session 目录而不进入 116 场 governed cohort。

### Step 1：Behavior 单模态

入口：`scripts/sart_formal_analysis.py` + `configs/behavior_formal_v2.yaml`。  
输入：`E:/正式实验`、`J:/Data` 中 B1/B2 原始 CSV，cohort、问卷和重复登记。  
动作：结构验证，生成 trial/probe/cycle/block/session 指标；Go omission 与 No-Go commission 分开；探针使用严格 onset 前 10/20/30 秒窗口；参与者聚类统计和参与者互斥预测分折。  
主要输出：`trial_metrics.csv`、`probe_primary_30s.csv`、`probe_window_sensitivity.csv`、`block_metrics.csv`、`session_metrics.csv`、`participant_disjoint_folds.csv`、模型失败/QC 表、`run_manifest.json` 和结果说明。  
结果边界：先得到行为描述、重复测量推断与行为预测基线；不得把 session 当独立自然人。

### Step 2：RGB 单模态与 RGB×Behavior

入口：`scripts/rgb_formal_downstream.py` + `configs/rgb_formal.yaml`。  
输入：`RGB/raw_union` 的 115 场 raw-first junction；Behavior 真实时间轴。  
动作：冻结 Motion 与曝光变化分轨、Pose 方向/确认、算法定义 Blink 候选；按真实时间形成 probe 前窗口汇总；先做覆盖/QC，再做参与者内/参与者间分解和参与者互斥验证。  
主要输出：已有 `10_analysis_ready`；需要补充冻结的 probe-level RGB feature table、RGB×Behavior matched table、coverage/QC、fold 和模型结果。  
结果边界：当前 Blink 未经人工事件验证，不能称为真值；PERCLOS（percentage of eyelid closure over the pupil over time）未放行。

### Step 3：NIR 单模态与 NIR×Behavior

入口：`scripts/nir_formal_pipeline.py`，依次读取 `nir_analysis_ready.yaml`、`nir_formal_analysis.yaml`、`nir_pipeline_validation.yaml`。  
输入：44+65 场 schema 6/7 topology pupil-only `eye_metrics.csv[.gz]`、真实 `unix_ms`、Behavior 时间轴、刺激视觉属性。  
动作：生成 staged source manifest；物化 pupil-only frame-level 数据与 baseline；建立 trial/probe/time-on-task 表；分离 source、geometry、analysis-domain、uncertainty、temporal QC；审计刺激亮度/对比度混淆。  
主要输出：`NIR/10_analysis_ready/frame_level`、baselines、QC 和 `analysis_ready_manifest.json`；`NIR/11_analysis_tables/sessions`、probe contract、模型失败表、图表/coverage manifest。  
结果边界：正式主信号是 pupil geometry；不得从 iris fraction 重建瞳孔/虹膜直径比，不把 ocular aperture ratio 改名为眨眼或 PERCLOS。

### Step 4：单模态和两两关系冻结

顺序：设计基线 → Behavior 基线 → RGB-only/NIR-only → Behavior+RGB → Behavior+NIR。  
所有比较必须使用相同 outcome、相同参与者分组和显式 matched subset。插补、缩放、特征选择与调参必须只在外层训练参与者内完成。

### Step 5：毫米波独立分析与接入

毫米波 producer、心率/呼吸率、运动/连续性质量控制和正式推断在 `greenboo26/focuswave-multimodal-attention-analysis` 完成。本仓库不复制第二份毫米波算法。接入时只消费版本化 merge-ready 表、真实时间键、QC、availability 和 provenance。

### Step 6：最终多模态

当前 `Attention-Analysis` 没有 production-authoritative fusion runner，状态仍是 `disabled_deferred`。已有的 72 场/46 参与者、1,295 probe 的 Behavior∩NIR∩RGB `PASS_MODEL_READY` 包是 **J 盘阶段性 matched subset**，不是新的 116 场全批次最终结果，且尚未训练正式模型。

后续建议同时保留两类输入：

1. **原始/高频 analysis-ready**：用于重新形成一致时间窗、做 QC 和验证新特征；
2. **冻结的 probe-level 特征**：用于建模，主键为 `participant_group_id, session_id, block_id, probe_id, window_name`，并保留 availability/QC/provenance。

也就是说，不应只保留原始信息，也不应只保留无法追溯的汇总特征；正确策略是“原始/analysis-ready 可追溯 + 冻结窗口特征进入模型”。

建模顺序建议为：Behavior 基线、单模态、两两组合、全模态；再比较正则化拼接、小型多层感知机（multilayer perceptron [MLP]）与质量感知晚期融合。外层采用留一参与者法（leave-one-subject-out [LOSO]），模态权重只能解释模型行为，不能解释为因果贡献。
