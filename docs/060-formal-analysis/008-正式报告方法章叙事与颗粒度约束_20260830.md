# 正式报告方法章叙事与颗粒度约束（2026-08-30）

本文记录分析代码与正式竞赛报告之间的转写约束。它属于分析仓库内部说明，不是正式报告正文。正式报告正文仍只维护在 `kyandi233-dev/FocusWave-Formal-Analysis@codex/code-fix-ledger`。

## 1. 章节级逻辑优先于局部措辞

分析事实转写为报告时先检查整章的信息递进，再处理术语和句式。第 4 章保持“参与者与研究结构 → 实验设计与程序 → 两阶段预实验与正式方案形成 → 正式实验程序与多模态采集 → 数据处理与统计分析”的顺序。同一任务结构、设备参数或统计原则只在主要归属位置完整说明一次。

正式正文不使用“下一节将说明”“后文介绍”等章节导航式元话语。章节通过科学内容自身建立逻辑关系，不用作者提示句串联。

## 2. 预实验结果的正文颗粒度

预实验在方法章中的功能是解释设计决策。正文只保留能够说明为什么选择某个 No-Go 比例、为什么延长 Block、为什么调整刺激序列和思维探针、为什么由 3 个长 Block 收缩为 2 个 Block 的关键方向性观察和极少量代表数字。完整预实验统计放入报告支持材料或附录，不在 4.3 平铺。

`Block` 在正文第一次出现时定义为“任务区块（Block）”，之后直接使用 `Block`。

## 3. 设备与采集信息

4.4 的正文以采集逻辑为主：三种传感通道分别观测什么、如何布置、如何保持条件一致、如何与任务事件建立共同时间参照。设备型号、频段、分辨率、帧率、镜头、工作距离等参数集中到设备与采集参数表，避免在正文段落和表格重复堆叠。

## 4. 算法名称与实现参数分层

正式正文必须保留会改变测量含义或统计解释的算法名称与关键分析参数。当前包括：

- NIR：YOLO26n、RITnet、pupil-only 直接瞳孔几何、视觉属性调整、事件前局部参照；
- RGB：Motion Energy、曝光/亮度变化分离、EAR、方向性姿态候选、眨眼候选；
- mmWave：距离域复数信号、呼吸/心搏相关频段、VMD 等关键分析方法、真实逐帧时间；
- Behavior：反应时与变异、Go omission/No-Go commission、d′/c/β、错误前轨迹和探针前窗口；
- Multimodal：共同探针窗口、共同样本、留一参与者交叉验证和同一外层测试参与者上的增量比较。

纯实现参数主要进入方法附录，例如 NIR 训练轮次、模型输入尺寸和 ROI 尺寸，毫米波滤波器阶数、VMD 内部参数与候选窗口等。代码文档可以保留全部实现细节，但不能要求正式正文按代码字段粒度展开。

## 5. 伦理与样本表述

现有正式报告资料支持参与者阅读实验说明、签署知情同意并在实验后获得报酬。目前没有伦理审批编号、伦理委员会名称或伦理豁免信息，因此报告不得自行生成相应声明。

正式研究总体继续按完整实验资料表述为 63 名参与者、119 次实验；当前已整理的分析子集不替代正式总体。具体结果再按实际分析分母报告。

## 6. 当前来源边界

Behavior、NIR 和 RGB 的代码事实以本分支最新实现为准。毫米波与多模态方法继续只读参考 `greenboo26/focuswave-multimodal-attention-analysis@main` 的最新生产代码和方法审计；本项目不向该外部仓库写报告或治理文件。

RGB 正式报告维持轻量范围：整体运动、曝光/亮度变化控制、必要的姿态确认与方向候选、眨眼候选事件。AU、情绪、rPPG、PERCLOS、复杂 RGB 独立预测不回到正式主线。

## 7. 写作复核要求

每次由代码事实更新正式报告时至少做两遍检查。第一遍确认事实与方法一致；第二遍从整章层面检查章节功能、因果与说明关系、重复、技术细节是否压过研究问题，以及方法是否能与预期结果结构对应。禁用词和工程术语检查放在整章逻辑复核之后完成。
