# 正式多模态 V2：当前路径、样本与单模态分析契约

> 状态：`codex/formal-analysis-v2-portable` 的当前正式下游总入口说明。  
> 新电脑先读仓库根目录 `ANALYSIS_SETUP_FIRST.md`；修复后完整复审见 `009-正式管线修复后完整复审_20260830.md`；逐项排错见 `010-新电脑迁移与常见报错检查表_20260830.md`。  
> 当前正式策略是**先冻结 Behavior、NIR、RGB 各自的单模态分析与 QC，再讨论多模态融合**。历史 adapter/merge scaffold 保留 provenance，但不是当前 production authority。

## 1. 四个必须分开的概念

正式分析不能把以下对象混成一个“样本数”：

1. `session_id`：一次实验/采集场次；
2. `participant_group_id`：正式统计、聚类重抽样和 participant-disjoint prediction 的参与者分组；
3. governed cohort：当前纳入正式分析队列的 session 集合；
4. modality availability：某个 session 的 NIR、RGB、mmWave 是否实际录到、结构有效并可进入该模态分析。

当前 canonical cohort 为 116 sessions / 61 participant groups / 10 个恰好双场组；共有 32 个 participant groups 含重复场次。这是当前 governed queue 的属性，不是永久 study total，也不要求每个模态必须 116/116 可用。

一个已知 participant/session 没录到 RGB、mmWave 或 NIR，只能改变该模态的 availability/QC 状态，不能删除 Behavior 或其他模态中的 session，也不能改变 participant identity。缺失模态禁止填 0 或伪装为 success。

## 3. 配置与机器路径

### 3.1 science config

提交到 Git 的 science config 只保存科学合同、字段口径、QC、时间语义和分析策略，不写当前电脑盘符。

当前公共合同是 `configs/formal_multimodal_v2.yaml`；它不是一个“一键全模态 production runner”。各模态具体执行仍分别读取自己的正式 config。

### 3.2 path registry

机器路径只进入本机：

```text
configs/paths.local.yaml
```

或由：

```text
ATTENTION_ANALYSIS_PATHS_CONFIG
```

指向等价文件。仓库模板 `configs/paths.example.yaml` 当前 version 3；loader 支持 1/2/3，未知未来版本 fail closed。

新电脑至少需要核对：

```text
formal_raw_roots
cohort_manifest
repeat_registry
questionnaire_derived_data
behavior_output_root
nir_analysis_ready_source_manifest_json
nir_analysis_ready_root
nir_analysis_tables_root
stimulus_visual_properties
rgb_raw_output_root
rgb_analysis_ready_root
rgb_analysis_tables_root
```

### 3.3 两个 NIR manifest 不得混用

当前 staged NIR：

```text
nir_analysis_ready_source_manifest_json
-> JSON object
-> sessions[]
```

历史 adapter：

```text
nir_source_manifest
-> CSV
-> legacy nir-adapt only
```

把两者指向同一个文件会产生 JSON/CSV 接口错误。

## 4. Behavior 正式科学合同

Behavior 当前正式入口为 `scripts/sart_formal_analysis.py`，使用 `behavior_formal_v2.yaml` 和共享 path registry。

当前核心口径：

- Go omission 与 No-Go commission 分开建模，使用各自机会数作为分母；
- RT 仅汇总正确 Go 反应；
- 多尺度输出包括 probe / cycle / block / session 等；
- RT 输出 mean、median、SD、MAD、IQR、CV、Theil–Sen slope；
- 输出 d′、criterion c、β；
- probe 主分析严格使用 probe 前试次，不包含锚定 trial，不跨 Block；
- 10/20/30 秒 sensitivity windows 不重复计为独立主样本；
- Q1 为名义四分类，Q2 为有序四等级；
- participant grouping 用于聚类、bootstrap 和 prediction fold；
- model failure 必须写入失败表，不允许空表冒充成功。

问卷/重复登记用于 participant identity 和相关协变量，采用不缩减 governed cohort 的 LEFT JOIN 思路。RGB/mmWave/NIR 是否缺失与 participant identity 是两层不同合同。

## 5. NIR 当前 pupil-only 契约

正式 NIR downstream 的输入是已完成的 fullclass-final / pupil-only 资产；下游统计阶段不自动重跑 YOLO/RITnet。

主链：

```text
fullclass-final source
-> pupil-only contract
-> 10_analysis_ready
-> 11_analysis_tables
-> pupil-only validation
```

正式主信号是 pupil geometry。可靠性不足的 PIR / pupil-to-iris / iris outer geometry 不进入正式 endpoint，也不得从 iris fraction 重建虹膜直径。

### 5.1 OAR 的正确角色

`fullclass_ocular_aperture_ratio_median` / `p90` 来自 visible ocular mask（sclera + iris + pupil）的 height/width，可作为 eye-opening QC candidate 保留。

它们：

- 不是 PIR；
- 不是 iris diameter；
- 不是 MediaPipe EAR；
- 不是 blink event；
- 不是 PERCLOS；
- 当前不自动成为 formal physiological endpoint。

当前正式语义已经拆成：

```text
PIR / iris geometry refused
ocular-aperture QC preserved
ocular-aperture formal endpoint = false
```

旧 `pir_oar_allowed` / `pir_oar_refused` 只可能出现在历史 provenance 资产；权威 package 接口和当前 science config 不再使用这种混合语义。

### 5.2 时间与 QC

NIR 正式对齐使用真实时间，不允许通过 `frame_idx/FPS` 伪造跨模态时间。QC 至少分 source、geometry、analysis-domain、uncertainty、temporal；`RITnet success` 不等于 `pupil geometry valid`。人工 padding 不进入正式科学分母。

## 6. RGB 当前轻量契约

当前权威路线：

```text
preserved RGB producer outputs
-> Motion QC（与 exposure 分轨）
-> optional/nonblocking Pose confirmation/direction
-> independent algorithm-defined Blink candidates
```

PERCLOS、AU、emotion、rPPG、复杂 RGB prediction、Motion/Pose/Blink 综合 risk score 和正式 multimodal fusion 当前 deferred。

如果整个 RGB session directory 缺失，runner 应保留 governed session，并为 Motion/Pose/Blink 写 `not_estimable` / `rgb_source_absent`；如果只缺某个 component 文件，只阻断对应 component。缺数据不能自动触发昂贵 producer。

## 7. mmWave 接口边界

mmWave 的 producer、信号处理和正式分析不在本仓库复制实现。对本项目而言冻结以下接口原则：

- source structural missing = explicit missing/invalid；
- 不填 0；
- 不写成 success；
- 不因 mmWave 缺失缩减 Behavior/NIR/RGB cohort；
- 只有显式 paired multimodal analysis 才构造 common-available subset；
- paired subset 必须同时报告原 governed cohort 与各模态 coverage。

## 8. participant identity 与兼容别名

当前 canonical 统计键为 `participant_group_id`。

- `participant_key`：当前已核验的 questionnaire/repeat-registry participant 来源；
- `repeat_participant_id`：legacy manifest input / provenance / 旧函数边界兼容别名；
- `analysis_group_token`：NIR storage compatibility alias；
- `session_id`：采集场次，不能替代 participant key。

跨模态正式接口必须验证这些别名与 canonical participant partition 的一致性，不能由某一模态是否缺失来重新定义 participant。

## 9. future fusion 的正确边界

当前 fusion 是 `disabled_deferred`。因此现在可以做的是：

- 单模态 feature/QC；
- 每模态 coverage 表；
- identity/key parity；
- 时间接口审计；
- future merge schema 审计。

现在不能声称已经形成正式多模态融合结果。

未来真正执行 paired/complementarity analysis 时，正确逻辑是：

```text
governed cohort
-> modality availability masks
-> explicit common-available subset for that analysis
-> participant-disjoint validation
-> preprocessing inside training folds
-> report coverage + performance together
```

不是先把缺任何模态的 session 从全项目永久删除。

## 11. 证据层级

必须持续区分：

1. code written；
2. synthetic/tests/CI passed；
3. representative real local smoke passed；
4. current governed queue/full run；
5. scientific conclusion。

前一层不能自动推出后一层。特别是 CI 成功不代表所有真实 modality source 都存在，也不代表 44-session 全量或正式科学结果已经产生。
