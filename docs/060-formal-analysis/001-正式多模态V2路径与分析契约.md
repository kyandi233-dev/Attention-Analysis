## 1. 为什么必须重构

旧分析入口同时存在三类耦合：

1. `behavior_formal.yaml`、`nir_behavior_alignment.yaml`、`nir_analysis_ready.yaml` 和 `nir_formal_analysis.yaml` 保存了 D/E/F 盘绝对路径或固定候选根。
2. 旧 NIR analysis-ready/formal 配置以 `iris_outer`、PIR 和 `centered_PIR` 为 primary（主分析）合同，但当前 `fullclass-final` 正式产物已经没有独立虹膜椭圆，不能继续使用 PIR。
3. 旧行为推断以 `subject/session` 为独立分组，无法正确处理重复参加者；当前正式 cohort 必须按 `repeat_participant_id` 聚类、重采样和分折。

因此 V2 不覆盖或删除旧脚本，而是建立新的 canonical（权威）正式入口。历史配置继续用于 provenance（溯源），不得拿历史数值作为当前结果。

## 2. 三层配置结构

### 2.1 科学配置：提交 Git

`configs/formal_multimodal_v2.yaml` 保存行为、NIR、毫米波、RGB 和融合的科学角色、候选指标、时间键、QC 轨道、禁止项、分析单位与 merge key（合并主键），以及重复参与者、分组交叉验证和结果准入规则。这里不允许出现本机盘符，也不硬编码 44、72 等 cohort 大小。

其中 RGB 的当前轻量执行范围以 `configs/rgb_formal.yaml` 为更具体的权威配置；`formal_multimodal_v2.yaml` 中仍存在的历史宽范围字段不得覆盖该轻量合同。

### 2.2 路径注册表：不提交 Git

从 `configs/paths.example.yaml` 复制本机版本为 `configs/paths.local.yaml`。该文件已加入 `.gitignore`。程序通过 `--paths-config configs/paths.local.yaml` 或环境变量 `ATTENTION_ANALYSIS_PATHS_CONFIG` 加载路径。

逻辑路径包括 `formal_raw_roots`、`cohort_manifest`、`repeat_registry`、`nir_source_manifest`、`nir_standardized_root`、`stimulus_visual_properties`、`behavior_output_root`、`rgb_output_root`、`mmwave_output_root`、`fusion_output_root`。换电脑、换硬盘、追加新数据时只改路径注册表，不改 Python 脚本和科学配置。

### 2.3 cohort/source manifest：数据合同，不是代码常量

`cohort_manifest` 至少包含 `session_id, include, repeat_participant_id`。当前 44 场/38 个匿名分析组/6 个双场重复组只是阶段性已整理数据的属性，不能写死进代码，也不能替代完整正式研究样本。未来追加场次后更新 manifest、重新生成统一分组折并重新拟合模型。

`nir_source_manifest` 至少包含 `session_id, status, eye_metrics_csv, schema_version`。每个 session 只能有一个 current authoritative（当前权威）NIR 来源。多候选来源必须先停止并解决，不能按目录顺序静默选择。

## 3. 当前正式行为接口

新入口：

`python scripts/sart_formal_analysis_v2.py --paths-config <本机路径表> --stage preflight`

然后运行 `--stage extract` 和 `--stage metrics`。V2 会在内存中把 `formal_raw_roots` 和 cohort membership（样本成员资格）注入旧 BB 提取骨架，并在输出行上补充 `session_id` 与 `repeat_participant_id`。

旧 `stats.py` 仍是 session-level（场次级）Wilcoxon/AnovaRM/MixedLM，不能作为重复参与者安全的正式推断。因此 V2 默认 `allow_legacy_session_level_stats: false`。正式统计以参与者为聚类、层级和分组验证单位。

正式结局覆盖 trial、probe、block、session 等尺度，包括具有明确分母和最低机会数条件的 d′、c、β、RT-CV、RT slope、Go omission、No-Go commission 和 Q1/Q2。Go omission 的更细时序拆分用于区分反应形成过程，不直接把某一子类命名为“注意遗漏”。

## 4. 当前正式 NIR pupil-only 接口

先运行：

`python scripts/formal_multimodal_analysis.py --paths-config <本机路径表> preflight`

预检通过后可运行：

`python scripts/formal_multimodal_analysis.py --paths-config <本机路径表> nir-adapt`

NIR 适配器按字段名而不是列位置读取，所以允许 schema v6/v7 共存。它要求真实 `unix_ms`，禁止用 `frame_idx / FPS` 伪造跨模态时间；把 `frame_left/frame_right` 仅在内存标准化为 `left/right` 并保留 `eye_raw`；保留 pupil diameter/area/axis、hard/soft pupil fraction；把 source、geometry、analysis-domain、uncertainty、temporal QC 分轨；明确 `RITnet success != pupil geometry valid`；拒绝包含 PIR/`pupil_to_iris`/`centered_PIR` 的历史输入；不从 `hard_iris_fraction`/`soft_iris_fraction` 重建虹膜直径。

### OAR 的正确位置

`fullclass_ocular_aperture_ratio_median/p90` 若生产器明确提供，可以保留为 NIR eye-opening candidate/QC（眼球开口候选/质量控制）。它不是 pupil 指标、不是 MediaPipe EAR、不是 blink event、不是 PERCLOS，也不得从 iris fraction 反推。若当前 source 没有 OAR，V2 明确记录 `unavailable_not_reconstructed`，不会为了兼容旧合同补一个伪 OAR。

## 5. NIR 亮度前置审计

正式 NIR—行为模型之前审计 current/previous stimulus luminance、contrast、size、identity，以及 time-on-task、block、eye、quality coverage。当前视觉属性是数字 sRGB 相对亮度/RMS contrast，不是物理 cd/m² 测量。视觉协变量是 NIR pupil 专属前置混淆审计，不自动加入毫米波/RGB 科学模型。

刺激前瞳孔窗口只允许使用严格发生在该窗口之前的视觉信息；事件相关变化与实验过程中的个体内相对变化使用不同参照。任务开始前 3 min 静息阶段只有在眼部具有足够可观测数据时才作为探索性参考。

## 6. 毫米波与 RGB 如何接入

### 6.1 毫米波

本仓库不复制毫米波 producer。毫米波方法与当前科学边界读取 `greenboo26/focuswave-multimodal-attention-analysis@main` 的最新证据。当前已明确：正式存储是 2T4R、8 通道、256 距离单元的复数距离域数据，距离向变换已在上游完成；逐帧时间应按当前冻结的采集时间语义与任务事件对应。HR、呼吸相关估计与身体运动分开解释，IBI/HRV 在逐搏和外部参考验证不足时不能升级为已验证正式生理指标。

阶段性可加载场次数只属于输入审计，不替代完整正式研究样本，也不能直接升级为最终报告分母。

### 6.2 RGB

RGB 当前权威入口为 `scripts/rgb_formal_downstream.py -> run_rgb_formal_v2()`，具体范围见 `configs/rgb_formal.yaml`。正式轻量路线为：

`Motion Energy + exposure control -> optional/nonblocking Pose confirmation/direction -> independent Blink candidates`

Motion Energy 与画面平均灰度变化保持分离；Pose 提供左右、上下和复合前后方向候选，前后方向不是物理位移真值；Blink 要求左右眼可观测性，并在时间 gap、多脸歧义或主脸追踪切换处中断。PERCLOS 当前关闭，Blink 在独立事件效度验证完成前只称候选事件。

## 7. 跨模态 merge-ready 合同

V2 的统一主键：trial=`repeat_participant_id, session_id, block_id, trial_id`；probe=`repeat_participant_id, session_id, block_id, probe_id, window_name`；block=`repeat_participant_id, session_id, block_id`；session=`repeat_participant_id, session_id`。

运行示例：

`python scripts/formal_multimodal_analysis.py --paths-config <本机路径表> merge-audit --unit block --table behavior=<CSV> --table nir=<CSV>`

任何缺列、空主键、重复主键都会 fail closed。非主键字段在合并时自动加 modality prefix（模态前缀），避免同名列静默覆盖。V2 只合并 row-level（行级）标准化数据；后续追加兼容记录后重新拟合模型，禁止平均两批的 p 值、AUC 或模型系数。

多模态科学比较进一步要求相同参与者、相同探针窗口和相同外层测试划分。具体增量贡献、LOS O/participant-out 设计和复杂融合层级见 `006` 指向的只读方法证据；该设计不等于已经生成正式多模态模型结果。

## 8. 当前科学状态与运行边界

当前分支已经完成 Behavior/NIR 正式下游的主要合同和 RGB 轻量代码收缩，RGB 相关合成测试/CI 已有通过证据；这些证据只证明代码和预设分析合同，不等于真实全量数据已经形成科学结果。

现有阶段性共同样本和参与者独立划分可以证明部分数据已经满足后续建模前提，但不能替代完整研究总体，也不能写成模型已经训练。毫米波仍按外部权威仓库的最新验证边界接入，旧时间语义或旧生理窗口结果不得直接回流为当前正式结果。

因此本分支的职责是保证输入、身份、路径、字段、时间方向、质量定义和跨模态比较条件一致；正式报告中的数值结果必须来自对应真实正式分析产物。

## 9. 最小迁移与运行步骤

1. 复制 `configs/paths.example.yaml` 为本机私有路径表。
2. 准备 current cohort manifest，确保所有用于参与者层推断的 session 有可解析的重复参与者分组。
3. 准备 current NIR source manifest，每个 session 只指向一个权威 fullclass-final eye metrics。
4. 运行 `formal_multimodal_analysis.py ... preflight`。
5. 运行 `sart_formal_analysis_v2.py ... preflight/extract/metrics`。
6. 按 NIR 当前 source manifest 运行 `nir-adapt` 并核验 schema、真实时间、QC 与视觉属性方向。
7. RGB 按 `configs/rgb_formal.yaml` 的轻量入口先做代表性真实数据 smoke，再扩大到 governed cohort；代码/CI 通过不能替代这一步。
8. 毫米波使用外部 producer 的 merge-ready 输出和当前权威时间语义，不在本仓库重建 producer。
9. 各模态输出统一 merge-ready 表后运行相应 merge audit。
10. 只有共同样本、参与者独立分折和模型输入真正冻结后，才运行正式增量/预测模型，并将结果与代码/测试状态分层报告。
