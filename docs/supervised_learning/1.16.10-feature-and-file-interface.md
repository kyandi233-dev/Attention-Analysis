## 1. 总数据流

```text
单模态正式 producer
  │
  ├─ Behavior probe table
  ├─ Ocular / NIR-RGB probe table
  ├─ RGB blink / movement probe table
  └─ mmWave cardiopulmonary probe table
  │
  ▼
Task B quality/admission audit
  ├─ formal_probe_identity.csv
  ├─ modality_probe_status.csv
  ├─ probe_feature_status.csv
  ├─ feature_coverage.csv
  └─ modality_availability.csv
  │
  ▼
Frozen feature registry + comparison spec
  │
  ▼
Task B comparison-specific analysis sets
  ├─ analysis_sets.csv
  └─ analysis_set_summary.csv
  │
  ▼
Task B materialize one analysis_set_id + membership_type
  │
  ▼
Task A wide probe table
  │
  ▼
Task A nested LOSO supervised run
  ├─ OOF predictions
  ├─ fold/failure audit
  ├─ participant/model evaluation
  ├─ paired feature/modality increments
  ├─ trajectory/session diagnostics
  ├─ paired comparison provenance
  └─ run manifest
```

单模态 producer 负责“测量是什么、怎样清洗、能否计算”；Task B 负责“这个比较实际有哪些 probe 可用”；Task A 只负责“在已经冻结的 predictor 和比较特异样本上怎样训练和评价”。三个层次不得互相替代。

## 2. Canonical probe key（标准探针键）

当前 Task B/Task A 的最小标准键由 `multimodal_formal/alignment.py` 冻结为：

| 字段 | 含义 | 要求 |
|---|---|---|
| `session_id` | 正式场次 ID | 非空 |
| `block_id` | `b1` / `b2` | 非空、合法 block |
| `probe_index_in_block` | block 内 probe 序号 | 正整数 |
| `participant_group_id` | 跨场次参与者统计身份 | 非空；同一 session 只能属于一个 group |

正式主窗口为 `window_name = pre_30s`。如果 producer 提供 `probe_event_id`、`probe_time_ms`、`probe_onset_unix_ms` 等字段，必须与 Behavior 权威 probe 元数据一致；Task B/Task A 不重新推导 Q1/Q2 标签。

## 4. Frozen feature registry（冻结特征登记表）

真实 registry 最终写入 `configs/supervised_learning_v1.yaml -> feature_registry.features`。模板见：

`configs/supervised_feature_registry_template_v1.yaml`

每个 feature 至少登记：

| 字段 | 作用 |
|---|---|
| `feature_id` | 当前精确表示的唯一 ID |
| `scientific_feature_id` | 科学维度 ID；用于约束同一维度不能在 Full 中重复表示 |
| `columns` | Task A 实际 predictor 列 |
| `role` | `behavior` / `sensor` |
| `modality` | `behavior / ocular / movement / cardiopulmonary` |
| `feature_type` | 如 `pupil / blink / body_motion / heart_rate` |
| `raw_source` | 实际 producer 文件/数据来源 |
| `source_namespace` | Task B producer 命名空间：`behavior / nir / rgb / mmwave` |
| `required_devices` | 现实生成该特征必须具备的设备 |
| `preprocessing_dependencies` | blink mask、motion correction、sync 等生产依赖 |
| `temporal_anchor` | 首轮固定以 `probe_time_ms` 为预测时点 |
| `temporal_scope` | 正式预测资格固定为 `pre_probe_only` |
| `time_legality_status` | 时间合法性状态 |
| `time_legality_evidence` | 可审计的窗口/producer 证据 |
| eligibility flags | standalone、Behavior+x、modality、Full、leave-one-out 等资格 |
| `allowed_device_packages` | M0–M7 工程设备包资格 |

### 4.1 时间合法性 fail-closed（失败关闭）

任何 feature 只要请求任一正式预测资格，或进入任一 device package（设备包），就必须满足：

```text
temporal_anchor = probe_time_ms
temporal_scope = pre_probe_only
time_legality_status = verified_pre_probe_only
time_legality_evidence != blank
```

候选尚未冻结时可使用：

- `pending_upstream_freeze`
- `blocked_future_information`
- `blocked_temporal_scope_unknown`

但这些状态下全部预测资格必须为 false，`allowed_device_packages` 必须为空。

验证入口：

```powershell
python scripts/validate_supervised_feature_registry.py `
  --config configs/supervised_learning_v1.yaml `
  --paths-config configs/paths.local.yaml
```

该检查只审计 upstream producer 的时间合法性；训练折内插补、标准化、列处理、C 选择仍由 Task A 的 nested LOSO（嵌套留一参与者交叉验证）合同单独管理。

## 5. Task B quality audit 文件接口

`quality_admission.write_quality_audit()` 当前固定写出：

- `formal_probe_identity.csv`
- `modality_probe_status.csv`
- `probe_feature_status.csv`
- `feature_coverage.csv`
- `modality_availability.csv`

### 5.1 `probe_feature_status.csv`

这是 Task B 最核心的长表。每一行表示“一个 probe × 一个 producer predictor”的可用性状态。

必需字段：

| 字段 | 含义 |
|---|---|
| canonical probe keys | `session_id / block_id / probe_index_in_block` |
| `participant_group_id` | 参与者统计身份 |
| `modality` | **历史字段名；当前语义是 producer source namespace，不是科学模态** |
| `feature` | predictor column |
| `value` | 实际数值；可为缺失 |
| `feature_computable` | 当前 probe 是否可直接计算 |
| `eligible_for_missing_strategy` | 是否仅属于允许训练折处理的 residual single-feature missingness（残余单特征缺失） |
| `missing_kind` | 缺失/失败原因类别 |

Task B 还可保留 source、alignment、native QC、mathematical support 等证据列，但不能根据全样本 Q1 关系决定 `feature_computable`。

## 6. Registry → Task B comparison spec 接口

`FeatureComparisonPlan.task_b_comparison_spec()` 生成每个比较的机器可读 spec：

```yaml
models:
  - behavior_reference
  - behavior_plus_modality::ocular
required_features:
  behavior:
    - <frozen_behavior_predictor>
  ocular:
    - <frozen_pupil_predictor>
    - blink_event_rate_per_min
required_feature_records:
  - feature_id: <feature_id>
    scientific_modality: ocular
    source_namespace: nir
    predictor_column: <frozen_pupil_predictor>
required_outcomes:
  - q1_nominal_4class
```

`required_features` 是科学模态 → predictor 的比较合同；`required_feature_records` 是 Task B 实际去哪个 producer namespace 找哪一列的身份合同。两者必须恰好覆盖同一 predictor union（预测变量并集）。

## 7. Task B analysis-set 输出

`write_analysis_sets()` 固定写：

- `analysis_sets.csv`
- `analysis_set_summary.csv`

### 7.1 `analysis_sets.csv`

一行表示“一个 probe × 一个 analysis_set_id”的成员资格。关键字段：

- canonical probe keys + `participant_group_id`
- `analysis_set_id`
- `comparison_models`
- `required_features`
- `required_feature_records`
- `feature_identity_mode`
- `required_modalities`
- `required_outcomes`
- `included_complete`
- `included_missing_aware`
- `missing_feature_n`
- `complete_exclusion_reason`
- `missing_aware_exclusion_reason`

`included_complete` 要求所有比较所需 predictor 均可计算且 Q1 合法；`included_missing_aware` 只允许上游已判为 residual single-feature missingness 的 predictor 缺失。

不同比较拥有不同 `analysis_set_id`。不能把不同共同样本上的 raw performance increment（原始性能增量）直接排行。

## 8. Task B materialized Task-A input

`materialize_supervised_input()` 每次只物化：

```text
一个 analysis_set_id × 一个 membership_type
```

允许的 membership：

- `included_complete`
- `included_missing_aware`

输出为一行一个 probe 的 wide table（宽表）。至少包含：

- canonical probe keys + `participant_group_id`
- `probe_event_id`
- `q1_nominal_4class`
- `analysis_set_id`
- `membership_type`
- `comparison_models`
- `required_features`
- `required_feature_records`
- `feature_identity_mode`
- `required_outcomes`
- 当前比较所需的全部 predictor columns

可附带 `q2_ordinal_4level`、`probe_time_ms`、`probe_onset_unix_ms`、`probe_order_in_block` 等报告/QC 元数据。Q2 不作为首轮 Q1 predictor。

## 9. Task A 正式输出接口

每次 run 写入 `<supervised_output_root>/<run_id>/`。当前固定文件名：

| 文件 | 内容 |
|---|---|
| `probe_predictions.csv` | 所有 outer-test probe 的 OOF（折外）概率与预测 |
| `fold_audits.json` | 每个 model × outer participant 的训练/预处理/失败审计 |
| `failures.csv` | 显式失败折 |
| `participant_log_loss.csv` | participant 等权评价中间表 |
| `model_evaluation.csv` | 模型总体评价 |
| `participant_bootstrap.json` | participant-cluster bootstrap（参与者聚类自助法） |
| `paired_participant_increments.csv` | 成对比较的 participant-level 增量 |
| `paired_model_increments.csv` | 成对模型增量总表 |
| `paired_fold_estimability.csv` | feature/modality 在各 outer fold 是否实际可估 |
| `paired_increment_bootstrap.json` | 成对增量 bootstrap |
| `probe_trajectory.csv` | OOF probe 轨迹 |
| `session_discrimination.csv` | session 层区分诊断 |
| `paired_comparison_provenance.json` | 比较定义、feature/modality/source/device/dependency 溯源 |
| `run_manifest.json` | 全部输入、配置、代码 SHA、比较合同与输出清单 |

正式模型仍固定为 outer participant-disjoint LOSO（外层参与者互斥留一）+ inner grouped 5-fold（内层参与者分组五折）+ participant-equal（参与者等权）训练/预处理/评价。

## 10. 当前哪些字段仍是 placeholder（占位）

框架已经可以冻结，以下内容必须等真实单模态结果后再填，不应现在猜：

1. Behavior RT level 最终是 `go_correct_rt_mean_ms` 还是 `go_correct_rt_median_ms`；
2. pupil 最终 signal（geometry / hard ratio）、cleaning track、blink buffer、bin width、level/variability/dynamic 表示及真实 predictor column；
3. pupil 是否实际需要 RGB，及其真实 `preprocessing_dependencies`；
4. RGB blink/movement 的真实 producer QC 放行状态；
5. HR/BR 的正式生理测量资格；
6. 每个真实 feature 的 `time_legality_evidence`。

这些内容冻结后只回填 registry 和 producer 接线；Task B / Task A 文件结构不再因具体特征选择而重新设计。
