## 0. 术语边界

FocusWave 当前正式监督学习流程**不再使用 Task A / B / C / D 作为方法阶段名**。这些名称来自 1.15 并行实现时期，当前只允许保留在历史 Issue/PR、workflow（工作流）、测试文件、函数名或兼容 API（应用程序接口）中，用于 provenance（来源追踪）和避免无必要的破坏性重命名。

因此，本文件按当前科学与数据语义描述流程。若代码中仍出现 `task_a`、`task_b` 等内部标识，应按本文件对应的语义阶段理解，不能把旧名称恢复成四条独立分析线。

## 1. 当前总数据流

```text
单模态科学特征产出与交接
  │
  ├─ Behavior probe table
  ├─ Ocular / NIR-RGB probe table
  ├─ RGB blink / movement probe table
  └─ mmWave cardiopulmonary probe table
  │
  ▼
probe 级资格、可计算性与来源审计
  ├─ formal_probe_identity.csv
  ├─ modality_probe_status.csv
  ├─ probe_feature_status.csv
  ├─ feature_coverage.csv
  └─ modality_availability.csv
  │
  ▼
Frozen feature registry + comparison spec
  │
  ▼
comparison-specific analysis set（比较特异分析集合）构建
  ├─ analysis_sets.csv
  └─ analysis_set_summary.csv
  │
  ▼
物化一个 analysis_set_id × membership_type
  │
  ▼
监督学习 wide probe table（宽探针表）
  │
  ▼
nested LOSO（嵌套留一参与者交叉验证）训练与评价
  ├─ OOF predictions（折外预测）
  ├─ fold/failure audit（折与失败审计）
  ├─ participant/model evaluation（参与者/模型评价）
  ├─ paired feature/modality increments（成对特征/模态增量）
  ├─ trajectory/session diagnostics（轨迹/场次诊断）
  ├─ paired comparison provenance（成对比较来源追踪）
  └─ run manifest（运行清单）
```

单模态 producer（特征生成程序）负责“测量是什么、怎样清洗、能否计算”；probe 资格审计负责“这个具体比较实际有哪些 probe 可用”；监督学习执行层只负责“在已经冻结的 predictor 和比较特异样本上怎样训练和评价”。三个层次不得互相替代。

## 2. Canonical probe key（标准探针键）

当前最小标准键由 `multimodal_formal/alignment.py` 冻结为：

| 字段 | 含义 | 要求 |
|---|---|---|
| `session_id` | 正式场次 ID | 非空 |
| `block_id` | `b1` / `b2` | 非空、合法 block |
| `probe_index_in_block` | block 内 probe 序号 | 正整数 |
| `participant_group_id` | 跨场次参与者统计身份 | 非空；同一 session 只能属于一个 group |

正式主窗口为 `window_name = pre_30s`。如果 producer 提供 `probe_event_id`、`probe_time_ms`、`probe_onset_unix_ms` 等字段，必须与 Behavior 权威 probe 元数据一致；统一下游接口不重新推导 Q1/Q2 标签。

## 3. 单模态 producer 输入

### 3.1 Behavior

当前正式入口：

`Behavior/formal_v3/probe_primary_30s.csv`

当前正式配置为 116 sessions / 61 participant groups；`go_correct_rt_cv` 的数学最低有效正确-Go 数是 2，不存在旧的 `n>=20` 正式硬门槛。

后续 registry 只从已经冻结的 Behavior reference（行为参照）中取 predictor；RT level 最终使用 mean（均值）还是 median（中位数）由单模态冻结决定。

### 3.2 Ocular / NIR + RGB

当前 1.16 pupil/blink（瞳孔/眨眼）测量审计已完成 G1 技术审计并进入 post-G1 科学交接。最终 predictor 以当前 Ocular science-output handoff（科学输出交接）为准，不再把旧 `NIR/11_analysis_tables/probe_pupil_models/probe_pupil_model_table.csv` 当作 1.16 最终合同。

如果正式 pupil 使用 RGB blink/motion 辅助清洗，科学模态仍为 `ocular`，但 `required_devices` 必须真实记录 `[nir, rgb]`，且对应 RGB 依赖必须单独通过时间合法性审计。

### 3.3 RGB blink / movement

当前科学角色为：

- blink：`blink_event_rate_per_min`，科学模态 `ocular`；
- visible movement（可见动作）：`body_motion_energy_median` 为 Movement 首轮主候选；
- pose lateral/vertical（姿态横向/纵向）为辅助/敏感性；
- radial proximity proxy（径向接近代理）只用于 QC/敏感性，不解释为真实物理位移；
- exposure/coverage（曝光/覆盖）属于 QC/设备支持。

当前 producer 表接口仍可读取：

`RGB/11_analysis_tables_116cohort/rgb_probe_pre30s_features.csv`

真实科学资格以 Movement/Ocular handoff、QC 和人工冻结结果为准。

### 3.4 mmWave cardiopulmonary

当前毫米波上游接口状态为 `MMWAVE_INTEGRATION = READY`，`MMWAVE_INTEGRATION_SNAPSHOT_V1` 是当前可版本化集成资产；这表示接口可以对接，**不代表毫米波科学 predictor 已通过正式时间合法性和生理测量资格**。

旧 merge-ready 接口包括：

- `mmWave/mmwave_probe_merge_ready.csv`
- `mmWave/mmwave_probe_merge_ready_E.csv`

HR（心率）/BR（呼吸率）当前维持 `HOLD / SUPPORTING_ONLY`，HRV（心率变异性）维持 `BLOCKED`。Formal `1.15.8` 记录的 probe 右端排他边界、`window_effective_start_unix_ms` 实际切片语义、`mmwave_hr_usable_window_fraction` 字段语义仍未验证关闭；其中前两项直接阻断依赖该 adapter 的 feature 被标记为 `verified_pre_probe_only`。

因此 snapshot v1 可以用于接口、schema（数据结构）和 supporting integration（支持性集成）验证，但相关 feature 在技术修复和回归证据完成前不得开启正式预测资格。

## 4. Frozen feature registry（冻结特征登记表）

真实 registry 最终写入 `configs/supervised_learning_v1.yaml -> feature_registry.features`。模板见：

`configs/supervised_feature_registry_template_v1.yaml`

每个 feature 至少登记：

| 字段 | 作用 |
|---|---|
| `feature_id` | 当前精确表示的唯一 ID |
| `scientific_feature_id` | 科学维度 ID；约束同一维度不能在 Full 中重复表示 |
| `columns` | 监督学习实际 predictor 列 |
| `role` | `behavior` / `sensor` |
| `modality` | `behavior / ocular / movement / cardiopulmonary` |
| `feature_type` | 如 `pupil / blink / body_motion / heart_rate` |
| `raw_source` | 实际 producer 文件/数据来源 |
| `source_namespace` | producer 命名空间：`behavior / nir / rgb / mmwave` |
| `required_devices` | 现实生成该特征必须具备的设备 |
| `preprocessing_dependencies` | blink mask、motion correction、sync 等生产依赖 |
| `temporal_anchor` | 首轮固定以 `probe_time_ms` 为预测时点 |
| `temporal_scope` | 正式预测资格固定为 `pre_probe_only` |
| `time_legality_status` | 时间合法性状态 |
| `time_legality_evidence` | 可审计的窗口/producer 证据 |
| eligibility flags | standalone、Behavior+x、modality、Full、leave-one-out 等资格 |
| `allowed_device_packages` | M0–M7 工程设备包资格 |

### 4.1 时间合法性 fail-closed（失败关闭）

任何 feature 只要请求任一正式预测资格，或进入任一 device package（设备包），就必须满足：

```text
temporal_anchor = probe_time_ms
temporal_scope = pre_probe_only
time_legality_status = verified_pre_probe_only
time_legality_evidence != blank
```

候选尚未冻结时可使用：

- `pending_upstream_freeze`
- `blocked_future_information`
- `blocked_temporal_scope_unknown`

但这些状态下全部预测资格必须为 false，`allowed_device_packages` 必须为空。

验证入口：

```powershell
python scripts/validate_supervised_feature_registry.py `
  --config configs/supervised_learning_v1.yaml `
  --paths-config configs/paths.local.yaml
```

该检查只审计 upstream producer（上游生成程序）的时间合法性；训练折内插补、标准化、列处理与超参数选择由嵌套 LOSO 训练合同单独管理。

## 5. probe 级资格审计文件接口

`quality_admission.write_quality_audit()` 当前固定写出：

- `formal_probe_identity.csv`
- `modality_probe_status.csv`
- `probe_feature_status.csv`
- `feature_coverage.csv`
- `modality_availability.csv`

### 5.1 `probe_feature_status.csv`

这是 probe 级资格审计的核心长表。每一行表示“一个 probe × 一个 producer predictor”的可用性状态。

必需字段：

| 字段 | 含义 |
|---|---|
| canonical probe keys | `session_id / block_id / probe_index_in_block` |
| `participant_group_id` | 参与者统计身份 |
| `modality` | **历史字段名；当前语义是 producer source namespace，不是科学模态** |
| `feature` | predictor column |
| `value` | 实际数值；可为缺失 |
| `feature_computable` | 当前 probe 是否可直接计算 |
| `eligible_for_missing_strategy` | 是否仅属于允许训练折处理的 residual single-feature missingness（残余单特征缺失） |
| `missing_kind` | 缺失/失败原因类别 |

资格审计还可保留 source、alignment、native QC、mathematical support（来源、对齐、原生质量控制、数学支持）等证据列，但不能根据全样本 Q1 关系决定 `feature_computable`。

## 6. Registry → comparison spec（比较规格）接口

`FeatureComparisonPlan.task_b_comparison_spec()` 是当前仍保留历史内部名字的兼容 API；其**当前语义**是生成比较特异分析集合所需的机器可读规格，不代表仍存在一条“Task B”方法线。

示例：

```yaml
models:
  - behavior_reference
  - behavior_plus_modality::ocular
required_features:
  behavior:
    - <frozen_behavior_predictor>
  ocular:
    - <frozen_pupil_predictor>
    - blink_event_rate_per_min
required_feature_records:
  - feature_id: <feature_id>
    scientific_modality: ocular
    source_namespace: nir
    predictor_column: <frozen_pupil_predictor>
required_outcomes:
  - q1_nominal_4class
```

`required_features` 是科学模态 → predictor 的比较合同；`required_feature_records` 是实际去哪个 producer namespace 找哪一列的身份合同。两者必须恰好覆盖同一 predictor union（预测变量并集）。

## 7. comparison-specific analysis set（比较特异分析集合）输出

`write_analysis_sets()` 固定写：

- `analysis_sets.csv`
- `analysis_set_summary.csv`

`analysis_sets.csv` 一行表示“一个 probe × 一个 analysis_set_id”的成员资格。关键字段包括 canonical probe keys、`participant_group_id`、`analysis_set_id`、`comparison_models`、`required_features`、`required_feature_records`、`required_modalities`、`required_outcomes`、`included_complete`、`included_missing_aware` 以及对应排除原因。

`included_complete` 要求所有比较所需 predictor 均可计算且 Q1 合法；`included_missing_aware` 只允许上游已判为 residual single-feature missingness 的 predictor 缺失。

不同比较拥有不同 `analysis_set_id`。不能把不同共同样本上的 raw performance increment（原始性能增量）直接排行。

## 8. 监督学习输入物化

`materialize_supervised_input()` 每次只物化：

`一个 analysis_set_id × 一个 membership_type`

允许的 membership：`included_complete`、`included_missing_aware`。

输出为一行一个 probe 的 wide table，至少包含 canonical probe keys、`participant_group_id`、`probe_event_id`、`q1_nominal_4class`、`analysis_set_id`、`membership_type`、`comparison_models`、`required_features`、`required_feature_records`、`required_outcomes` 和当前比较所需全部 predictor columns。

可附带 `q2_ordinal_4level`、`probe_time_ms`、`probe_onset_unix_ms`、`probe_order_in_block` 等报告/QC 元数据。Q2 不作为首轮 Q1 predictor。

## 9. 嵌套 LOSO 监督学习输出接口

每次 run 写入 `<supervised_output_root>/<run_id>/`。当前固定文件名：

| 文件 | 内容 |
|---|---|
| `probe_predictions.csv` | 所有 outer-test probe 的 OOF 概率与预测 |
| `fold_audits.json` | 每个 model × outer participant 的训练/预处理/失败审计 |
| `failures.csv` | 显式失败折 |
| `participant_log_loss.csv` | participant 等权评价中间表 |
| `model_evaluation.csv` | 模型总体评价 |
| `participant_bootstrap.json` | participant-cluster bootstrap（参与者聚类自助法） |
| `paired_participant_increments.csv` | 成对比较的 participant-level 增量 |
| `paired_model_increments.csv` | 成对模型增量总表 |
| `paired_fold_estimability.csv` | feature/modality 在各 outer fold 是否实际可估 |
| `paired_increment_bootstrap.json` | 成对增量 bootstrap |
| `probe_trajectory.csv` | OOF probe 轨迹 |
| `session_discrimination.csv` | session 层区分诊断 |
| `paired_comparison_provenance.json` | 比较定义、feature/modality/source/device/dependency 溯源 |
| `run_manifest.json` | 全部输入、配置、代码 SHA、比较合同与输出清单 |

正式模型固定为 outer participant-disjoint LOSO（外层参与者互斥留一）+ inner grouped 5-fold（内层参与者分组五折）+ participant-equal（参与者等权）训练/预处理/评价。

## 10. 当前仍待真实冻结的字段

框架已经冻结，以下内容必须等真实单模态结果后再填：

1. Behavior RT level 最终是 mean 还是 median；
2. pupil 最终 signal（geometry / hard ratio）、cleaning track、level/variability/dynamic 表示及真实 predictor column；
3. pupil 最终是否实际需要 RGB，及其真实 `preprocessing_dependencies`；
4. RGB blink/movement 的真实 producer QC 与人工冻结状态；
5. HR/BR 的正式生理测量资格及毫米波 adapter 时间合法性；
6. 每个真实 feature 的 `time_legality_evidence`。

这些内容冻结后只回填 registry 和 producer 接线；probe 资格审计、比较特异分析集合、输入物化和嵌套 LOSO 训练评价的文件结构不再因具体特征选择重新设计。
