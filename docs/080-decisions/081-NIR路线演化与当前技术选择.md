# 081｜NIR 路线演化与当前技术选择

## 决策目的

本文件不是按日期重复工作记录，而是把已经发生的关键技术选择串成一条“为什么最后形成当前路线”的决策链。原始实验过程、失败样本、参数尝试和阶段性判断仍以 `docs/工作记录/` 为准。

当前正式 NIR 路线为：

```text
NIR video
    ↓
自训练 YOLO26n eye detector
    ↓
周期性重新检测 + tracking
    ↓
单眼 ROI
    ↓
RITnet
    ↓
时序 QC / 指标输出
```

## 决策 1：不继续把完整人脸检测作为双眼特写 ROI 的前置条件

早期方案依赖 MediaPipe FaceLandmarker、YuNet、YOLO-face 等完整人脸检测器，再从人脸关键点或人脸框派生眼睛 ROI。这条路线在完整脸画面上具有合理性，但正式 NIR 数据同时存在双眼特写输入；在特写条件下，多个完整人脸后端发生系统性失检或错误检测。

关键问题不是某个 `corner_span`、置信度或简单尺度参数没调好，而是**输入域与模型任务不匹配**：模型期待完整人脸，正式特写画面却可能只包含眼睛及局部面部结构。

因此后续决策从“继续调完整人脸 detector”转为“直接检测 eye bbox”。历史 full-face 路线继续保留，用于解释为什么被淘汰，而不再作为当前正式入口。

## 决策 2：从通用 eye/face-parts 候选转向 NIR 专用自训练 eye detector

face-parts 等候选能够直接检测眼部区域，解决“不依赖完整人脸”的结构问题，但其训练域主要是普通 RGB 图像，与正式 NIR 特写存在明显域差。

为了让 ROI detector 的训练分布更贴近正式数据，项目最终建立 `datasets/nir-eye-dataset-v1/`，使用正式 NIR 视频抽帧并人工标注单类 `eye` bbox，再用被试级 train/val/test 训练 YOLO26n。

选择 NIR 专用 detector 的核心理由是：

- 输入域与正式视频一致；
- 任务定义直接对应后续单眼 ROI；
- 不再依赖完整人脸是否可见；
- 可以通过独立 held-out 被试 test 量化泛化性能。

最终 YOLO26n 100 epochs 训练完成，冻结 test 记录 mAP50=0.9913、mAP50-95=0.6589，支持进入后续视频处理。

## 决策 3：YOLO 负责定位，不把 bbox 当作瞳孔测量

YOLO 的目标是输出 eye bbox。它不能回答 ROI 内哪些像素属于 pupil，也不能用 bbox 尺寸替代瞳孔直径。因此正式结构采用两级模型：

```text
YOLO → spatial localization
RITnet → pixel-level segmentation
```

这使 ROI 检测误差和瞳孔分割误差可以分轨记录，也避免把“眼睛框得准”误写成“瞳孔测得准”。

## 决策 4：保留 RITnet 作为当前分割模型

项目早期比较和调研过 PuRe、PuReST、DeepVOG、Iris 等多条瞳孔/眼部路线。不同方法对输入定义、输出语义和运行环境要求不同，例如 Iris 更接近虹膜关键点语义，PuRe/PuReST 属于传统/几何检测路线，DeepVOG 有独立深度学习依赖。

当前 portable runtime 最终封装的是 RITnet。RITnet 能直接对标准化单眼 ROI 输出像素级类别，并由 pupil mask 进一步拟合椭圆、中心和等效直径，和“YOLO 只负责定位”的两级结构匹配。

这不意味着历史算法比较没有价值。相关代码与工作记录继续保留，用于方法选择 provenance 和后续敏感性分析。

## 决策 5：增加 tracking 是计算优化，不是替代检测

一百多名被试、单段约 25 分钟的视频意味着逐帧 YOLO 会形成较大计算量。连续视频中眼睛位置具有时间连续性，因此引入 tracking，让中间帧用较轻量的位置更新，周期性或异常时再用 YOLO 校正。

该决策的原则是：

```text
YOLO = 定位锚点 / 纠偏
tracking = 中间帧计算优化
```

而不是：

```text
首次 YOLO 后永久相信 tracker
```

portable runtime 支持 CSRT/KCF，并在 tracker 失败、bbox 非法或中心异常跳变时立即回退 YOLO。这种设计把速度优化限制在可回退框架中。

## 决策 6：不把 portable package 默认参数直接改称最终全量冻结参数

2026-08-22 的 `runtime/nir-yolo-tracking-ritnet-v1/` 在建立时定位为 GPU 短视频准入 package，默认配置包括 CSRT、10 帧重检测、ROI expansion 等。后来项目已经完成正式全量运行，但当前 Git 分支没有保存那次 full-run 的最终 `run_manifest.json` 或 08-22 之后的 committed 工作记录。

因此整理时采用保守决策：

- 可以把完整实现路径、模型身份和 package 默认值写清楚；
- 可以确认项目已经完成全量；
- **不能因为当前只找到这个 package，就推断 package 默认值一定等于 full-run 最终值。**

这样做是为了避免仓库整理反过来制造伪 provenance。

## 决策 7：冻结包不拆、不直接重写

portable runtime 同时保存目录版本、ZIP、ZIP SHA256 和 package 内 `SHA256SUMS.txt`。如果为了让 README 看起来“最新”而直接改写 package 内文件，就会破坏原冻结资产与 checksum 的一致性。

因此当前选择是：

- package 内部保持 2026-08-22 原状；
- 当前状态与历史边界写在 `runtime/README.md`；
- `src` 不强行吸收该 frozen package；
- 若未来开发 v2 runtime，应新建明确版本，而不是静默修改 v1。

## 决策 8：历史候选代码和记录继续保留

当前路线已确定不等于历史路线“无用”。MediaPipe、YuNet、YOLO-face、face-parts、PuRe/PuReST、DeepVOG、Iris、Gate1、benchmark、sequence 等资产可以回答：

- 为什么换路线；
- 哪类输入导致前一方案失败；
- 当时比较了什么；
- 哪个历史 artifact 如何生成；
- 某个结果是否受到方法选择影响。

因此仓库整理采用“标清角色而不是删除”的原则。任何真正的文件删除仍需单独确认。

## 当前仍未闭合的决策证据

以下项目需要等找到实际 full-run 原始记录后再冻结：

- 正式全量最终 tracker；
- 正式全量最终重检测频率；
- 正式 ROI expansion；
- RITnet 最终门控与拒绝标准；
- 最终 GPU / 软件环境；
- 最终时序插值和汇总参数；
- 正式 full-run 的 run manifest / 输出版本。

这些项目当前标记为“provenance 待补”，而不是重新进入“生产尚未开始”状态。项目阶段已经完成，缺的是仓库中的复现证据，不是分析本身没有做。
