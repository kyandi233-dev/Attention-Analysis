# NIR 专用 YOLO 眼框训练计划

## 2026-08-21 执行状态更新

> 2026-08-21 17:30（Asia/Shanghai）｜北京已完成一百多名正式被试采集；眼框模型已在 AMD RX 6750 GRE 电脑上启动 CPU 训练，计划为 100 epochs。

- 当前任务是眼睛 ROI 检测器训练，不是正式视频全量提取。
- 训练完成后，权重将保留训练记录、数据集 split、环境版本和验证结果，再考虑转移到 NVIDIA 电脑。
- 正式视频路线已改为 `YOLO + tracking + RITnet`。PuReST 保留为传统算法比较/备用路径，不再作为当前唯一的正式下游假设。
- tracking 方法、YOLO 重新检测间隔、失败重置条件和 RITnet 参数，须在珠海先用短视频进行速度与连续性基准测试。

> 2026-08-17 Asia/Shanghai｜目的：为非全脸 NIR 画面训练一个只识别 `eye` 的眼部 ROI 检测器；本文件只保留当前需要实施的步骤，Causa 等文献中的像素级虹膜/瞳孔分割作为后续参考，不在本轮实施。

## 1. 参考方法与本项目取舍

Causa 等人的流程是：Eye-tiny-YOLO 检测左右眼 → MIL/CSRT 跟踪 → CCNet 分割虹膜和瞳孔 → 时间序列特征。我们采用其“专用 NIR 眼框检测 + 连续跟踪”的思路，但将检测器换成现代 YOLO11n，并以 YOLOv8n 作为对照。

本项目暂不复现 CCNet：它需要像素级虹膜、瞳孔和巩膜掩码，标注成本远高于眼框；当前 PuRe/PuReST 已经承担瞳孔检测，因此先解决 ROI 定位瓶颈。

## 2. 必须完成的步骤

### 步骤 A：建立离线标注集

1. 从正式 NIR 视频中抽取代表性帧，不使用所有连续帧。
2. 覆盖全部被试和困难画面：双眼特写、混合画面、暗图、过曝、反光、闭眼/半闭眼、头部移动、MediaPipe 失败帧。
3. 每张图给两只眼画矩形框，类别只设为 `eye`；不标瞳孔圆，也不标左右眼两个类别。
4. 保留原图、YOLO 标签、抽样清单和标注版本。

第一轮目标：约 300–500 张图，全部被试均有样本。若第一轮模型在困难画面漏检，再追加 200–400 张困难帧。

### 步骤 B：按被试划分数据

不能随机按帧划分，否则相邻帧会同时出现在训练和测试中，结果会虚高。

建议：

- train：约 70% 被试；
- val：约 15% 被试；
- test：约 15% 被试。

每个集合都要记录 subject、video、frame_idx、画面类型和标注版本。

### 步骤 C：训练两个对照模型

使用同一套图片、同一划分、同一评价指标，分别训练：

- YOLO11n：主候选；
- YOLOv8n：兼容性和性能对照。

输入图像为 NIR 灰度复制成 3 通道。输入尺寸优先测试 `imgsz=1280`；若显存或速度不足，再比较 `imgsz=960`。

第一轮只训练单类目标：

```yaml
names:
  0: eye
```

### 步骤 D：评价眼框和 ROI，而不是只看 mAP

必须输出：

- 双眼检测率；
- 单眼检测率；
- 漏检率；
- 假眼框率；
- 两框重叠率；
- 每名被试的检测率；
- 裁剪后瞳孔是否在 ROI 内；
- ROI 中 PuReST 有效检测率；
- 连续帧直径跳变、中心跳变和恢复时间。

最终模型必须在未参与训练的被试上验证。若 YOLO11n 的 mAP 较高但下游 PuReST 更差，应按下游结果选择模型。

### 步骤 E：接入连续处理

第一版先每帧运行 YOLO，确认正确性后再做速度优化：

```text
YOLO 检测眼框
    ↓
按横坐标排序为左右眼
    ↓
按固定比例扩展眼框
    ↓
裁剪并缩放为标准单眼 ROI
    ↓
PuRe/PuReST
```

如果每帧检测太慢，再加入 CSRT 或其他跟踪器：每 5–10 帧重新 YOLO 检测，中间帧跟踪；跟踪失败、框跳变或质量下降时立即重新检测。

## 3. 停止条件

在以下条件满足前，不冻结为正式 ROI：

1. 测试被试上双眼检测率达到预设门槛；
2. 没有持续性假眼框或两个框严重重叠；
3. 眼框扩展后的 ROI 能稳定覆盖瞳孔；
4. PuReST 下游有效率和连续性不低于当前可用方案；
5. 所有训练、验证、测试清单和权重均已保存。

## 4. 暂不实施但保留的参考

CCNet 像素分割只有在“YOLO 眼框 + PuReST”仍不能满足质量要求时再考虑。届时需要重新标注单眼图像中的虹膜、瞳孔和巩膜掩码，不能用现在的眼框标签代替。
