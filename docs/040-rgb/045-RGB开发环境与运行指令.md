总控直接调用两个环境各自的 `python.exe`，不要求你手动在阶段之间切环境。

### 当前正式流程：raw-first + 三线并行

```text
1. 快速准备 Face 15 Hz 帧清单

2. 同时启动三条独立分析：
   Motion：原视频全帧率 OpenCV 帧差
   Pose：10 Hz MediaPipe Pose landmarks
   Face：15 Hz Py-Feat DirectML
         RetinaFace batch = 8
         multitask batch = 16

3. 三条 raw 都结束后做完整性检查
   → sub-XXX_manifest.json
```

三条分析会分别读取同一个 RGB AVI，但相互之间没有数据依赖，因此不再串行等待。运行时终端每 15 秒打印一次三条进程的状态；详细 stdout/stderr 保存在：

```text
D:\_AttentionData\Beijing-RGB\sub-XXX\_runlogs\
```

正式 raw 完成标准只有：

```text
sub-XXX_motion_raw.parquet
sub-XXX_motion_manifest.json

sub-XXX_pose_landmarks.parquet
sub-XXX_pose_manifest.json

sub-XXX_face_raw.parquet
sub-XXX_face_raw_manifest.json
```

最终 `sub-XXX_manifest.json` 中：

```text
completion_status = complete
extraction_complete = true
```

表示本次不可恢复/昂贵的 RGB 原始提取已经完整完成，不等于 QC 通过。

## 5. cohort 全量运行

单被试新并行流程验收后：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_rgb_formal_cohort.ps1
```

cohort runner 会先刷新 `rgb_inventory.csv`，只处理 `analysis_eligible=True` 的正式被试，然后逐人调用单被试并行总控。

它会自动：

```text
已有完整 manifest → skip
未完成 → run
某一 raw 分支已完成 → 对应分支自动 skip
单个被试失败 → 写入 cohort_status.csv，继续下一人
全部结束 → 写 cohort_manifest.json
```

只跑指定被试：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_rgb_formal_cohort.ps1 `
  -Subjects sub-031,sub-032,sub-033
```

进度文件：

```text
D:\_AttentionData\Beijing-RGB\cohort_status.csv
D:\_AttentionData\Beijing-RGB\cohort_manifest.json
```

## 6. `-Force`

正常全量不要使用 `-Force`。已有完整 raw 会自动跳过；partial output 会停止，避免静默覆盖。

只有你明确检查过现有结果并决定重跑时，才使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_rgb_formal_subject.ps1 `
  -Subject sub-031 `
  -Force
```
