### 当前 Face 正式优化

`sub-032` 基准表明 Face 是总墙钟瓶颈，因此正式 Face runner 已做以下优化：

```text
RetinaFace batch: 8 -> 16
Py-Feat multitask batch: 16 -> 32
prefetch batches: 3
CPU RetinaFace postprocess inflight: 2

最终检测阈值仍为 0.5
但将 0.5 前置到 bbox / 5点关键点 decode 和 NMS 之前
→ 不再为大量低分 anchor 做无意义 CPU 解码

RetinaFace DirectML batch N
与
CPU decode / NMS / crop batch N-1
流水重叠
```

这不改变正式 15 Hz 采样率，也不改变最终 0.5 检测口径。

### 当前已验证路径：三线独立并行

```text
1. 快速准备 Face 15 Hz 帧清单

2. 同时启动：
   Motion：原视频全帧率 OpenCV 帧差
   Pose：10 Hz MediaPipe Pose landmarks
   Face：15 Hz Py-Feat DirectML

3. 三条 raw 都结束后做完整性检查
   → sub-XXX_manifest.json
```

运行时终端每 15 秒打印一次进程状态；详细 stdout/stderr：

```text
D:\_AttentionData\Beijing-RGB\sub-XXX\_runlogs\
```

## 4. 单次视频解码实验模式

为继续减少同一 AVI 被 Motion / Pose / Face 分别解码造成的重复开销，新增：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_rgb_formal_subject.ps1 `
  -Subject sub-033 `
  -SharedDecode
```

该模式结构：

```text
一个 OpenCV reader 只顺序解码原 AVI 一次
        │
        ├─ 每帧：Motion full-fps
        │
        ├─ 10 Hz：送 Pose 后台线程
        │
        └─ 15 Hz：以无损 raw BGR 字节送 DirectML Face 子进程
```

Face 不走 JPEG / PNG 临时文件，不改变像素值。因为 `attention-rgb` 与 `attention-face-directml` 仍然保持两个 Conda 环境，所以 Face 使用本机进程管道接收 raw BGR，而不是强行合并环境。

**注意：`-SharedDecode` 当前属于实机验收模式。** 在代表被试完成速度和输出 parity 检查前，不默认用于 44 人 cohort。原来的三进程并行路径继续保留作为 fallback。

## 5. 正式 raw 完成标准

只有以下昂贵/原始层文件是 extraction completion 的必要条件：


最终 `sub-XXX_manifest.json`：

```text
completion_status = complete

```

表示 RGB 原始提取完整，不等于 QC 通过。

## 7. cohort 全量运行

单被试优化版本验收后：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_rgb_formal_cohort.ps1
```

cohort runner 会先刷新 `rgb_inventory.csv`，只处理 `analysis_eligible=True` 的正式被试。已有完整 manifest 自动跳过；某一 raw 分支已完成时，该分支自动 skip。

当前在 `-SharedDecode` 完成代表被试 parity / speed 验收前，cohort 仍使用已验证的三进程并行模式。

## 8. `-Force`

正常全量不要使用 `-Force`。已有完整 raw 会自动跳过；partial output 会停止，避免静默覆盖。

只有明确检查并决定重跑时才使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_rgb_formal_subject.ps1 `
  -Subject sub-033 `
  -Force
```

## 9. 当前原则

先把 44 人的 Motion / Pose / Face raw 完整落盘。任何能从 raw 重建的 tracking、blink、PERCLOS、Pose features 和统计指标全部后移。速度优化优先保持同一正式采样率、同一模型和同一最终检测阈值，不用降低科学信息量换速度。
