# 045｜RGB开发环境与运行指令

RGB 开发当前使用同一个 `rgb-dev` worktree，但不同 Python backend 必须使用不同 Conda 环境。**Git 分支/工作目录与 Conda 环境是两件独立的事。**

## 统一工作目录与分支

RGB 开发仓库根目录：

```text
D:\aaawork\07-竞赛\厚璨杯\021-analysisplan\Attention-Analysis-rgb-dev
```

该 worktree 应保持在：

```text
rgb-dev
```

进入目录并确认：

```powershell
cd "D:\aaawork\07-竞赛\厚璨杯\021-analysisplan\Attention-Analysis-rgb-dev"
git branch --show-current
git status --short --branch
git pull --ff-only
```

`git pull` 与 Conda 环境无关；只要当前目录是这个 Git worktree 就可以拉取代码。

## 环境矩阵

| 环境 | Python | 用途 | 典型命令 |
|---|---|---|---|
| `D:\CondaEnvs\attention-rgb` | 3.11 | 主 RGB pipeline、audit、Motion、Pose、QC、Face sample/Py-Feat QC | `python scripts/rgb_analysis.py ...` |
| `D:\CondaEnvs\attention-face-pyfeat` | 3.11 | Py-Feat Detectorv2 官方候选推理 | `python scripts/face_benchmark_pyfeat.py ...` |
| `D:\CondaEnvs\attention-face-libreface` | 3.9 | LibreFace 2.0 官方候选推理 | `python scripts/face_benchmark_libreface.py ...` |

### 主 RGB 环境

```powershell
conda activate "D:\CondaEnvs\attention-rgb"
cd "D:\aaawork\07-竞赛\厚璨杯\021-analysisplan\Attention-Analysis-rgb-dev"
```

该环境安装了本项目 `attention_pipeline` 包，所以 `scripts/rgb_analysis.py` 应在这里运行，例如：

```powershell
python scripts/rgb_analysis.py --stage pose-qc --subject sub-031
python scripts/rgb_analysis.py --stage pose-features --subject sub-031
python scripts/rgb_analysis.py --stage face-sample --subject sub-031
python scripts/rgb_analysis.py --stage face-pyfeat-qc --subject sub-031
```

不要在候选模型独立环境中运行 `rgb_analysis.py`，否则该环境未安装 `attention_pipeline` 时会出现：

```text
ModuleNotFoundError: No module named 'attention_pipeline'
```

### Py-Feat 独立环境

```powershell
conda activate "D:\CondaEnvs\attention-face-pyfeat"
cd "D:\aaawork\07-竞赛\厚璨杯\021-analysisplan\Attention-Analysis-rgb-dev"
```

只运行独立候选 runner：

```powershell
python scripts/face_benchmark_pyfeat.py `
  --benchmark-dir "D:\_AttentionData\Beijing-RGB\_test\face-benchmark\sub-031" `
  --batch-size 8 `
  --device cpu
```

### LibreFace 独立环境

```powershell
conda activate "D:\CondaEnvs\attention-face-libreface"
cd "D:\aaawork\07-竞赛\厚璨杯\021-analysisplan\Attention-Analysis-rgb-dev"
```

只运行独立候选 runner：

```powershell
python scripts/face_benchmark_libreface.py `
  --benchmark-dir "D:\_AttentionData\Beijing-RGB\_test\face-benchmark\sub-031" `
  --batch-size 32 `
  --num-workers 0 `
```

这些 standalone runner 刻意不依赖 `attention_pipeline`，避免为了候选模型 benchmark 把 Py-Feat/LibreFace 的依赖装进主 RGB 环境。

## 数据输出位置

Conda 环境只决定“用哪套 Python/模型依赖运行”，不会改变数据位置。所有 RGB pilot/benchmark 当前仍写入：

```text
D:\_AttentionData\Beijing-RGB\_test\
```

Face 共同 benchmark 输入与候选输出位于：

```text
D:\_AttentionData\Beijing-RGB\_test\face-benchmark\sub-031\
```

## 快速判断当前该用哪个环境

- 命令里是 `scripts/rgb_analysis.py` → **`attention-rgb`**；
- 命令里是 `face_benchmark_pyfeat.py` → **`attention-face-pyfeat`**；
- 命令里是 `face_benchmark_libreface.py` → **`attention-face-libreface`**；
- Git `pull/status/branch` → Conda 环境不重要，但必须在正确 worktree 中。

候选环境只负责模型推理；模型输出生成后，尽量切回 `attention-rgb` 做 QC、合并和正式 pipeline 开发。
