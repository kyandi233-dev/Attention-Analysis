# 410｜RGB 当前状态与全量执行总结（2026-08-26）

> 本文件是 RGB 工作线的**当前状态快照**，用于记录已经完成的实现、实机验证、当前正式参数、AMD/NVIDIA 两端差异以及仍待完成的工作。长期稳定的方法、算法与参数依据见 [`049-RGB正式分析方法与参数依据.md`](049-RGB正式分析方法与参数依据.md)。

## 1. 当前总体结论

RGB 正式主线已经收口为 **Face + Pose + Motion 的 raw-first 全量提取**。正式分析范围统一为 **baseline 开始连续至 Block2 结束**，包括 instructions、practice、transition、inter-block transition 等中间阶段；所有模态均保存真实时间戳和帧身份，以便后续与 Behavior / NIR 对齐。

当前正式时间分辨率：

| 模块 | 正式时间分辨率 | 当前算法 |
|---|---:|---|
| Motion | 原视频 full FPS（当前视频约 30 fps） | OpenCV 相邻灰度帧差 |
| Face | timestamp-driven 15 Hz | Py-Feat 2.1.1 Detectorv2 scientific core |
| Pose | timestamp-driven 10 Hz | MediaPipe Pose Landmarker Lite |

三类频率属于测量设计，不按被试或硬件临时改变。Motion 使用 full FPS 是因为相邻帧差本身就是测量定义；Face 15 Hz 用于兼顾 AU / gaze / head pose 与短时眼睑、blink、PERCLOS 信息；Pose 10 Hz 面向坐姿条件下相对较慢的头肩与姿态变化。

## 2. 当前正式数据流

```text
RGB AVI + RGB timestamps + master_timeline + Behavior
                       ↓
             正式分析时间范围定位
                       ↓
              Face 15 Hz 帧清单
                       ↓
     ┌─────────────────┼──────────────────┐
     │                 │                  │
Motion full FPS     Pose 10 Hz        Face 15 Hz
OpenCV              MediaPipe          Py-Feat
     │                 │                  │
     └─────────────────┼──────────────────┘
                       ↓
              raw-only validator
                       ↓
             sub-XXX_manifest.json
                       ↓
             downstream derived / QC
```

正式默认使用 **Motion / Pose / Face 三条独立 reader 并行**。实验性 SharedDecode 已在 AMD 侧实机测试；当前测试没有显示出墙钟时间优势，因此不作为正式 cohort 默认路径。

## 3. AMD 当前正式实现

分支：`rgb-amd`。

Windows AMD GPU 不使用 CUDA。Face 采用 **Py-Feat 模型的 DirectML port**，并没有替换成另一套人脸检测器：

```text
RGB frame
→ Py-Feat RetinaFace R34 ONNX
→ score / bbox / 5-point decode / NMS / square crop
→ Py-Feat multitask scientific core ONNX
→ AU / emotion / valence-arousal / gaze / head pose / 478 mesh / blendshape
→ face_raw.parquet
```

执行后端：`ONNX Runtime + DmlExecutionProvider`。

当前 Face 正式配置：

| 参数 | 当前值 | 类型 |
|---|---:|---|
| Face sampling | 15 Hz | 科学参数 |
| detection threshold | 0.5 | 科学/检测规则 |
| NMS threshold | 0.4 | 检测后处理规则 |
| RetinaFace batch | 32 | 性能参数 |
| multitask batch | 64 | 性能参数 |
| prefetch batches | 3 | 性能参数 |
| CPU postprocess inflight | 2 | 性能参数 |

RetinaFace `<0.5` 候选在 bbox / landmark decode 与 NMS 前提前剔除，用于减少低分 anchor 的无效计算；最终保留规则仍为 `score >= 0.5`。reader prefetch 与 CPU/GPU overlap 只改变执行调度，不改变采样与科学输出。

### AMD 实机状态

三线并行 raw 主链已经通过 full-span validator。`sub-036` 正式结果：

```text

qc_pass = null
issues = []
warnings = []
```

`sub-036` 当前 raw 规模：

| 输出 | 行数 |

| Face frame schedule | 24,425 |

| Motion raw | 48,848 |

Face raw 行数高于 Face schedule 属正常情况，因为 multi-face 时同一采样帧会保留多个人脸行。AMD cohort runner 已进入正式使用状态，支持 audit、eligible discovery、完整被试 skip、单 raw branch resume、失败记录后继续，以及持续更新 `cohort_status.csv` / `cohort_manifest.json`。

## 4. NVIDIA 当前正式实现

分支：`rgb-nvidia`。

NVIDIA Face 不复制 AMD 的 ONNX executor，而直接使用 Py-Feat 2.1.1 native PyTorch CUDA：

```python
Detectorv2(device="cuda", identity_model=None)
→ detector.detect(..., data_type="tensor", face_detection_threshold=0.5)
```

NVIDIA formal runner 强制：

```text
torch.cuda.is_available() == True
execution_backend = pytorch_cuda
device = cuda / cuda:<index>
```

不允许 silent CPU fallback。

native Detectorv2 对外只有一个端到端 CUDA batch，因此 AMD 的 `RetinaFace B32 + multitask B64` 不能机械翻译成 NVIDIA 的两个 batch。NVIDIA 当前默认 `native_cuda_batch=16`，候选为 `16 / 32 / 64`；应在 RTX 5070 上依据 throughput、peak VRAM 与稳定性冻结最终值。batch 是性能参数，不改变科学定义。

### NVIDIA 当前 Gate

正式 NVIDIA cohort 启动前仍需完成：

1. `sub-130` full-span Motion / Pose / Face raw；
2. final validator；
3. stable nullable Parquet schema regression test；
4. native CUDA batch 16 / 32 / 64 的吞吐与峰值显存记录；
5. representative native Py-Feat ↔ AMD DirectML backend parity。

## 5. AMD 与 NVIDIA 的科学可比性

两端保持同一 scientific contract：

```text
Py-Feat 2.1.1 scientific core
Face sampling = 15 Hz
Face detection threshold = 0.5
identity_model = None
所有 detected faces 保留
no-face planned sample 保留
统一 video_frame_position / capture_frame_idx / unix_ms
统一正式分析时间范围
```

AMD 与 NVIDIA 不要求底层代码逐行相同。AMD 是 ONNX Runtime DirectML，并自行连接 RetinaFace 与 multitask core；NVIDIA 是 native Detectorv2 / PyTorch CUDA。正式跨平台合并前应使用完全相同的代表帧进行 parity，包括检测一致率、bbox IoU、AU、emotion、gaze、head pose、478 mesh 与 blendshape 数值差异。

## 6. 当前 raw 保存内容与可回溯性

### Face raw

当前保存：

- `video_frame_position`、`capture_frame_idx`、`unix_ms`；
- phase / block / trial / probe / behavior context；
- 所有 detected faces 与 no-face placeholder；
- RetinaFace bbox、FaceScore、5-point landmarks；
- 20 AU；
- 7 emotion；
- valence / arousal；
- gaze；
- 6DoF head pose；
- 478-point mesh 的 normalized 与原图像素坐标；
- 68-point compatibility landmarks；
- native blendshapes，包括 `eyeBlinkLeft` / `eyeBlinkRight`。

因此后续无需重新运行 Py-Feat 即可重建：Face tracking、primary face、EAR、眼睑开度、虹膜直径、aperture/iris、normalized eye openness、blink、PERCLOS，以及 Face 变量的 trial / block / probe / sliding-window 特征。

### Pose raw

每个 10 Hz 时点保存所有返回 pose 的 33 landmarks，包括 normalized/world coordinates、visibility、presence、pose bbox、多 pose / no-pose 状态与完整时间身份。因此 shoulder/posture motion 与质量门控后的 Pose features 可直接后算，无需重跑 MediaPipe。

### Motion raw

按原视频 full FPS 保存时间、亮度、相邻帧差、global motion energy、changed-pixel ratio、真实 `dt_ms` 及 capture/timestamp gap。常规 global-motion 时间窗统计无需重跑视频。

### 仍需读取原视频的边界

raw-first 并不等于保存全部原始像素。如果未来需要：

- Face 超过 15 Hz 或 Pose 超过 10 Hz 的新模型推理；
- 引入当前 raw 不包含且必须依赖原始像素的新视觉模型；
- 重新定义必须从像素 ROI 直接计算的指标；

则仍需读取原始 RGB AVI。原始视频因此继续作为最高层 provenance 保留。

## 7. Derived 与 QC 当前状态

以下内容全部后移，不阻挡 raw extraction：

```text
Face tracking
primary-face selection
EAR / eyelid / aperture-iris
blink event detection
PERCLOS
Pose derived features
QC inclusion
trial / block / probe / sliding-window aggregation
统计建模
```

当前 blink / PERCLOS 的上游信息已经充分落盘，但最终事件阈值、持续时间规则、PERCLOS 是否采用 P80 及是否排除快速 blink，仍需要代表被试分布和 overlay QC 后冻结。

`extraction_complete=true` 与 `qc_pass` 必须区分：前者表示昂贵模型原始信息已完整抽取；后者表示该被试是否满足最终科学质量要求。当前正式 manifest 中 `qc_pass=null` 是预期状态，不代表 QC 失败。
