# 043｜姿态与运动量分析方法

## 1. 为什么 Pose 与 Motion 要分开

RGB 身体分析同时回答两个问题：**身体具体怎么动**由 Pose 关键点回答；**总体动了多少**由 Motion Energy 回答。两者互补，不是二选一。

## 2. MediaPipe Pose

当前采用 MediaPipe Tasks Pose Landmarker 作为第一版身体姿态工具，使用官方 Pose Lite `.task` 模型和 `VIDEO` 模式。正式视频 pilot 先用 10 fps 推理，从真实 baseline 起点连续到 Block2 结束；该 fps 目前只用于快速验证，不代表最终冻结参数。

### Raw 信息保留

第一次推理不只保存派生的手腕/肩部指标，而完整保存模型返回的：

- 每个采样帧的 `video_frame_position`、`capture_frame_idx`、`unix_ms`；
- phase / block / trial / probe 上下文；
- 最多 2 个人体，避免 baseline 主试入镜时提前丢掉第二个人；
- 33 个 normalized landmarks 的 `x/y/z`；
- visibility / presence；
- 33 个 world landmarks 的 `x/y/z` 与可用的 visibility/presence；
- 每个人体的 normalized bbox；
- `pose_valid` / `pose_count` / `pose_index`；
- 未检测到人体的采样帧仍保留一行 `pose_valid=False`。

这一设计遵循 044 的“先保留后筛选”原则。`wrist_motion`、`upper_body_motion`、`trunk_lean`、`posture_variability` 都属于后续 derived feature，不替代完整 landmarks。

第一版不请求高体积 segmentation masks。当前研究需要的 `body_motion_energy` 先由完整 landmarks 构建可重复的人体 ROI；只有 landmark ROI 明确不足时才重新评估 mask，而不是一开始把逐帧 mask 大量落盘。

### 多人处理

Raw 层不假定 MediaPipe 返回的第 0 个人一定是被试。pilot 允许 `num_poses=2` 并完整保存；后续根据画面位置、连续性和实验场景定义 primary subject 规则。baseline 主试经过画面不会因此污染成“只有一个 pose 且默认就是被试”的不可逆结果。

## 3. Motion Energy

第一版使用 OpenCV 相邻灰度帧差异：

```text
mean_abs_difference = mean(abs(gray_t - gray_t-1))
global_motion_energy = mean_abs_difference / 255
global_motion_energy_per_sec = global_motion_energy / dt_seconds
```

同时保存 std/sum/max difference、changed-pixel ratio、gray mean/std/min/max、brightness delta、真实 dt 和 gap QC。

### gap 与时间抖动

真实 Unix timestamp gap 或 capture-frame 缺号时，gap 后第一帧保留身份/时间/阶段信息，但相邻帧 Motion 写 missing。`sub-031` 已验证 102 ms、101 ms、13.853 s、758 ms 四个 timestamp gap 均正确处理。

`sub-031` 的 dt 分布 P50=32、P90=46、P95=53、P99=70 ms；当前 1.5× median irregular flag 占约 7.67%，因此只作为 QC，不直接删帧。正式统计使用真实时间窗，不假定严格 30 fps 等间隔。

### global 与 body Motion

人工 representative-frame review 已确认 baseline 最高 global Motion 主要由主试进入/离开画面造成，而不是简单曝光突变。因此：

- `global_motion_energy` 保留为整画面变化量与 QC；
- 不把 global Motion 直接等价为被试身体运动；
- Pose 建立人体 ROI 后计算 `body_motion_energy`，作为更接近被试自身总体运动的正式候选量；
- global 序列不删除，body/global 的差异本身也是有用 QC 信息。

## 4. 性能

`sub-031` global Motion 正式时间窗 46,479 帧，约 78.3 fps，zstd Parquet 约 3 MB。Pose 的真实速度、coverage、multi-pose 率和输出体积等待 10 fps 正式视频 pilot 实测后记录。

## 5. 与 Face 的关系

最终 RGB 行为特征形成三套互补时间序列：

```text
Face   → AU / head / gaze / expression-related features
Pose   → structured body movement / posture
Motion → global/body movement magnitude
```

三者按真实 Unix 时间与 NIR pupil/blink/PERCLOS 和 SART 行为事件对齐。
