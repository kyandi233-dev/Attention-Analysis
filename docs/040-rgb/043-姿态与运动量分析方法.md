# 043｜姿态与运动量分析方法

## 1. 为什么 Pose 与 Motion 要分开

RGB 身体分析需要同时回答两个问题：

- **身体具体怎么动**：由 Pose 关键点回答；
- **整体动了多少**：由 Motion Energy 回答。

因此 MediaPipe Pose 与 OpenCV Motion Energy 是互补关系，不是二选一。

## 2. MediaPipe Pose

当前默认使用 MediaPipe Pose 作为第一版身体姿态工具。它提供 33 个身体关键点，可覆盖头、肩、肘、腕、髋、膝、踝等区域。

原始关键点坐标只是中间数据，正式研究变量需要从坐标派生，例如 left/right wrist motion、elbow/shoulder motion、upper-body motion、trunk lean、posture variability 和 body-center displacement。为了避免摄像头远近导致像素位移不可比，跨被试运动幅度应优先按肩宽、躯干尺度或其他稳定人体尺度标准化。

MediaPipe Pose 当前作为默认路线；只有正式录像上出现明显稳定性或性能问题时，才启动 YOLO Pose 等替代方案 benchmark。

## 3. Motion Energy

第一版使用 OpenCV 相邻灰度帧差异得到连续 movement magnitude。Motion 不负责识别动作类别，而是保存可重复派生运动量的逐帧测量。

当前 pilot 的核心量定义为：

```text
mean_abs_difference = mean(abs(gray_t - gray_t-1))
global_motion_energy = mean_abs_difference / 255
global_motion_energy_per_sec = global_motion_energy / dt_seconds
```

同时保存 `std/sum/max_abs_difference`、`changed_pixel_ratio`、gray mean/std/min/max 和 brightness delta。`changed_pixel_ratio` 当前使用配置中的开发阈值；它不是不可更改的正式科学阈值。

### 时间间隔与掉帧

Motion 同时检查两种 gap：真实 Unix timestamp 间隔超过 `gap_reset_ms`，或 FocusWave `capture_frame_idx` 出现缺号。任一发生时，gap 后第一帧仍保留身份、亮度、phase/trial 等信息，但不与 gap 前帧计算帧差，相关 motion 字段写为 missing。除此之外还保存 `dt_multiple_of_median` 与 `irregular_dt`；轻微异常 dt 先标记而不立即删除。

`sub-031` full-FPS pilot 已确认 4 个 reset：102 ms（Block1）、101 ms（interblock transition）、13.853 s（Block2）、758 ms（Block2）。这 4 行全部为纯 timestamp gap，`capture_missing_frame_indices_before=0`；四行均正确写为 `motion_valid=False` / `global_motion_energy=NaN`。

### 时间抖动分布

`sub-031` Motion QC 的真实 `dt_ms` 分布为：P50=32、P90=46、P95=53、P99=70 ms；92.3% 的 interval ≤48 ms，98.6% ≤66 ms。当前 `irregular_dt_multiple=1.5`（约 >48 ms）标记 3,564 行，占 7.67%。这一比例说明它更适合作为“时间抖动提示”而不是自动删除标准，因此当前不根据 `irregular_dt=True` 过滤 raw Motion。

后续统计应优先利用真实 `dt_ms` 和固定真实时间窗聚合，而不是假定每一帧严格等于 1/30 s。`global_motion_energy_per_sec` 作为附加量保留，但不在当前阶段单独认定为最终主指标。

### 亮度变化与 global Motion

`sub-031` QC 中 `global_motion_energy` 与 `abs(gray_mean_delta)` 的 Pearson 相关约为 `r=0.642`。最高 Motion 与最大亮度变化集中在 baseline 起始附近的相同一组帧，因此 global full-frame difference 可能同时包含真实身体运动和整体亮度/曝光变化。

这并不等于已经证明“Motion 被曝光污染”：真实大幅身体运动本身也可能改变整帧平均灰度。因此正式决策前必须人工回看代表 frame pair。相反，`motion_vs_changed_pixel_ratio≈0.753` 不是独立混淆证据，因为 changed-pixel ratio 本身就是同一帧差图的另一种度量。

新增 `motion-review` stage 只读取少量代表帧并生成一个 contact sheet：

```powershell
python scripts/rgb_analysis.py --stage motion-review --subject sub-031
```

输出 `_test/sub-031_motion-review.png` 与配套 JSON；每行左侧为上一帧、右侧为当前帧，覆盖 highest Motion、largest brightness change 和 P50/P90/P99 的典型 Motion。该步骤只用于方法验证，不修改 raw parquet，也不是正式 batch 的必需输出。

### Trial / probe 上下文

Motion pilot 会把 FocusWave B1/B2 行为 CSV 中可可靠映射的上下文附到逐帧结果，包括 `trial_num`、condition、cycle、stimulus、no-go/correct/error、probe 信息、`trial_onset_unix_ms`、`time_from_trial_onset_ms`、`trial_active`、`probe_active` 和 behavior state。

Probe 时段不会被静默当成普通刺激 trial：根据 `probe_onset_time` 到 `probe_response_time` 标记 `probe_active`；问题结束到下一 trial 之间可标记 `post_probe_recovery`。

## 4. global 与 body Motion Energy

当前 pilot 先计算 `global_motion_energy`。后续 MediaPipe Pose 建立稳定人体区域后，再增加 `body_motion_energy` 与 ROI validity。两者同时保留：global 用于总体变化/QC，body 作为更接近被试实际运动的主要候选指标之一。

当前 QC 进一步说明为什么不能只保留 global Motion：如果画面亮度变化会抬高整帧帧差，人体 ROI / mask 提供了额外的空间约束。因此 Pose 稳定后应正式评估 body Motion 与 global Motion 的差异，而不是删除已经保存的 global 序列。

如果后续发现 MJPEG 压缩噪声、光照波动或微小运动灵敏度使简单 frame difference 不够，再比较 optical flow；第一阶段不提前扩大到 optical-flow 主链。

## 5. 性能与输出体积（当前 pilot）

`sub-031` 的正式分析窗口共 46,479 帧。当前 Windows/OpenCV full-FPS pilot 运行约 593.4 s，处理速度约 78.3 fps；zstd 压缩后的 Parquet 约 3.0 MB。该结果用于开发阶段估算，不作为最终 batch runtime 保证；后续加入 Pose/Face 后需要分别重新 benchmark。

## 6. 与 Face 的关系

最终 RGB 行为特征形成三套互补时间序列：

```text
Face   → AU / head / gaze / expression-related features
Pose   → structured body movement / posture
Motion → total movement magnitude
```

这些变量按真实 Unix 时间与 NIR pupil/blink/PERCLOS 和 SART 行为事件对齐。

## 7. 当前不做动作类别识别

第一阶段不做“摸脸、伸懒腰、喝水、转身”等 Action Recognition。当前研究首先关心连续运动幅度和姿态变化；只有现有 Pose/Motion 指标无法回答明确研究问题时，才考虑建立动作类别模型。
