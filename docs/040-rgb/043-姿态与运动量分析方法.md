# 043｜姿态与运动量分析方法

## 1. 为什么 Pose 与 Motion 要分开

RGB 身体分析需要同时回答两个问题：

- **身体具体怎么动**：由 Pose 关键点回答；
- **整体动了多少**：由 Motion Energy 回答。

因此 MediaPipe Pose 与 OpenCV Motion Energy 是互补关系，不是二选一。

## 2. MediaPipe Pose

当前默认使用 MediaPipe Pose 作为第一版身体姿态工具。它提供 33 个身体关键点，可覆盖头、肩、肘、腕、髋、膝、踝等区域。

原始关键点坐标只是中间数据，正式研究变量需要从坐标派生，例如：

- left/right wrist motion；
- elbow motion；
- shoulder motion；
- upper-body motion；
- trunk lean；
- posture variability；
- body-center displacement。

为了避免摄像头远近导致“像素位移不可比”，跨被试运动幅度应优先按肩宽、躯干尺度或其他稳定人体尺度进行标准化，而不是直接比较原始像素距离。

MediaPipe Pose 当前作为默认路线；只有正式录像上出现明显稳定性或性能问题时，才启动 YOLO Pose 等替代方案 benchmark。

## 3. Motion Energy

第一版使用 OpenCV 相邻帧差异计算连续运动量。目标不是识别“正在做什么动作”，而是得到每一时刻的 movement magnitude。

至少保留两条序列：

- `global_motion_energy`：整帧变化量，用于总体变化与 QC；
- `body_motion_energy`：限制在人区域/人体 mask 内的变化量，作为被试真实运动的主要候选指标。

这样可以区分：

- 背景或屏幕变化很大、人体基本没动；
- 被试本身确实发生明显运动。

如果后续发现 MJPEG 压缩噪声、光照波动或微小运动灵敏度导致简单 frame difference 不够，再比较 optical flow；第一阶段不提前扩大到 optical-flow 主链。

## 4. 与 Face 的关系

最终 RGB 行为特征应形成三套互补时间序列：

```text
Face  → AU / head / gaze / expression-related features
Pose  → structured body movement / posture
Motion→ total movement magnitude
```

例如可以同时得到：

- `head_yaw`；
- `head_motion`；
- `upper_body_motion`；
- `right_wrist_motion`；
- `trunk_lean`；
- `body_motion_energy`。

这些变量后续再按 Unix 时间与 NIR pupil/blink/PERCLOS 和 SART 行为事件对齐。

## 5. 当前不做动作类别识别

第一阶段不做“摸脸、伸懒腰、喝水、转身”等 Action Recognition。原因是当前研究首先关心连续运动幅度和姿态变化，而不是离散动作标签。只有后续研究问题明确需要某类动作事件，并且现有 Pose/Motion 指标无法回答时，才考虑建立动作类别模型。
