## 文档编号规则

顶层目录编号先表达**模块归属**：

- `010-overview/` → overview；核心说明使用 `011–019`；
- `020-nir/` → NIR；核心说明使用 `021–029`；
- `030-behavior/` → Behavior；核心说明使用 `031–039`；
- `040-rgb/` → RGB；核心说明使用 `041–049`；
- `050-decisions/` → decisions；核心说明使用 `051–059`。

因此，核心编号不是全仓库单纯按创建时间连续递增，而是“**十位表示模块，个位表示该模块中的核心阅读顺序**”。例如 `021-...` 属于 NIR，`051-...` 属于 decisions。

日期型历史资料继续使用 `MM-DD-序号-...` 或其他明确日期命名，因为日期本身就是 provenance（来源/过程追踪）。历史资料一旦不再承担核心入口职责，不应继续占用其他模块的核心编号。例如原 `020-nir/011-...` 已恢复为 `020-nir/08-13-01-...`，避免与 `010-overview/011-...` 混淆。

程序文件、配置、模型、数据、测试和普通运行脚本默认不加排序数字；只有文件本身存在真实运行顺序或重要性顺序时才使用编号。目录入口统一使用 `README.md`，不使用 `00-README` 或 `000-目录与映射` 只为排序。

## GitHub 协作区域与仓库文档的边界

实时协作状态不再占用科研文档编号：

- **Project（项目看板）**：显示总体阶段、状态和负责人；
- **Issue（任务单）**：一次具体本地执行一个独立 Issue，完成并验收后关闭，下一任务另开；
- **Discussion（讨论区）**：保存尚未冻结的方法学讨论，形成决定后再写回正式科研文档或 `050-decisions/`；
- **`docs/`**：只保存需要长期版本控制的科研计划、数据契约、正式方法/决策和历史工作记录。

ChatGPT 与 Codex Luna 的长期执行分工见仓库工程规则 `.github/CODEX-LUNA-COLLABORATION.md`。早期把多轮任务/结果堆在同一 Issue 或放进 NIR 编号文档的做法仅作为历史记录保留，不再作为当前入口。

## 信息职责

- `010-overview/`：现在是什么、怎么连接。
- `020-nir/`、`030-behavior/`、`040-rgb/`：对应模块现在怎么做，以及需要保留的模块历史说明。
- `050-decisions/`：为什么这样选、何时被替代。
- `工作记录/`：当时具体发生了什么。

当前方法只有一个 canonical 说明位置；其他文档需要提及时应链接过去，避免多处复制形成互相矛盾的“当前版本”。
