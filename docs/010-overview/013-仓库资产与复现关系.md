# 013｜仓库资产与复现关系

仓库一级目录按“当前职责”分类，而不是按“历史上曾经参与过什么过程”分类。同一个实体只保留一个 canonical role；已经退出当前工作的资产通过工作记录、decision record、Git 历史和冻结历史版本追溯，不在 `main` 中重复堆放。

## 核心数据流

```text
datasets/
    ↓ 训练数据与固定划分
training/
    ↓ 训练过程与训练结果
model weights
    ↓ 冻结到正式运行环境
runtime/
    ↓ 正式分析
仓库外正式全量输出
```

## 当前一级目录职责

| 目录 | 回答的问题 | 典型内容 |
|---|---|---|
| `src/attention_pipeline/` | 系统核心逻辑怎么实现？ | 可复用 Python 源码 |
| `scripts/` | 当前还需要执行哪些仓库级任务？ | 数据集抽取、模型评估、待重建行为入口 |
| `configs/` | 仓库级配置是什么？ | 预实验/历史配置；正式 NIR 以 runtime 内配置为准 |
| `datasets/` | 训练数据从哪里来？ | 冻结标注数据与 provenance |
| `training/` | YOLO 模型怎么训练出来？ | split、dataset yaml、runs、训练结果 |
| `runtime/nir-formal/` | 怎样复现已经运行过的正式 NIR？ | 冻结权重、RITnet 运行源码、运行脚本、依赖与正式配置 |
| `runtime/legacy/` | 怎样追溯旧环境？ | 历史运行快照 |
| `tests/` | 怎样自动检查当前代码没有坏？ | 回归测试代码 |
| `docs/` | 当前方法、模块状态、决策和历史过程在哪里解释？ | overview、模态文档、decisions、工作记录 |

## 为什么没有根 `models/` 和 `artifacts/`

当前正式模型已经有明确 canonical 位置：

```text
training/nir-eye-yolo/.../best.pt
runtime/nir-formal/models/nir-eye-yolo26n-best.pt
runtime/nir-formal/models/ritnet-best_model.pkl
runtime/nir-formal/ritnet/
```

根 `models/` 原先保存的第三方完整源码副本与历史候选模型均不参与当前正式运行，已在记录来源、用途和淘汰原因后从 `main` 删除。

根 `artifacts/` 原先保存的 Gate/preview/ROI compare/smoke 等阶段性输出也已按用户授权全部删除。它们不是当前正式结果的 provenance 主链，历史用途和删除原因由工作记录与 Git 历史保留。

因此当前主线不再创建空壳 `models/README.md` 或 `artifacts/README.md` 来说明已经不存在的目录；对应说明统一放在 `docs/`。

## 行为分析版本边界

旧 `docs/030-behavior/sart-formal/`、`configs/sart_formal.yaml` 与当前 `src/attention_pipeline/behavior_formal/` 主要形成于 v3.0 BBB 阶段。最终正式实验 runtime 已冻结为 FocusWave v3.1.3、正式被试编号下限 31、两个正式 B block。旧 BBB 结果作为历史研究资产保留，但不能继续充当当前正式行为分析口径。
