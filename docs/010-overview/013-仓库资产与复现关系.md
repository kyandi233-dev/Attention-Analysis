# 013｜仓库资产与复现关系

仓库一级目录按“当前职责”分类，而不是按“它曾经参与过什么过程”分类。同一个实体只保留一个 canonical role；历史关系通过 README、decision record、工作记录和 Git 历史表达，不靠在当前主线重复保存所有旧资产。

## 核心数据流

```text
datasets/
    ↓ 训练数据与固定划分
training/
    ↓ 训练过程与训练结果
model weights
    ↓ 冻结到正式运行环境
runtime/
    ↓ 正式分析
仓库外正式全量输出
```

## 当前目录职责

| 目录 | 回答的问题 | 典型内容 |
|---|---|---|
| `src/attention_pipeline/` | 系统核心逻辑怎么实现？ | 可复用 Python 源码 |
| `scripts/` | 我要执行哪个任务或诊断？ | 当前任务入口、评估工具与历史脚本；历史脚本不一定仍可直接运行 |
| `configs/` | 仓库级配置是什么？ | 行为配置、历史兼容配置；正式 NIR 以 runtime 内配置为准 |
| `datasets/` | 模型的数据从哪里来？ | 冻结训练/标注数据与 provenance |
| `training/` | YOLO 眼框模型怎么训练出来？ | split、dataset yaml、runs、训练结果 |
| `models/` | 当前模型资产在哪里、历史模型为什么退出？ | 模型注册与来源说明；正式权重不从这里读取 |
| `runtime/nir-formal/` | 怎样复现已经运行过的正式 NIR？ | 冻结 YOLO/RITnet 权重、RITnet 必要源码、运行脚本、依赖与正式配置 |
| `runtime/legacy/` | 怎样追溯旧环境？ | 历史运行快照 |
| `tests/` | 怎样自动检查代码没有坏？ | 回归测试代码；不是“所有曾经测试过的东西” |
| `docs/` | 当前方法、模块状态、决策和历史过程在哪里解释？ | overview、模态文档、decisions、工作记录 |

## 当前模型 provenance

正式 YOLO26n 眼框模型保留完整链路：

```text
datasets/
→ training/nir-eye-yolo/
→ training/.../weights/best.pt
→ runtime/nir-formal/models/nir-eye-yolo26n-best.pt
→ 正式 NIR 全量分析
```

正式 RITnet 运行资产位于：

```text
runtime/nir-formal/ritnet/
runtime/nir-formal/ritnet_runtime.py
runtime/nir-formal/models/ritnet-best_model.pkl
```

其上游来源和冻结版本见 `runtime/nir-formal/ritnet/UPSTREAM.md`。

## 已退出当前主线的资产

2026-08-23 经用户明确授权，当前 `main` 删除：

- `artifacts/`：早期 Gate / preview / ROI compare / smoke 等阶段性输出；
- `models/external/`：RITnet 完整上游副本、DeepVOG、DeepVOG-3D、pye3d、YOLO face-parts 等第三方候选源码；
- `models/historical/`：MediaPipe Face Landmarker、YOLO-face、YuNet 等历史候选模型文件。

这些删除不改变正式分析结果，也不切断当前正式模型的可复现链路。删除原因与当时资产用途保留在 `docs/工作记录/`；旧版本文件仍可通过 Git 历史和 `history/tracking-era-2026-08` 追溯。

## 历史候选的处理原则

“曾经使用过”不等于必须永久驻留当前 `main`。已经退出正式路线、可重新获取或只为旧实验服务的第三方源码/模型，优先保留：

- 上游 URL 与版本/commit；
- license；
- 当时用途；
- 测试结果与淘汰原因；
- 工作记录和 Git 历史。

只有当前正式 runtime 直接依赖、且需要冻结才能确保可迁移复现的源码和权重，才作为当前运行资产保留。
