# 013｜仓库资产与复现关系

仓库一级目录按“当前职责”分类，而不是按“它曾经参与过什么过程”分类。同一个实体只保留一个 canonical role；历史关系通过 README、decision record 和工作记录链接表达，不靠重复复制文件。

## 核心数据流

```text
datasets/
    ↓ 训练数据与固定划分
training/
    ↓ 训练过程与训练结果
model weights
    ↓ 冻结到正式运行环境
runtime/
    ↓ 正式分析
仓库外正式全量输出
```

## 目录职责

| 目录 | 回答的问题 | 典型内容 |
|---|---|---|
| `src/attention_pipeline/` | 系统核心逻辑怎么实现？ | 可复用 Python 源码 |
| `scripts/` | 我要执行哪个任务或诊断？ | 命令入口、诊断和历史比较脚本 |
| `configs/` | 仓库级配置是什么？ | 行为配置、历史兼容配置；正式 NIR 以 runtime 内配置为准 |
| `datasets/` | 模型或分析的数据从哪里来？ | 冻结训练/标注数据与 provenance |
| `training/` | 模型怎么训练出来？ | split、dataset yaml、runs、训练结果 |
| `models/external/` | 哪些第三方算法源码被保存？ | RITnet、DeepVOG、pye3d 等外部项目源码 |
| `models/historical/` | 哪些独立模型资产属于历史候选？ | 已退出当前正式路线的模型文件 |
| `runtime/nir-formal/` | 怎样复现已经运行过的正式 NIR？ | 冻结权重、运行脚本、依赖与正式配置 |
| `runtime/legacy/` | 怎样追溯旧环境？ | 历史运行快照 |
| `tests/` | 怎样自动检查代码没有坏？ | 回归测试代码；不是“所有曾经测试过的东西” |
| `artifacts/` | 哪些历史评估/QC证据需要保留？ | Gate、benchmark、preview、审批/QC 证据；不是正式全量输出 |
| `docs/` | 当前方法、模块状态、决策和历史过程在哪里解释？ | overview、模态文档、decisions、工作记录 |

## 关于历史候选

“rejected / historical” 是状态，不等于自动删除。旧模型源码、评估证据或运行包是否继续保留，应根据其 provenance 价值决定；真正删除任何现有研究资产仍需明确授权。
