# 012｜模态结构与当前状态

本文件只回答各研究模态目前处于什么状态，避免把“模块存在”误解为“当前已经运行”。

| 模态 / 层 | 当前状态 | 当前入口 | 说明 |
|---|---|---|---|
| NIR | **正式全量已完成，当前主分析模态** | `docs/020-nir/`、`runtime/nir-formal/` | 正式主链为逐帧 YOLO26n → ROI → RITnet batch inference |
| Behavior | **最终 BB 分析实现已建立** | `docs/030-behavior/`、`scripts/sart_formal_analysis.py` | FocusWave v3.1.3，正式结构为 B1/B2；旧 BBB 独立保留为历史可执行复现 |
| RGB | **开发 / 方法验证中** | `docs/040-rgb/`、`src/attention_pipeline/rgb/` | `rgb-dev` 基于 AMD/DirectML；Face 比较 Py-Feat 与 LibreFace，Pose 使用 MediaPipe Pose，Motion 使用 OpenCV Motion Energy |
| Cross-modal | **概念与接口保留，当前未作为独立运行模块** | 本文件 | 单模态测量和研究问题成熟后再建立独立融合代码/配置/文档 |
| Attention / scoring | **不把算法输出直接等同于专注真值** | 后续研究决策 | 行为、眼部指标、测量质量与最终评分模型保持分层 |

正式 Behavior 与 NIR 当前都以 `sub-031+`、FocusWave v3.1.3、两个正式 B block 为共同实验边界。RGB 开发同样以最终 BB 结构为目标；其实验程序 provenance 以 `FocusWave/formaltest` 为准，现有正式数据主要对应 v3.1.3 / v3.1.4。RGB 使用自身帧时间戳与 `master_timeline.csv` / 行为绝对时间对齐，不依赖视频帧率推算阶段边界。

## 何时把新模块升级为独立目录

只有当一个模块至少形成独立实现或分析流程，并产生需要长期维护的多份说明文档时，才在 `docs/` 建新的编号目录。RGB 现已达到开发模块条件，因此 `040-rgb/` 从旧保留接口升级为当前开发入口；这不表示 RGB 已冻结或完成全量分析。
