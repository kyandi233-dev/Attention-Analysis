## tests/ 的职责

根 `tests/` 只负责仓库级代码回归与协议行为验证，不处理正式全量数据，也不保存正式分析结果。

它与 runtime 内部可能存在的自检测试职责不同：

- 根 `tests/`：验证项目源码、配置解析、行为/NIR逻辑、评价与可移植性契约。
- runtime 内部测试：如果存在，只验证对应运行包自身的最小可运行性或窗口逻辑，不替代根测试集。

## 已有测试范围

| 文件 | 覆盖范围 |
|---|---|
| `test_protocol_and_config.py` | 协议、阶段/探针定义、配置解析与相关开关 |
| `test_behavior.py` | RT、QC、d′分母、窗口边界与行为统计逻辑 |
| `test_io.py` | dropped 行、AVI位置映射、block/输入解析 |
| `test_nir.py` | NIR 几何、眼别、ROI、仿射、椭圆与缺失语义 |
| `test_review.py` | 标注/复核设计、seed复现、字段与保存/恢复接口 |

> 具体测试文件可能随着后续开发增加；本索引描述的是职责边界，不应被理解为完整且永久固定的文件清单。

## 当前整理原则

1. 不把正式分析脚本搬进 `tests/`。
2. 不把历史 artifacts 当作测试夹具随意覆盖。
3. 对已经全量运行的正式 NIR 管线，测试用于防止代码回归，不用于重新定义项目是否“已准入”。
4. 如后续决定将本文件改名为 `README.md`，必须按用户批准的方式处理旧路径；当前不删除任何文件。
