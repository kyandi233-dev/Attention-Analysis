# Artifacts

`artifacts/` 当前保存的是 2026-08 中旬 NIR 候选路线产生的阶段性评估输出。这里**不是正式全量分析结果目录**，也不等于“所有研究过程文件都应该放在这里”。

当前正式 NIR 全量结果仍保存在仓库外独立分析目录；当前正式模型的数据与训练 provenance 分别由 `datasets/`、`training/` 和 `runtime/` 承担。

## 为什么 `datasets/` / `training/` 不属于 archive

`datasets/` 和 `training/` 虽然也是研究过程中形成的资产，但它们仍然直接解释当前正式模型从哪里来：

```text
datasets/
→ training/
→ YOLO best.pt
→ runtime 冻结副本
→ 正式 NIR 全量分析
```

因此它们是**当前正式结果的有效 provenance**，不是已经退役的历史包。

`artifacts/` 中的内容不同：它们主要来自已经结束的 ROI / Gate / smoke 候选阶段。

## Gate / QC / benchmark / preview 分别是什么意思

这些词描述的是研究开发活动，不是必须建立四个固定目录：

- **Gate**：准入检查点。满足预先设定条件后，某条方法路线才允许继续进入下一阶段。
- **QC (Quality Control)**：质量控制。检查输出是否可用、是否存在失败、异常或缺失。
- **Benchmark**：在统一数据和指标下比较多个算法 / 参数方案的性能。
- **Preview**：预览输出，用少量图片或网页先人工查看结果是否符合预期。
- **Smoke test**：冒烟测试，用极少量数据快速排除明显的程序或输入域问题。

这些名称表示“当时为什么生成这些东西”，并不说明它们都值得永久留在主线。

## `archive/` 是否需要存在

当前不建议把整个 `artifacts/` 机械改名为 `archive/`。

`archive/` 更适合表示：

> 已退出当前工作，但因为历史价值仍决定长期保留的内容。

而当前 `artifacts/` 中只有 `gate1-24eyes/` 明显符合“长期保留研究证据”的标准；其他目录更接近可重新生成的临时/阶段输出。

因此更合理的后续路径是：

1. 先确认 `preview / roi-compare / smoke*` 是否允许删除；
2. 保留 `gate1-24eyes/`；
3. 如果希望顶层命名更准确，再考虑把长期保留内容改为例如：

```text
evidence/
└── nir-gate1-24eyes/
```

而不是建立一个含义宽泛的 `archive/`，把训练数据、模型 provenance 和临时输出混在一起。

## 删除原则

- 人工标注、人工审批和难以无损重新生成的证据优先保留。
- 纯脚本生成、可由原始数据与 Git 历史重新生成的阶段输出可以作为删除候选。
- 删除前确认关键结论已经写入工作记录 / decisions。
- 工作记录本身不参与 artifacts 清理。
- 任何实际删除仍需用户明确批准。
