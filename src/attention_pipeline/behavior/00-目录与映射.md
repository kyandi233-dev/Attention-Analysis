# 00｜behavior —— 早期行为证据层

## 当前定位（2026-08-23）

`behavior/` 是项目较早阶段建立的**行为证据与不确定性分析层**。它仍然有代码和历史复现价值，并且旧统一 `cli.py` 仍直接调用其中模块，因此当前不删除、不改包名，也不与 `behavior_formal/` 强行合并。

需要与后续正式分析模块区分：

```text
behavior/
    = 较早的通用行为 evidence / reporting 路线

behavior_formal/
    = 后续正式 BBB SART 分析路线
```

两者共享部分基础概念，但不是简单重复文件。

## 文件职责

| 文件 | 当前职责 |
| --- | --- |
| `extract.py` | 读取正式行为 CSV，生成 trial 长表、RT QC 标记和基础 block 指标（含 loglinear d′） |
| `evidence.py` | 时间窗、No-Go 机会窗、Jeffreys 后验与探针前窗等 evidence 逻辑 |
| `reporting.py` | 该早期 evidence 路线的报告与绘图辅助；其中部分通用绘图函数仍被 `behavior_formal/figures.py` 复用 |
| `__init__.py` | 包初始化 |

## 与 `behavior_formal/` 的关系

`behavior_formal/` 在正式 BBB SART 数据契约上进一步实现了：

- 27 列正式输入校验；
- trial 级预警指标；
- block / cycle-bin / 时间窗 / 探针四层指标；
- RT-SD、RT-CV、ex-Gaussian τ；
- SDT 的 d′、c、β；
- 主效应、交互、回归、相关及多重比较校正；
- 正式图表和 Markdown 报告。

因此目前最合理的结构不是把两套代码物理合并，而是先保留：

```text
behavior/          # earlier evidence layer / compatibility
behavior_formal/   # formal BBB SART analysis
```

如果未来确实要统一，应先解决旧 `cli.py` 调用、`behavior_formal.figures` 对 `behavior.reporting` 的复用，以及两套指标口径的兼容问题，再讨论迁移。
