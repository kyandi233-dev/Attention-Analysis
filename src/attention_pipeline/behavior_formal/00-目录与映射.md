# 00｜behavior_formal —— 正式 BBB SART 行为分析

## 当前定位（2026-08-23）

`behavior_formal/` 是当前仓库中针对正式 BBB SART 数据建立的**正式行为分析模块**。它负责从正式行为 CSV 读取与契约校验开始，一直完成指标计算、统计分析、图表和 Markdown 报告。

本模块输出的是行为证据与统计结果，不把多种行为指标压缩成单一“专注分数”。

## 模块流程

```text
正式 beh CSV
→ extract.py：读取、校验、trial 长表、QC / trial markers
→ metrics.py：block / cycle-bin / window / probe 指标
→ stats.py：主效应、交互、回归、相关、效应量与校正
→ figures.py：正式图表
→ report.py：正式 Markdown 分析报告
```

## 文件职责

| 文件 | 主要职责 |
| --- | --- |
| `extract.py` | 正式 27 列输入契约；3 个正式 block 读取；RT QC；trial 级预警指标；正式数据完整性校验 |
| `metrics.py` | block、周期 bin、时间窗、探针四层指标；RT-SD / RT-CV；ex-Gaussian μ/σ/τ；SDT d′ / c / β；Jeffreys 区间等 |
| `stats.py` | 被试级推断；Friedman / Wilcoxon、Holm 校正、bootstrap CI、交互/回归/相关等正式统计逻辑 |
| `figures.py` | 正式 BBB SART 图表；输出到报告目录，并复用 `behavior.reporting` 中部分通用绘图辅助 |
| `report.py` | 汇总过程、统计结果和图表映射，生成正式 Markdown 报告 |
| `__init__.py` | 包初始化与模块定位说明 |

## 与 `behavior/` 的边界

`behavior/` 是更早建立的 evidence / reporting 层，旧 `cli.py` 仍依赖它；`behavior_formal/` 则是在正式 BBB SART 数据和最终分析需求上扩展形成的完整分析链。

当前不要因为二者存在相似函数就直接合并：

1. `behavior_formal/` 的数据契约与指标体系更完整；
2. 旧 `behavior/` 仍承担历史复现与兼容职责；
3. `behavior_formal.figures` 当前还直接复用 `behavior.reporting` 的通用绘图函数；
4. 合并会涉及 import、CLI、历史结果口径和文档引用的系统性迁移。

因此当前保留两个模块是有意的兼容安排，而不是尚未清理的简单重复目录。

## 后续整理建议

如果之后确实要统一行为模块，建议先建立“共享基础层 + 正式分析层”的迁移设计，例如把真正通用且口径一致的函数抽到公共模块，再逐步迁移调用方。任何旧模块删除都必须在完成调用审计后，并取得用户明确同意。
