# 00｜NIR 源码目录与映射

## 当前定位（2026-08-23）

`src/attention_pipeline/nir/` 保存 NIR 研究过程中形成的**可复用基础逻辑、历史 ROI / benchmark / sequence 评估代码，以及正式数据路径和时间轴辅助**。

项目当前已经完成 YOLO26n 眼框模型训练和正式 NIR 全量分析，但最终采用的 YOLO + tracking + RITnet 完整 runner **不在本子包中**。当前分支已经核验到完整 portable implementation 位于：

```text
runtime/nir-yolo-tracking-ritnet-v1/run_pipeline.py
```

因此：

```text
src/attention_pipeline/nir/
    = 历史研究阶段 + 可复用 NIR 核心/评估逻辑

runtime/nir-yolo-tracking-ritnet-v1/
    = 已冻结的 YOLO26n + tracking + RITnet 完整 portable implementation
```

不要再把旧 `sequence.py`、`sequence_eval.py` 或包级 `cli.py` 自动描述成后来正式全量的 YOLO + RITnet 最终入口。

## 当前文件职责

| 文件 | 当前职责 |
| --- | --- |
| `formal.py` | 正式实验 NIR 视频、timestamp、行为文件路径及 block 时间窗对齐等正式数据辅助 |
| `roi.py` | ROI、仿射、眼部几何、椭圆与 IoU 等基础几何函数；包含早期固定眼角 ROI 路线所需逻辑 |
| `metrics.py` | NIR 基础测量指标，包括缺失处理后的 PERCLOS 基础实现 |
| `review.py` | 代表性帧、ROI 人工 review、盲标、审批门及历史数据构建流程 |
| `benchmark.py` | Stage 4 六算法单帧 benchmark、几何/光度门、admission 判定和参数 sweep |
| `sequence.py` | Stage 5 历史连续序列路线：抽样、逐帧早期 ROI/可见性与测量流程 |
| `sequence_eval.py` | Stage 5 历史 sequence 状态机、插值、连续性指标、时间线与评估报告 |

## 与当前正式 YOLO + Tracking + RITnet 路线的关系

后期正式路线发生了关键技术转变：眼 ROI 不再依赖早期完整人脸 / 固定眼角 ROI 方案，而是使用自行训练的 YOLO26n 直接定位双眼框，再通过 tracking / 周期重检测减少逐帧 YOLO 计算，并将单眼 ROI 输入 RITnet。

当前仓库已核验 portable runner 实现：

```text
NIR AVI
→ YOLO26n eye bbox
→ CSRT / KCF tracking 或逐帧 YOLO
→ 周期重检测 / tracker failure fallback
→ ROI 扩展与裁剪
→ RITnet segmentation
→ frames.csv / eyes.csv / summary.json / run_manifest.json
```

该 runtime 中的：

```text
models/nir-eye-yolo26n-best.pt
```

与：

```text
yolotrain/runs/yolo26n_eye_100epoch/weights/best.pt
```

Git blob 完全相同；runtime 中的 `ritnet-best_model.pkl` 与 `models/RITnet-master/best_model.pkl` 也完全相同。因此 portable package 与当前正式模型资产具有直接、可验证的模型血缘。

但当前 GitHub 分支仍未找到最终正式全量运行时保存的 `run_manifest.json` 或等价命令记录，所以不能仅依据 2026-08-22 portable package 的默认 `tracker=csrt`、`redetect_interval=10`、ROI 扩展比例等参数，自动宣布这些就是最终 full-run 的冻结参数。

## 历史 Stage 4 / Stage 5 代码为什么继续保留

早期六算法 benchmark、MediaPipe/固定 ROI、sequence 状态机和插值评估已经不是后来正式 YOLO + RITnet 路线的最终实现，但它们仍然记录了算法筛选、失败模式、连续性评估和方案转向的研究过程。

因此当前整理原则是：

1. 保留这些模块及其历史路径；
2. 明确标记它们的研究阶段和职责；
3. 不把历史代码伪装成当前生产入口；
4. 不因为路线被替代就删除其源码或工作记录；
5. 如果未来要把 runtime 正式实现重新模块化进 `src/attention_pipeline/nir/`，应建立新的迁移方案，而不是直接覆盖历史模块。

## 历史说明

> 2026-08-14（Asia/Shanghai）｜NIR 源码将端到端 ROI 失败、瞳孔可见性、检测失败与插值严格分轨；Stage 4 新增六算法基准与参数调优，Stage 5 建立连续序列路线。

- `sequence.py`：连续序列抽样与逐帧早期 ROI；
- `sequence_eval.py`：状态机、短缺口插值、连续指标与报告。

该内容作为技术路线演化历史保留，但不再代表 2026-08-23 项目最终使用的完整 NIR pipeline。
